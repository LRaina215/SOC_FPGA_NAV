# 除轮速目标滤波外的控制链审查

范围：当前fpga/src与7000模型本地response_env.py，结合2026-10-19 01:02两段实车记录；本次未改运行代码、模型或烧录。测试和采集只生成诊断文件。

## 1. FPGA姿态初始化未使用启动时真实重力（已复现）
imu_fusion.v重力状态复位为[0,0,-4096]；bias_done只写gyro bias和清calibrating，未用加速度方向初始化gx/gy/gz。随后每样本仅以82/4096修正。mem_policy看到首个fusion_valid即可启动，没有等待初始姿态收敛。

独立RTL静态20°测试：首次标定后重力[0,28,-4096]，相当于−0.392°；50个10ms样本后为[0,876,-4002]，相当于−12.35°，而静态输入仍为−20°。BIAS_SAMPLES缩为4用于快速验证，不改变标定后姿态逻辑。

实车run64标定最后约1.1秒，accel atan2(ay,az)均值−2.88°，run66为−5.21°；首次active融合角仅−0.098°/−0.224°。静态加速度角不是动态运动的真值，但启动前差异与RTL缺陷一致。建议稳定标定窗口平均重力并归一化作为初始姿态，完成后再允许active。

## 2. 仿真编码器整圈回绕误计（已定位并复现）
response_env.py112..115直接用当前关节角度减固定origin转累计计数，然后减上次计数。PhysX关节角度会从约+2π跳到−2π，这不是物理转了两圈。

复现数据simulation_wrap_probe.npz：2.328s左轮位置6.27581787、累计计数1316；2.336s位置−6.27058411、计数−1320，相差−2636。直接读取的物理轮速−0.094536m/s；输入模型轮速槽被clip到−100（按物理左轮换算为+21.67m/s）。需累加每个物理步的小角度增量（处理回绕）再模拟编码器。train_response_scratch.py调用同一HardwareRobot，故训练环境同一路径值得重新校验；尚未重训或证明该异常决定了已训练模型行为。

## 3. 实车零目标时直接清PID及关PWM（实现差异）
main.v MOTOR_CLOSED_LOOP_AT_ZERO=0；motor520_closed_loop.v111..117在target==0时清积分、微分历史、参考并输出0，PWM的enable也在目标0时关闭。它是零目标滑行策略，不是零速反馈制动。原reduced仿真速度P环在目标0且轮子转动时仍输出制动力矩。过零时控制不连续，有可能加重摆动，但不能据此独断为摔倒唯一原因。

## 4. 实车斜坡及控制器仍不等同原响应仿真（实现差异）
实车20mm/s每2ms；从0到600mm/s至少60ms，从−600到+600至少120ms。新增LPF位于该斜坡之前，两者并存。原reduced环境LPF之后是每2ms直接速度P到扭矩，无该斜坡、I/D/前馈、PWM/驱动死区。即使周期和LPF相同仍不是相同闭环。

## 5. 舵机机械闭环未辨识（物理参数限制）
FPGA每20ms更新PWM，IK前馈+最大±19µs动作修正；方向只在policy_action_map应用一次，模型模式servo_driver关闭二次方向转换，未发现重复反向。仿真相同目标以理想关节PD产生扭矩，能直接访问实际角度/角速度；真实JS6620内部位置环、负载和供电响应未辨识。FPGA遥测只有脉宽指令，没有真实舵机角度。

建议优先修复1与2，再在相同环境下比较保留/改变零速策略及斜坡。暂不继续盲目放大轮速或以周期一致宣称已完成动态对齐。
