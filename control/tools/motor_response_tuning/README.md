零目标闭环通过`MOTOR_CLOSED_LOOP_AT_ZERO=1`启用，只在控制使能时运行。急停、控制失能和故障仍关断驱动。近零指令不再清除微分历史；参考为0且测得速度在±10mm/s以内时，存储积分按1/8逐样本衰减，避免旧负载补偿导致爬行。底层模块默认保留兼容模式，顶层明确启用新行为。`MOTOR_CLOSED_LOOP_AT_ZERO=0`可恢复原来的零速滑行语义。

600mm/s是PID参考限速，不是车身加速度保证；0->0.3m/s可在一个采样步更新参考，-0.6->+0.6仍需两个采样步。输出仍限制在±0.6m/s，PWM上限仍为96%，20kHz载波、换向空白周期和原有故障保护均保留。

## 数据与参数选择

`fit_and_tune.py`读取已有10958帧串口记录，筛选模型活动、无故障、倾角小于10度、PWM未接近饱和、相邻时间差20ms的数据。左/右有效样本3869/3923。拟合低阶速度方程，再在左右拟合值附近选取±25%增益、±30%时间常数的18组假设，比较513组PID/前馈/参考限速组合；参考是45ms时间常数加10ms延迟的仿真速度响应。加入编码器量化、PWM饱和、积分限制、零速积分衰减及堵转/反向保护。

选择P4、I0.35、D0.5、FF3.5、参考步长600。在这些假设下，启发式综合评分比旧参数低约74%；这不是实车性能提升百分比。拟合加速度残差约1.35~1.38m/s²，存在机身运动、地面接触和闭环相关性的干扰；不代表唯一真实电机模型，实际响应仍需复测。结果见`tuning_result.json`。

## 遥测升级

新固件使用230400、8N1、100Hz；监控默认值同步调整。接旧固件请加`--baud 115200`。协议解码兼容V1/V2，新CSV固定包含PID字段；V1没有的值保留为空/NaN，不伪造为0。

V2前100字节与V1一致，追加：左/右PID内部参考（各int32 mm/s）、左/右误差（各int32 mm/s）、左/右控制更新计数（各uint16）。总负载120字节，带帧头和CRC共126字节，约12600字节/秒，占230400 8N1链路约55%。参考/误差和计数只在对应PID完成计算后更新；各传感器仍为最近一次有效数据，不代表严格同时采样。

```bash
bash /home/cyd/fpga/tools/fpga_telemetry/open_monitor.sh --port auto
# 尚未换新固件时：
bash /home/cyd/fpga/tools/fpga_telemetry/open_monitor.sh --port auto --baud 115200
```

部署新固件时需重启旧的115200后台记录器；不要同时用两个进程独占同一串口。

## 验证与边界

`bash tools/motor_response_tuning/run_checks.sh`检查原有PID、微分、20kHz PWM、编码器、过零反馈制动、失能、反馈超时、顶层参数、真实串口位级输出、CRC、碎片输入、坏帧恢复、V1/V2共存，以及红外/急停集成行为。测试输出会提示临时目录。

轮速调整本身不改变网络。随后已将7000轮模型导出为18位F12权重并装入工程，定点误差和RTL验证见`model/mem_7000/`，新位流见`fpga/impl/pnr/fpga_model7000.fs`。JS6620保持20ms刷新，其机械速度未实测标定。

新的布局布线与50MHz静态时序已通过；实际带载稳定性尚未验证。先以新的串口数据检查目标、内部参考、轮速、PWM和倾角是否同步改善，再判断是否适合继续调整。
