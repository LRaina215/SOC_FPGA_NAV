## 5.2 历史观测的140维顺序

历史缓存存5 帧，每帧 28 维，每帧内部都采用上表顺序，按最旧到最新排列：

| 历史索引 | 内容 |
| --- | --- |
| 0～27 | 最旧的一帧 |
| 28～55 | 第二帧 |
| 56～83 | 第三帧 |
| 84～111 | 第四帧 |
| 112～139 | 最新的一帧 |

本版训练中的最新历史帧包含当前观测：推理当前帧时，先将本帧观测移入历史末尾，再提供“当前 28 维＋历史 140 维”。初始化或重置时，用第一帧重复填满五帧；不要把 140 维全部填零，也不要错用“排除当前帧的五帧历史”。训练控制周期为0.002s × 4 = 0.008s，即 125Hz。
测试向量inputs.mem的每组存储顺序为：当前观测 28 字在前，历史观测 140 字在后，共 168 字。实际 RTL 推理核的当前观测和历史写入端口是否分开，以模块端口为准。

## 5.3 六路输出顺序和执行换算

注意顺序是左髋、左膝、左轮、右髋、右膝、右轮，不是“四路舵机后面跟两路轮子”。以下action均指限幅后的归一化实数。

| 输出 | 对应执行器 | 换算与接法 |
| --- | --- | --- |
| action0 | 左髋舵机  SERVO1 | 高度 IK 基础角度＋action0 × 0.03rad |
| action1 | 左膝舵机  SERVO2 | 高度 IK 基础角度＋action1 × 0.03rad |
| action2 | 左轮  电机2 | 物理前进目标线速度v_left = -action2 × 0.6m/s |
| action3 | 右髋舵机  SERVO3 | 高度 IK 基础角度＋action3 × 0.03rad |
| action4 | 右膝舵机  SERVO4 | 高度 IK 基础角度＋action4 × 0.03rad |
| action5 | 右轮  电机1 | 物理前进目标线速度v_right = +action5 × 0.6m/s |

舵机修正满幅0.03rad约为1.72°，不是舵机全部升降活动范围；升降由基础姿态随高度指令变化完成。基础角度加修正后，还需按实物舵机零位、方向标定转换为 PWM 脉宽。

# 七、上下位机通信

## 7.1 控制方式

上位机为RK3588，下位机为FPGA。上位机通过同一个接口同时下发**车体目标前进速度** `v_cmd`（m/s）和**目标偏航角速度** `yaw_cmd`（rad/s）；FPGA将两者原子更新到现有模型指令接口，不直接覆盖左右轮输出。正角速度左转，负角速度右转。

```text
RK3588 send_speed(port, v_cmd, yaw_cmd)
    → UART_RXD → command_forward_q12＋command_yaw_q12
    → 模型观测＋IMU＋编码器 → 六路模型动作
    → 四路舵机控制＋双轮目标速度 → 轮速PID → 电机PWM
```

建议先使用 **`v_cmd = +0.3m/s`** 测试前进。这是目标值，不保证实车恰好达到0.3m/s。

| 速度 | 含义 |
| --- | --- |
| 上位机目标速度 `v_cmd` | 希望车体达到的前进速度，输入模型观测第6项前按原规则缩放 |
| 模型输出轮速 | 模型根据平衡状态分别给出的左右轮目标速度，可以不同，也可以随时间变化 |
| 实际速度 | 编码器反馈的左右轮速度；会受到电机响应、负载、摩擦和速度环参数影响 |

**模型给出的目标轮速与实际运行速度不一定相同，上位机给0.3m/s也不代表两轮一直以0.3m/s运行。** 核对速度应读取反馈，不应只看发送值；车轮打滑时，编码器轮速也不能完全代表车体对地速度。

现有模型后退学习效果不足，当前使用建议以向前行驶为主。需要向后方移动时，优先由上位机规划“**原地旋转180°，再以+0.3m/s前进**”。转到180°必须依据朝向反馈判断完成，不建议只按固定时间转动。串口现已支持转向：`send_speed(port, 0.0, +1.0)`左转，`send_speed(port, 0.0, -1.0)`右转。上位机根据朝向反馈确认转过180°后，先发送`send_speed(port, 0.0, 0.0)`结束转向，再发送`send_speed(port, 0.3, 0.0)`前进；FPGA不自动判断180°是否完成。

## 7.2 接线与串口参数

| RK3588串口 | FPGA接口 | 球脚 |
| --- | --- | --- |
| TX | UART_RXD，P11-39 | A15 |
| RX | UART_TXD，P11-40 | A16 |

## 7.3 串口运动接口：同时下发线速度与角速度

软件调用形式：`send_speed(serial_port, speed_mps, yaw_radps=0.0)`。省略角速度等价于发送0。发送工具代码位于 `tools/uart_speed_validation/speed_command.py`，导入不会自动打开串口或发送指令。

新指令固定10字节，线速度与角速度在同一帧中更新，所有多字节整数为**小端**：

| 字节偏移 | 字段 | 格式与内容 |
| --- | --- | --- |
| 0～1 | 帧头 | `A5 5A` |
| 2 | 指令版本 | `10`（十六进制，速度指令帧） |
| 3 | 数据长度 | `04`，表示线速度＋角速度数据共4字节 |
| 4～5 | 目标前进速度 | int16，有符号，单位mm/s；+0.3m/s发送300 |
| 6～7 | 目标偏航角速度 | int16，有符号，单位mrad/s；+1rad/s发送1000，−1rad/s发送−1000 |
| 8～9 | CRC16 | 对字节2～7计算CRC16/CCITT-FALSE，结果低字节先发 |

CRC参数：多项式0x1021，初值0xFFFF，输入/输出不反射，最终异或0x0000。有效线速度范围为−600～+600mm/s，角速度范围为−2900～+2900mrad/s；CRC错误、版本/长度错误或任一数值超范围时，两个目标都不更新，不会只接受半条指令。截断报文在字节间隔超过10ms后丢弃，等待重新同步；这不是速度指令失效计时器。

- 前进+0.3m/s、角速度0：`A5 5A 10 04 2C 01 00 00 DE D2`。
- 原地左转+1rad/s：`A5 5A 10 04 00 00 E8 03 EA 34`。
- 原地右转−1rad/s：`A5 5A 10 04 00 00 18 FC DB 39`。
- 线速度和角速度同时清零：`A5 5A 10 04 00 00 00 00 92 9D`。
- FPGA内部换算：`forward_q12 = round(speed_mmps × 4096 / 1000)`，`yaw_q12 = round(yaw_mradps × 4096 / 1000)`；300mm/s对应1229，1000mrad/s对应4096。观测缩放由原模块完成，上位机不要额外乘2或1.3。
- 兼容旧8字节帧（版本`10`、长度`02`、仅线速度）；接收旧帧时角速度同时置0，不会保留上次转向指令。新软件统一发送10字节帧。

RK3588发送示例（把工具文件放在Python可导入的位置，并安装pyserial）：

```python
import time
import serial
from speed_command import send_speed

# 替换为RK3588实际启用的3.3V TTL UART设备节点。
with serial.Serial("/dev/ttyYOUR_UART", 230400, timeout=0.1,
                   write_timeout=0.5) as port:
    try:
        for _ in range(50):          # 示例：持续1秒发送前进目标
            send_speed(port, 0.3, 0.0)
            time.sleep(0.02)        # 50Hz更新足够，不是FPGA推理周期
    finally:
        send_speed(port, 0.0, 0.0)       # 结束时显式发送零速度目标
        port.flush()
```

接收规则：首个有效速度帧之前维持原红外/编译期速度来源；收到后由串口同时接管前进速度和转向角速度，后续保持最后有效值，直到下一帧或FPGA复位。**当前断线不会自动清零，结束运动需显式发送线速度0、角速度0；复位后恢复原来源。** 串口接管后红外方向键不覆盖这两个目标，红外高度和急停保留。线速度优先级为急停 → `FIXED_FORWARD_ENABLE`固定指令 → 有效串口速度 → 原红外/编译期速度；角速度优先级为急停 → 有效串口角速度 → 原红外/编译期角速度；使用串口时保持 `FIXED_FORWARD_ENABLE=0`，默认 `UART_SPEED_ENABLE=1`。

`send_speed(port, 0.0, 0.0)`代表模型的零前进、零转向目标，模型仍可驱动轮子纠偏维持平衡，不等于关闭PWM或急停。该接口在 `MODEL_ENABLE=1` 时送入模型；手动模式继续使用原 `TARGET_LEFT_MPS` / `TARGET_RIGHT_MPS`，不通过此接口直控轮子。

## 7.4 反馈与当前实现状态

FPGA到上位机的遥测仍使用原V2协议：100Hz、帧头 `A5 5A`、版本2、120字节数据、CRC16，共126字节。解析代码为 `tools/fpga_telemetry/protocol.py`。重点读取：

| 反馈字段 | 含义 |
| --- | --- |
| `forward_command` | FPGA当前采用的车体目标速度，m/s；可核对串口指令是否进入控制链 |
| `yaw_command` | FPGA当前采用的目标角速度，rad/s；串口转向指令的反馈值 |
| `left_target` / `right_target` | 模型经执行映射后的双轮目标，m/s |
| `left_reference` / `right_reference` | 速度环当前使用的参考速度，m/s |
| `left_speed` / `right_speed` | 编码器测得的左右轮速度，m/s |
| `active`、故障字段 | 模型是否运行、传感器和执行器状态 |

遥测里的包序号是反馈帧序号，不是上位机指令应答序号；当前没有新增ACK报文。看到 `forward_command` 更新，只能确认目标已进入控制链，不能据此断言实际速度已跟上。

速度帧接收由 `fpga/src/uart_speed_rx.v` 实现，`fpga/src/main.v` 完成顶层接入，包含 CRC / 范围检查、双目标原子更新与 Q12 换算。独立 UART 的构建记录见 `tools/uart_speed_validation/manifest.json`；共同工程的命令入口及位流配置见[控制适配说明](FORK.md)。

## 7.6 遥控器目标值与上位机推荐值

遥控器代码为 `fpga/src/ir_remote_control.v`。以下数值是送入模型的车体指令，不是直接发给电机的PWM或最终轮速：

| 按键 | NEC键码/十六进制 | 目标线速度/m·s⁻¹ | 目标角速度/rad·s⁻¹ | 对应Q12 |
| --- | --- | --- | --- | --- |
| 2，前进 | `18` | +0.3 | 0 | `forward_q12=1229` |
| 8，后退 | `52` | −0.3 | 0 | `forward_q12=-1229` |
| 4，左转 | `08` | 0 | +1.0 | `yaw_q12=4096` |
| 6，右转 | `5A` | 0 | −1.0 | `yaw_q12=-4096` |
| 松键/无有效方向键 | — | 0 | 0 | 方向指令回零，模型继续平衡 |

方向键是按住输出固定值，NEC重复码延长有效期；不是按一次0.1、再按一次0.2的累加方式。松开后没有重复码约180ms，方向指令回零。升降键保留高度，5键急停锁存，均沿用现有逻辑。

**上位机推荐沿用遥控器的目标档位：正常前进+0.3m/s；转向目标左+1.0rad/s、右−1.0rad/s；结束动作给0。** 对原4500，仿真给+0.3m/s时均速约+0.252m/s；给左+1.0rad/s时约+1.215rad/s，给右−1.0rad/s时约−1.144rad/s，实际硬件仍需看遥测。

- 直接调用：前进`send_speed(port, 0.3, 0.0)`；左转`send_speed(port, 0.0, 1.0)`；右转`send_speed(port, 0.0, -1.0)`；结束`send_speed(port, 0.0, 0.0)`。不要把角速度当作前进速度发送。
- 后退不作为推荐常用动作；优先“线速度给0、角速度给±1 → 根据朝向反馈确认转180° → 两者清零 → 前进给+0.3m/s”。该顺序由上位机执行，FPGA不会自动旋转或累计转角。
- 串口首次接管后，红外方向键不再覆盖线速度和角速度；红外高度、急停仍保留。恢复红外方向控制需复位，或编译时设置`UART_SPEED_ENABLE=0`。
- 串口保持最后有效的线速度和角速度，不能依赖遥控器180ms松键回零；上位机结束动作时应显式发送`send_speed(port, 0.0, 0.0)`。
