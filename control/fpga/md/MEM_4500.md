# model_4500 接入与指令接口

当前工程：`/home/cyd/fpga/fpga`，顶层 `src/main.v`，时钟 50MHz。
入口 `src/mem_policy.v` 已接六轴 BMI088、原始 AB 编码器、四路舵机和双轮 PID；OLED 保留左右轮实际 m/s 与六轴物理量显示。

## 最常改的参数（main.v 顶部）

```verilog
parameter MODEL_ENABLE=1'b1;
parameter CONTROL_ENABLE=1'b1;
parameter EMERGENCY_STOP=1'b0;
parameter real COMMAND_FORWARD_MPS=0.00;
parameter real COMMAND_YAW_RADPS=0.00;
parameter real COMMAND_HEIGHT_M=0.1305;
```

| 参数 | 用法 |
|---|---|
| `MODEL_ENABLE` | 1：模型直接控制舵机/双轮目标；0：回到原来的 `TARGET_LEFT/RIGHT_MPS` 和四路 `SERVO_*_US` 手动参数 |
| `CONTROL_ENABLE` | 1运行；0停轮、模型舵机保持最后姿态；重新使能清除运行故障锁存 |
| `EMERGENCY_STOP` | 1急停，关闭电机PWM；解除后还需复位，或把运行使能先置0再置1 |
| `COMMAND_FORWARD_MPS` | 前进速度，单位m/s；正前进、负后退；使用训练范围 -0.6～+0.6 |
| `COMMAND_YAW_RADPS` | 转向角速度，单位rad/s；正左转、负右转；使用训练范围 -2.9～+2.9 |
| `COMMAND_HEIGHT_M` | 底盘高度，单位m；调大升高、调小降低；自动夹到Q12端点348～778，约0.085～0.190m |
| `IMU_BIAS_SAMPLES` | 默认200，上电约2秒保持静止，完成陀螺零偏标定后才运行模型 |
| `MOTOR_ENABLE` / `SERVO_ENABLE` | 独立执行器开关；模型模式下任一关闭，会阻止模型控制运行 |

升降不需要独立方向位：例如把高度从 `0.1305` 改成 `0.15` 即升高，改成 `0.10` 即降低。当前高度参数直接作为高度目标，没有额外的升降轨迹规划。
跳跃观测位固定为0（`rl_observation_v5.v` 的第9项）；本4500模型训练配置关闭跳跃，未接跳跃动作流程。

这些 `parameter` 是**编译时常量**，修改后重新综合、布局布线并烧录。后续接按键、UART或上位机时，直接把 `main.v` 中下面这些wire的右端换成寄存器/模块输出：

| 运行时信号 | 格式 |
|---|---|
| `command_run` | 1运行，0停轮/清除运行故障 |
| `command_emergency_stop` | 1急停 |
| `command_forward_q12` | signed24，m/s×4096；0.1m/s约410 |
| `command_yaw_q12` | signed24，rad/s×4096 |
| `command_height_q12` | signed24，m×4096；130.5mm约535，150mm约614/615 |

以后接外部接口时需将异步输入同步到clk域，并保证多位指令同一拍更新；不要新增未约束的顶层管脚。现有物理管脚约束保持原样。

## 模型数据和执行链

1. `bmi088.v` 读取 AX/AY/AZ/GX/GY/GZ；量程±3g、±2000dps。
2. `imu_fusion.v` 用标定后的轴向（X右、Y前、Z上）生成rad/s与重力单位向量；直立重力为[0,0,-1]。此处陀螺换算用4466，不能沿用±1000dps的2234。
3. `rl_observation_v5.v` 生成28维当前观测、五帧140维历史；启动时五帧均填第一帧，历史顺序为旧→新，包含当前帧。原始编码器左右均乘-1转为模型的关节方向。
4. `rl_policy_tick_v5.v` 默认每400000时钟即8ms取一次快照；`fc_v4_top.v` 用 `$readmemh` 初始化ROM并执行七层定点推理。
5. `policy_action_map.v`：左轮目标 `-action2×600 mm/s`，右轮 `+action5×600 mm/s`；继续交给原来的 `motor520_closed_loop.v` 速度PID，编码器反馈10ms一帧。
6. 舵机脉宽为 `机械零位 + 高度IK前馈 + 已标定方向×action×19µs`；动作限幅±1，腿部残差±0.03rad。IK与观测使用同一帧高度；方向为[+1,-1,+1,+1]。`servo_driver.v` 模型模式关闭二次方向变换，50Hz输出四路PWM。
7. 上一帧模型动作回填观测，使用归一化动作，不能填PWM或mm/s。

`MODEL_ENABLE=1` 时，左右轮速手动参数不会成为模型故障后的备用速度。前进指令0表示模型停车/平衡目标，模型仍可能给轮子小的纠偏速度；要禁止电机输出，用运行使能或急停。

`src/mem/weights.mem`、`bias.mem`、`elu.mem` 从 `/home/cyd/fpga/model/mem_4500` 导出文件复制；`model_manifest.json` 记录结构与来源。四份 `leg_ik_*.mem` 来自参考工程的高度IK表。

`.mem` 在综合时装入FPGA ROM，运行时不读取Linux文件系统。工程和烧录文件包含模型参数；改 `.mem` 后也需要重新编译。`build_oled.tcl` 已开启 `-bit_incl_bsram_init 1`。路径相对工程目录，构建请使用：

```bash
cd /home/cyd/fpga/fpga
bash build_oled.sh > build_oled.log 2>&1
```

## 留出的标志与观察点

这些是内部逻辑信号，未新增物理调试引脚，可在仿真中直接观察；若要在板上持续读取，后续可接UART或逻辑分析仪，并保留相关调试网表信号。

| main.v 信号 | 含义 |
|---|---|
| `sensor_ready` / `sensor_error` / `sensor_error_code` | BMI初始化/通信状态 |
| `imu_calibrating` / `imu_bias_suspect` | 正在零偏标定/标定时可能在运动；可疑偏置需静止后复位重新标定 |
| `imu_accel_rejected` | 本帧加速度不可信，融合暂用陀螺传播 |
| `model_ready` | 传感器及模型无故障，具备运行条件 |
| `model_active` | 已使能、收到第一帧有效动作并正在控制执行器 |
| `model_action_valid` | 每次推理发布动作的一拍脉冲 |
| `model_fault[2:0]` | bit0传感器/运行条件异常；bit1超出8ms截止时间；bit2核心错误、饱和或帧号不匹配 |
| `model_completed_frames` | 成功推理计数 |
| `model_inference_cycles` | 单次核心推理时钟数，实测83534，50MHz下约1.671ms（另加观测/装载开销） |
| `model_executed_actions[143:0]` | 六个signed24 Q12动作，action0位于最低24位 |
| `model_left_mmps` / `model_right_mmps` | 模型输出的双轮目标速度，单位mm/s |
| `model_lh/lk/rh/rk_us` | 四路最终物理舵机脉宽，µs |
| `left/right_speed_cms` | 双轮编码器反馈，单位0.01m/s |
| `left/right_motor_fault` | 原速度PID故障：1反馈超时、2堵转、3运动方向相反 |

`model_status_flags[7:0]`：bit0 BMI ready；bit1正在标定；bit2偏置可疑；bit3样本超时；bit4模型故障；bit5执行器故障/急停/执行器禁用；bit6运行停止锁存；bit7 active。

传感器样本超过50ms未更新、模型超时/错误、PID异常或急停时停轮，舵机保持最后姿态；不会自行重启。`CONTROL_ENABLE`先0再1可清除运行锁存；陀螺偏置可疑需要复位。

## 六轴全部显示横杠时的诊断

`AX: -.--g` / `GX: ----.-` 表示六轴样本不可用：BMI未初始化、通信出错或尚未收到有效样本。这个判断直接来自BMI驱动，不受模型使能或IMU融合校准状态控制。

诊断修订版在六轴不可用时把首行轮速标题切换为 `BMI088: WAIT` 或 `BMI088: ERR x`；数据恢复后自动显示原轮速标题。模型和电机控制逻辑没有因此改变。

| ERR码 | 含义 |
|---|---|
| 1 | 地址写阶段无ACK |
| 2 | 寄存器/控制字节无ACK |
| 3 | 地址读阶段或写数据阶段无ACK |
| 4 | SCL无法拉高，等待超时 |
| 5 | 空闲SDA持续为低，等待超时 |
| 6 | IIC引擎/事务状态异常 |
| 7 | 芯片ID不匹配 |
| 8 | 配置寄存器回读校验不匹配 |

重新烧录FPGA不会同时复位仍在供电的传感器。若下载过程中中断IIC事务，先将FPGA与BMI088一起断电重启，观察是否恢复；若仍报错，以显示出的具体错误码继续定位。

## 轮子/舵机无响应时的板上状态显示

`main.v` 的 `OLED_MODEL_DEBUG=1`（诊断配置）将首行轮速换成：

```text
M:81 F:0 N:1234 E:00
```

六轴物理量仍显示在下面三行。BMI未就绪/通信错误时，优先显示BMI WAIT/ERR。将 `OLED_MODEL_DEBUG=0` 并重新编译可恢复轮速首行。所有数字为十六进制：

- M：`model_status_flags`；81通常表示BMI就绪且模型正在运行；03通常表示BMI就绪、仍在标定。bit6表示运行停止已锁存，bit4表示模型故障，bit2表示标定时运动可疑。
- F：`model_fault`；0无模型故障，bit0运行条件/传感器故障，bit1超时，bit2推理核错误。可能按位组合；例如5含bit0及bit2。
- N：已完成推理帧数的低16位，正常约每秒增加125，会回绕；持续为0000表示未完成有效推理。
- E：左/右电机最近故障，各一位。0无记录，1编码器反馈超时，2堵转，3实际运动方向相反。记录一直保留到复位或command_run=0，避免停机后PID清零掩盖故障。

此诊断版只增加显示与故障记录，未提高目标速度、放大动作或关闭停止保护。传感器通信恢复不能清除已经锁存的模型停机，复位后需保持静止重新标定。

模型状态诊断版 `impl/pnr/fpga_model_debug.fs` 已完成综合/布局布线，50MHz通过，Fmax 55.830MHz，setup/hold违规均为0；屏幕像素与完整模型集成测试均通过。本代理未执行烧录。烧录后请报告首行M/F/N/E，以及N是否持续变化。
