# 底盘与 RL 运动控制联调说明

11-04整车交付：原4500与导航已在PNR100同片实现，CPU136KiB、双串口；CH为主机输入，P11-40为控制遥测，P11-39外部速度输入关闭。遥控0键超声波只限制手动前进，网页停止保留平衡，IR5为既有控制锁停。当前来源、数值和验收边界见[阶段交接](../3_guide/project_handover_20261104.md)。

本说明介绍导航与原 4500 控制的代码边界、命令适配、测量反馈和联调方法。字段和时序定义见 [ICD](../2_interface/icd.md)，寄存器见[寄存器表](../2_interface/regmap.md)，接线见[引脚表](../2_interface/pinout.md)。

## 1. 同片集成结构

导航 RTL、PicoRV32 固件与原 4500 控制集成在同一个 FPGA 顶层。控制侧采集 BMI088 与编码器，运行姿态融合、125 Hz 策略、四路舵机及双轮速度闭环；导航侧使用同源测量维护位姿并生成车体运动目标。

```text
雷达 → 点云 / 地图 / 定位 / 规划
                         ↓
NAV SAFE → 命令租约与单位适配 → 原 4500 策略 → 舵机 / 轮速闭环
                         ↑                        │
                BMI088 / 编码器 ←────── 运动反馈 ──┘
```

| 模块 | 入口与作用 |
|---|---|
| 导航 | `rtl/`、`fw/`：感知、地图、定位、规划与安全速度 |
| 控制 | `control/fpga/src/`：传感器、策略、执行器与遥测 |
| 联合适配 | `integration/g2/`：共同顶层、命令租约、单位与反馈适配 |
| 传感器诊断 | `integration/g3/`：独立采集与反馈检查 |

BMI088 使用一个 I2C 主机，导航共享控制侧样本并转换坐标、单位和时间。策略内部保持原训练坐标、观测缩放与动作顺序。

SYN50 / PNR63 的命令授权、红外覆盖、BMI 总线恢复及固件 INIT 配置见[PNR63 实现报告](../4_design/g2_PNR63_review_20261028.md)，控制来源见[维护说明](../../control/FORK.md)。

## 2. 系统边界

### 2.1 导航侧负责什么

`nav_subsystem` 和导航固件负责：

- 雷达帧接收、点云、局部地图和定位；
- 无图 / 有图导航、目标跟踪、探索和局部规划；
- 产生机身坐标系下的期望速度；
- 通过 `safety_guard` 执行最终速度限幅、加速度斜坡、命令看门狗和急停；
- 消费底盘回传的**对地速度**并积分位姿。

导航输出的是运动目标，不是电机力矩、关节角或腿端轨迹。

### 2.2 RL 底盘侧负责什么

RL 组负责：

- 接收导航的期望速度和运动模式；
- 结合姿态、腿长、轮速、接触状态等观测完成速度跟踪和轮腿控制；
- 将策略输出转换为执行器命令，并完成执行器侧限幅和故障降级；
- 估计机身坐标系下的实际**对地速度**，按约定产生 `odo_valid` 和 `odo_*`；
- 在策略异常、观测超时、通信丢失、姿态倾覆或执行器故障时保持平衡或安全停机。

RL 不得绕过导航侧 `safety_guard`，也不得把自己的内部电机速度或期望速度直接伪装成 `odo_*`。

## 3. 复用现有控制工程的代码边界

外部主工程的实际链路为 `bmi088` → `imu_fusion` / `rl_observation_v5` → `mem_policy` → 高度 IK 与舵机、双轮目标速度 → 速度 PID / PWM。集成时复用这些模块；以下是逻辑边界，不要求为整理目录重写算法：

```text
platform/          FPGA/MCU/RK3588 适配、时钟域、引脚、UART/CAN
interface/         ch_* 解码、valid/seq 检查、odo_* 打包
policy/            RL 推理、模式选择、期望速度跟踪
state_estimator/   姿态、腿长、轮速、接触状态、对地速度
actuator/          腿轮执行器控制、执行器限幅
safety/            RL 侧故障降级、倾覆保护、通信超时
sim/               仿真环境、传感器回放、策略离线评估
tests/             接口单测、故障注入、架空和实车验收
```

在本仓库里，上面的 RTL 部分放 `rtl/chassis/`（testbench 在 `rtl/chassis/tb/`，定点参考模型在 `model/`），训练与仿真代码可以留在底盘组自己的仓库。

### FPGA 内部署（推荐，也是比赛的目标形态）

控制主工程与导航都使用 50 MHz。目标是在同一 FPGA 内将导航安全输出接到现有 `command_forward_q12` / `command_yaw_q12` 入口：

```text
nav_subsystem.ch_* → interface → policy/state_estimator → actuator
                         ↑                         ↓
                 ext_stop / safety          odo_* → nav_subsystem
```

现有控制顶层使用低有效 `reset_n`，部分模块为异步复位；导航使用同步高有效 `rst`。共同顶层需明确极性、同步释放及传感器初始化完成条件，不能只把端口同名相连。底盘模块用同一个 `clk` 时不需要跨时钟域处理；确需其他时钟时，跨时钟域不能直接采样单拍信号，
应使用 `rtl/common/nav_cdc.v` 的脉冲同步或 `nav_async_fifo.v`，并在接口层恢复本地的 `cmd_valid` / `odo_valid` 事件。

### 现有串口入口与任务接口的区别

控制仓库最新 UART 是底盘调试/上位机速度入口，RL 推理仍在 FPGA。它与导航 `NV` 任务协议不同：

```text
当前独立控制：RK3588 / PC → UART速度帧 → FPGA模型命令
整车目标链路：RK3588 / PC → 导航任务 → SAFE → 控制模型命令
```

独立控制工程的速度帧为 10 字节：`A5 5A 10 04` + int16 小端前进速度（mm/s）+ int16 小端偏航角速度（mrad/s）+ CRC16。字段范围为 ±600 mm/s、±2900 mrad/s，串口为 230400 8N1；V2 遥测为 100 Hz、126 字节。

独立 UART 在首帧接管后保持最后有效目标，10 ms 接收超时用于丢弃残帧。共同双串口工程关闭 P11-39 速度输入，由 NAV SAFE 和命令租约管理目标；P11-40 继续输出遥测。红外方向键提供本地覆盖，按释放超时交还导航。命令授权与任务停稳参数见 ICD 第 1 节。

### 模型与共享 IMU 的已知合同

- 原 4500 模型：当前观测 28 维 + 含当前帧的五帧历史 140 维；历史编码为 3 维潜变量，拼接成 31 维 actor 输入，输出左髋、左膝、左轮、右髋、右膝、右轮六动作。初始化用第一帧重复填满历史。
- `mem_policy.PERIOD_CLKS=400000`，50 MHz 下目标周期 8 ms / 125 Hz；实际完成周期、最坏推理延迟及雷达负载下抖动仍需联合构建/实测，不能用参数值代替测量。
- 命令、观测、激活、输出为 signed 24-bit Q12。导航适配只把 mm/s、mrad/s 换成 m/s、rad/s 的 Q12，观测缩放 ×2 / ×1.3 由原观测模块完成，不重复缩放。
- 轮动作语义：左轮物理前进目标 `-action2 × 0.6 m/s`，右轮 `+action5 × 0.6 m/s`；舵机为高度 IK 基准加动作修正。不得把动作解释成电机力矩或直接 PWM。
- 当前权重 40704×16 bit、偏置 425×32 bit、ELU 表 3073×24 bit；旧“约 5000 参数 / RL ≤6 BSRAM”预算作废。实际 ROM 拼装、推理核及整车资源以新综合/布线报告为准。
- BMI088 配置为加速度 ±3 g / 100 Hz、陀螺 ±2000 dps / 2 kHz；采集循环为约 10 ms 轮询，芯片 ODR 不等于向外发布频率。200 个样本静止零偏校准约 2 s；融合输出角速度及重力向量，不输出绝对 yaw。
- 控制机体系 X 右、Y 前、Z 上；导航 X 前、Y 左、Z 上。向导航共享三轴向量时应按 `(Xn,Yn,Zn)=(Yc,-Xc,Zc)` 换轴，随后核对 pitch/roll 符号与零位；底盘模型内部既有坐标不改。导航需要的角度、时间戳和有效性由适配层产生。

## 4. FPGA 内部接口契约

### 4.1 导航到 RL

`nav_subsystem` 在每个 `SAFE.TICK_US` 输出节拍产生一次 `ch_valid` 单拍。数值在该拍有效，RL 接口层应只在 `ch_valid=1` 时采纳一条新命令。

| 信号 | 位宽 / 类型 | 单位 | 语义 |
|---|---:|---|---|
| `ch_vx` | signed 16 bit | mm/s | 机身 X 轴前向期望速度 |
| `ch_vy` | signed 16 bit | mm/s | 机身 Y 轴左向期望速度；非全向底盘应为 0 |
| `ch_wz` | signed 16 bit | mrad/s | 绕 Z 轴期望角速度；正值为从上方看逆时针、车头向左转 |
| `ch_mode` | 8 bit | — | 固件现在只写 0（正常）与 4（主机下发 `mode estop`，速度已为 0）。拟定编码：低 4 位行为 / 地形模式，第 5:4 位姿态请求，跳跃预留（[chassis_review.md](chassis_review.md) 第 3.8 节、第 4 节），D2.1 冻结 |
| `ch_stop` | 1 bit | — | 导航置位后下一节拍目标直接为0，不经斜坡；旧保持平衡意图与控制硬停断驱动不同，最终映射在G1冻结 |
| `ch_wdog` | 1 bit | — | 导航命令超过 `SAFE.WD_US`（200 ms）未更新：速度**按加速度限制减到 0**；复位后第一次指令前也为 1 |
| `ch_valid` | 1 bit | — | 新速度输出单拍（当前缺省每 1 ms 一次；控制策略为 8 ms，接收锁存与策略采样分开） |
| `ch_seq` | 16 bit | — | 输出序号，用于检测丢周期、重复或回绕 |

导航固件每 100 ms 提交一次新指令，节拍之间 `safety_guard` 按斜坡逼近；导航实际会发的范围（前进 ≤ 0.5 m/s、倒车 0.15 m/s、
角速度 ≤ 1.2 rad/s、纯原地转向）见 [icd.md](../2_interface/icd.md) 第 4 节。控制仓库推荐前进 0.3 m/s、转向 ±1 rad/s，但明确原 4500 后退效果不足；这些推荐值和仿真响应不是整车实测包络。先冻结实测允许范围并限制导航，再按真实导航指令回放。倒车脱困在策略证明可用前应禁用或另验收替代动作；“转 180° 再前进”需要足迹检查和航向反馈，不可无条件替代倒车。

坐标约定：X 前、Y 左、Z 上。RL 机械坐标不同于此约定时，必须在 `interface/` 适配层显式换轴或取反，不得修改导航算法中的坐标定义。

`ch_stop` 本身不切断电机电源。导航旧设计意图是零目标保持平衡；控制 `external_fault` 则会关闭轮驱动。G1须明确分级语义并验证，不能直接连接两信号却宣称仍平衡。正常车体零目标与单轮零目标也不同：当前 `MOTOR_CLOSED_LOOP_AT_ZERO=0` 在单轮目标零时禁PWM/清PID。

### 4.2 RL 到导航

| 信号 | 位宽 / 类型 | 单位 | 语义 |
|---|---:|---|---|
| `odo_vx` | signed 16 bit | mm/s | 机身 X 轴对地速度 |
| `odo_vy` | signed 16 bit | mm/s | 机身 Y 轴对地速度；非全向底盘通常为 0 |
| `odo_wz` | signed 16 bit | mrad/s | 机身对地角速度 |
| `odo_valid` | 1 bit | — | 新里程计样本单拍 |

`odo_*` 要提供有有效性说明的机身对地速度估计；当前尚无已验收的接触状态与对地反馈，不得把拟融合字段写成实测事实。以下内容不能直接作为 `odo_*`：电机转速、单个轮子的切向速度、未经车身俯仰补偿的轮速、导航下发的期望速度、重复发送的上一样本。

导航固件的用法决定了三条硬要求（详见 [icd.md](../2_interface/icd.md) 第 4 节、[chassis_review.md](chassis_review.md) 第 3.6 节）：

- `odo_wz` 用 IMU 陀螺 z 轴角速度（导航用它积分航向，并在静止时估计零偏），不用左右轮速差；
- `odo_valid` 固定 50–100 Hz：导航位姿历史 64 项、每个样本一项，1 kHz 时只能覆盖 64 ms，雷达帧与目标的时间补偿会失效；
- 当前导航零偏逻辑以精确零平移反馈和小角速度作为条件；只有独立静止判定成立时才能归零。目标为零或正在平衡不代表静止，不能为触发零偏估计而覆盖真实反馈。

控制当前遥测提供左右轮实际速度、融合角速度、目标高度及状态，但尚无已核验的导航 `odo_*` 对地速度适配。须从有符号轮速、机身俯仰及有效条件形成反馈，俯仰补偿正负号按编码器和坐标定义推导并实测；不能笼统地“减去”一个角速度。编码器测速窗 10 ms 与策略 8 ms 不同，需保留样本更新事件并检查新鲜度。

拟增加底盘状态字 `odo_stat` 与腿长 `odo_l0_mm` 的旧方案仍未进入本地导航 RTL/YAML；旧提案见 [chassis_review.md](chassis_review.md) 历史第 4 节。现有 `model_status_flags` 不是该状态字，不能直接逐位转接。先冻结固定导航高度和必要的就绪/故障反馈，动态高度及跳跃按后续能力另行扩展。

FPGA 在采到 `odo_valid` 时用 `SYS.TIME_US` 产生 `ODO_TS`，并递增 `ODO_CNT`。输入接口本身不携带外部时间戳；如果外部控制器有时间戳，应在桥接层记录并说明映射关系，不要把外部时钟值直接写成 FPGA 时间。

### 4.3 采样、复位和握手

- `ch_valid` 和 `odo_valid` 都是事件脉冲，不是保持到下一次采样的电平。
- 接口层按 `ch_valid` 锁存；`ch_seq` 用于检查接收事件。策略 125 Hz 读取最近值时本来就会跨过多个 1 kHz 输出节拍，不应把这种正常抽样误判为故障。
- `odo_valid` 的周期应固定并记录；导航允许因没有新样本而暂时不积分，但不能用期望速度填补。
- 复位后导航没有有效底盘命令，安全逻辑处于看门狗触发语义；RL 侧必须先完成初始化和自检，再允许执行器运动。
- 跨时钟域必须做同步或 FIFO；不能把 FPGA 单拍信号直接接到异步 RL 时钟域。
- 所有计数器和时间戳按 32 位微秒回绕设计，差值比较必须使用模回绕安全的无符号方式。

## 5. SAFE 寄存器与固件对齐

SAFE 基址为 `0x5000`，完整定义以 `config/regmap.yaml` 为准：

| 寄存器 | 地址 | 用途 |
|---|---:|---|
| `SAFE.CTRL` | `0x5000` | `ENABLE`、`HOLONOMIC`、软件 `ESTOP` |
| `SAFE.LIM_V` | `0x5004` | `VX_MAX`、`VY_MAX`，mm/s |
| `SAFE.LIM_W` | `0x5008` | 最大角速度，mrad/s |
| `SAFE.LIM_A` | `0x500C` | 每个输出节拍允许的速度 / 角速度变化量 |
| `SAFE.TICK_US` | `0x5010` | 速度输出节拍，默认 1000 us |
| `SAFE.WD_US` | `0x5014` | 命令看门狗，默认 200000 us |
| `SAFE.CMD_V` | `0x5018` | `vx`、`vy`；先写此寄存器 |
| `SAFE.CMD_W` | `0x501C` | `wz`、`mode`；写此寄存器提交整条命令 |
| `SAFE.OUT_V/W` | `0x5020` / `0x5024` | 实际限幅和 ramp 后的输出 |
| `SAFE.STAT` | `0x5028` | 看门狗、急停、外部急停和序号状态 |
| `SAFE.EXT_MASK` | `0x502C` | 选择启用的外部急停输入 |
| `SAFE.ODO_V/W/TS/CNT` | `0x5030`–`0x503C` | 最新里程计、FPGA 接收时间和样本计数 |

固件 `hal_send_cmd()` 先写 `CMD_V`，再写 `CMD_W` 触发提交。RL 组若需要主机调试，应复用该语义；不要只写 `CMD_V` 后假定速度已经更新。

`SAFE.LIM_A` 的单位是"每个输出节拍"：缺省 `TICK_US = 1000` 时 DV = 2 即 2 m/s²，DV 最小只能到 1 m/s²。自平衡车需要更小的加速度时，
可在冻结输出周期时评估更长节拍或更细斜坡表示；旧建议的 10 ms 与当前 8 ms 策略周期并不相同，不能为凑周期直接改常量。`tools/board_init.py` 目前只写 `LIM_V/LIM_W/CTRL`，`LIM_A/TICK_US/WD_US/EXT_MASK` 的初始化仍需在导航适配阶段补上。

当前默认值是开发默认值，不是实车标定结果。底盘组必须提供实测的：是否全向、最大前后向速度、最大横移速度、最大角速度、加速度能力、外接圆半径和站立腿长（各姿态）。确认后同步更新：

- `lp_cfg.caps`；
- `SAFE.LIM_V/LIM_W/LIM_A`；
- `config/nav_params.yaml` 或对应生成配置；
- `docs/4_design/platform.md` 和测试记录。

## 6. 安全边界与故障策略

### 导航侧已经提供

- 速度限幅；
- 每输出节拍的加速度斜坡；
- 命令看门狗；
- 软件急停；
- 外部急停输入选择；
- `ch_stop`、`ch_wdog` 和输出序号。

导航安全接口限制车体目标；RL 为保持平衡产生的瞬时轮速可以与车体目标不同，不能把 SAFE 的车体速度上限机械地用作每个电机的瞬时轮速上限。底盘执行器限幅及平衡包络单独验证。

### 控制保护与系统故障处理

`mem_policy.v` 提供传感器初始化、零偏门控、50 ms 样本超时、推理与执行器故障锁停；`main.v` 管理红外锁停与电机故障联动。导航 `ch_stop` 请求零车体目标并保留平衡，控制锁停关闭相应轮输出。共同工程通过命令租约管理目标新鲜度和恢复授权。

适配时补齐或核对：

- 策略推理超时、定点溢出/饱和及故障锁存后的动作（当前整数 RTL 无浮点 NaN / Inf）；
- 观测超时、传感器断线、接触状态不可信时的动作；
- `ch_seq` 丢失或重复时的处理；
- 姿态倾覆、腿长越界、轮滑、执行器过流和通信断链的降级；
- 从运动到保持平衡、降速、趴下或断电的状态机；
- 故障恢复是否需要人工确认。

物理急停必须独立接入 `ext_stop` 或底盘硬件安全回路，并配置 `SAFE.EXT_MASK`。不能把串口命令、软件 `ch_stop` 或 RL 自己的故障标志当作唯一急停。

物理急停回路及其逻辑输入按新引脚冻结表落实。旧方案 P11 第 8 针已被实际控制工程的 BMI088 SCL 占用，不能沿用为急停脚。若采用常闭触点，须同时设计上拉/下拉及断线检测方式，不能仅凭“低有效 + 上拉”就声称断线必然急停。共同顶层负责同步去抖、极性转换和 `SAFE.EXT_MASK` 初始化；下载/复位期间的驱动状态须核对外部电路。

注意：当前 `ext_stop` 在板级顶层仍为占位，真实按钮接入、极性、去抖和故障安全电平需要在整车顶层中明确并测试。

## 7. 仿真与回放复用

不要另起一套单位或速度结构。优先复用仓库已有接口：

- `fw/include/nav_types.h`：`nav_cmd_t`、`nav_chassis_caps_t`；
- `fw/hal/hal.h`：`hal_send_cmd()`、`hal_odom()`；
- `fw/test/hal_sim.c`：主机侧 HAL 和队列模型；
- `sim/closed_loop/`：导航闭环场景和假雷达；
- `rtl/plan/safety_guard.v` 及其 testbench；
- `tools/nav_host.py` / `docs/2_interface/icd.md`：任务和状态报文，不替代底盘实时接口。

导航组可以提供两样东西帮助训练与验证：闭环仿真里真实导航固件产生的指令序列（训练与回放的指令分布）；
以及把底盘 MuJoCo 模型接进导航闭环仿真的适配（`run_cl.py --bot`，底盘侧给出"输入 (vx, wz)、输出真值位姿 / IMU 帧 / 里程计"的步进接口），
这样能在上车之前做"导航 + 底盘"联合仿真（[chassis_review.md](chassis_review.md) 第 3.11 节）。

最少应有以下回放和故障用例：

1. 正负 `vx`、正负 `wz` 的方向与单位；
2. 全向开 / 关时 `vy` 的行为；
3. 速度限幅和加速度斜坡；
4. `ch_valid` 丢周期、重复 `ch_seq`；
5. 看门狗、软件急停和外部急停；
6. `odo_valid` 丢样本、突发延迟和时间戳回绕；
7. 轮速与姿态不一致、打滑和对地速度偏差；
8. 定点异常、推理超时、执行器故障和通信断链；
9. 导航雷达流负载下的控制周期和最坏延迟。

## 8. 推荐联调顺序

### 阶段 0：接口冻结

双方共同签字确认坐标、符号、单位、位宽、`ch_valid/odo_valid` 语义、控制周期、看门狗、复位状态和故障降级。特别确认 `odo_*` 是对地速度，以及 `wz > 0` 是否为左转。
以 [chassis_review.md](chassis_review.md) 的 2026-10-21 问题关闭表为输入，优先冻结模型/位流版本、命令所有权、IMU 换轴/时间戳、对地速度、固定导航姿态和停止语义。已实现的 I2C 驱动、AB 编码器与转向不重新列为开发任务。

### 阶段 1：整车顶层连接

先抽出已有 `main.v` 的控制链，增加导航命令与反馈适配，再建立共同顶层、IMU 扇出、必要地址译码、复位和约束；桩模块只在隔离接口问题时使用。首次联合构建前核算 ROM/BSRAM，旧 ≤6 块预算已失效。共同顶层完成 `ch_*`、`odo_*`、`ext_stop` 的真实连接，`board_init.py` 补上 SAFE 初始化。最新 UART 代码有独立上板价值，但它不能替代同片导航+控制的联合位流验收。

### 阶段 2：架空测试

轮子离地、物理急停在手边：

1. 默认无命令时电机不应产生非预期运动；
2. 给正 `vx`，确认车体前向；给负 `vx`，确认后向；
3. 给正 `wz`，确认从上方看左转；
4. 验证 `ch_valid` 消费、限幅、ramp 和 `ch_seq`；
5. 停止发送命令，确认看门狗在约定时间内进入安全状态；
6. 触发软件和物理急停，确认速度归零且策略仍按定义保持平衡或安全降级。

### 阶段 3：推车里程计

关闭驱动或由安全人员推车：直线推行已知距离，确认 `odo_vx/vy` 方向和单位；原地转已知角度，确认 `odo_wz` 符号。检查 `ODO_CNT` 单调增加、`ODO_TS` 合理、导航位姿积分没有因丢样本跳变。

### 阶段 4：低速落地

从经实测允许的低限幅开始，先空旷地面直行和原地转，再验证停车、看门狗和急停。短距离倒车单独列能力门槛；未通过时不允许导航使用倒车恢复。每次只改变一个参数，保存固件、比特流、底盘版本、参数和控制台日志。

### 阶段 5：导航场景

底盘接口通过后才进入无图 N1–N8、有图 P1–P5、坡道 / 台阶和正式扫图。SLAM 扫图与 SFP 以太网不在底盘接口冻结之前展开；
RK3588 经 USB 串口的台架联调（[rk3588_design.md](rk3588_design.md) 第 8 节）不依赖底盘，可以并行。

## 9. 双方交付清单

### RL / 底盘组提交

- 接口适配层和信号时序图；
- 坐标、符号、单位、采样周期和版本号；
- 对地速度估计说明（含姿态补偿、打滑处理和有效条件）；
- 策略输入输出、动作范围、异常降级状态机；
- 物理急停、通信断链和执行器故障处理；
- 实测能力参数和站立腿长；
- 仿真回放、故障注入、架空测试记录和日志格式。

### FPGA / 导航组提供

- `nav_subsystem` 端口和 `icd.md` / `regmap.md`；
- `safety_guard` 的限幅、ramp、看门狗和急停行为；
- `nav_cmd_t` / HAL 接口和闭环仿真入口；
- 板级时钟、复位、引脚和构建约束；
- 导航状态报文和测试工具。

实现与测试结果分别见[控制来源](../../control/FORK.md)、[终点与停止](../4_design/endpoint_stop_20261022.md)和[PNR63 报告](../4_design/g2_PNR63_review_20261028.md)。
