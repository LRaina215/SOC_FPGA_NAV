# RK3588 边缘任务引擎与 FPGA 对接设计

RK3588 将视觉、语音、语言理解与任务编排连接起来，为 FPGA 提供导航目标、任务模式和视觉目标，并向 Web 与微信小程序提供统一业务接口。导航定位、路径规划、避障与轮腿控制由 FPGA 执行。

总体关系见[系统架构](../system_architecture.md)，报文字段、单位与编码见 [ICD](../2_interface/icd.md)。

## 1. 模块组成

| 模块 | 实现 | 职责 |
|---|---|---|
| 视觉感知 | YOLO26n INT8、Astra RGB-D、颜色与目标跟踪 | 输出类别、属性、三维位置、目标 ID 和时间信息 |
| 语音识别 | SenseVoice INT8、sherpa-onnx | 将车载录音与上传音频转为文本 |
| 语言理解 | Qwen3-1.7B W8A8、RKLLM | 解析任务意图、参数并生成文字交互 |
| 语音合成 | Matcha + Vocos | 生成车载播报音频 |
| 业务后端 | FastAPI、SQLite、WebSocket | 管理任务请求、确认、事件、状态与持久化 |
| FPGA 桥接 | fpga_bridge | 独占 FPGA 链路，处理任务状态、目标筛选、地图传输与测量反馈 |
| 视频服务 | Rockchip MPP、MediaMTX | 编码车载画面，为 Web 与小程序提供视频源 |

YOLO 与 Qwen 使用 NPU，语音与几何后处理使用 CPU。感知服务依据任务活动调整检测频率，视频编码独立使用 MPP。

## 2. 任务与报文

| 业务任务 | 下发报文 | 执行与反馈 |
|---|---|---|
| 定点 / 返航 | GOAL | FPGA 定位、规划并执行；RK 复核目标与到达状态 |
| 多点巡检 | GOAL / WAYPOINTS | RK 管理点序列、停留和暂停，FPGA 执行各段 |
| 找物 | MODE + TARGET | 探索与视觉筛选协作，发现匹配目标后接近 |
| 跟随 | MODE + 周期 TARGET | 持续更新目标，按有效期处理目标丢失 |
| 初始定位 | SET_POSE | 设置先验地图中的初始位姿 |
| 地图加载 | MAP_BEGIN / MAP_DATA / MAP_END | 分块发送，逐块 ACK，最终 READY |
| 暂停 / 取消 / 停止 | MODE 与任务状态管理 | 撤销运动目标，等待新鲜反馈确认 |

自主车体速度来自 FPGA 导航。RK 的模型结果先经任务类别、参数、置信度与确认流程处理，再转换为上述报文。

## 3. 物理链路

### 3.1 双串口配置

| 通道 | FPGA 端 | RK 配置 | 数据 |
|---|---|---|---|
| 导航 | 板载 CH，L21 / M21 | 921600 8N1；设备按枚举选择 | NV 任务、目标、地图、STATUS 与 MAP_ACK |
| 控制遥测 | P11-40 / A16，3.3 V TTL | 独立 USB-TTL，230400 8N1 | 原 V2 帧，126 字节，约 100 Hz |

共同工程关闭 P11-39 外部速度输入。桥接进程统一管理两个串口，其他服务通过桥接接口提交请求。

### 3.2 SFP 扩展

SFP1 连接 P6 / U11、Q0 Lane2。独立诊断采用 1000BASE-X、自协商和 SFP-GE-T 电口模块，默认 FPGA 地址为 `192.168.2.100:9000`。SFP 扩展将 NV 任务与 CONTROL_V2 放在同一 UDP 链路；CONTROL_V2 由 4 字节 NV 头加原 126 字节遥测组成。

双串口共同工程与 SFP 独立工程分别配置。SFP 接线、构建及实测见[通道映射说明](../4_design/sfp_mapping_correction_20261024.md)。

## 4. 视觉目标与地图处理

### 4.1 TARGET 生成

1. 使用相机内参完成 RGB-D 深度关联。
2. 对检测框按类别、颜色和置信度筛选。
3. 维持目标 ID，估计相机系三维位置。
4. 按安装外参变换到导航机身系 X 前、Y 左、Z 上。
5. 填入类别、ID、位置与采集到发送的延时，交给 bridge 发送。

桥接发送频率上限为 12 Hz，超过 400 ms 的视觉帧丢弃。导航按目标时间管理有效性，TARGET 超过约 1.5 s 未更新后进入目标丢失处理。当前导航使用目标平面位置推进跟踪，z 与置信度字段在协议中保留。

### 4.2 先验地图

地图工具生成 SLF128 的 NVMP v3 包。桥接检查 48 字节头、geometry 0x0107、profile 0x33580001、ZHI 350 / ZLO −300、18 位槽字及容量；粗代价图采用 10 cm 格、最大 64 × 64。

发送按 BEGIN、DATA、END 阶段进行，等待对应 ACK 与最终 READY。传输期间继续处理主机保活、状态与停止请求。Web 的独立预览仅生成显示图，实际导航地图由加载流程更新。

## 5. 遥测与任务状态

### 5.1 数据来源

| 数据 | 来源 | 使用方式 |
|---|---|---|
| 位姿、导航模式与目标速度 | STATUS，约 5 Hz | 地图展示、任务状态与导航诊断 |
| 轮速、编码器、姿态、策略和故障 | 控制 V2，约 100 Hz | 平台展示、停止观察与诊断 |
| 检测框、目标属性与位置 | RK 感知服务 | 找物、跟随及视觉展示 |
| 视频 | RK 编码与云端媒体源 | WebRTC / HLS 播放 |

STATUS 的速度字段是导航指令；实际运动判断使用控制测量。原始遥测保留 `transport/source/version/fresh/receive_age_ms/measurement_age_ms/raw`，展示层按需要降频。

### 5.2 停止与完成

任务完成需结合目标身份、估计距离、导航状态与连续运动反馈。RK 采用双轮速度 ≤5 mm/s、角速度 ≤20 mrad/s、持续 500 ms，并要求反馈健康新鲜、序号和测量时间前进。暂停、取消及停止从请求后重新累计观察窗口。

界面使用 `verifying_arrival`、`waiting_stop` 和 `stop_unconfirmed` 表达核验阶段。控制租约的平均速度授权用于控制权恢复，与任务完成判据分别处理。

编码器粒度、轮胎滑移与机体摆动会影响停止测量；独立地面测量用于评估实际位置和漂移。

### 5.3 重复包、复位与失联

重复 STATUS 不刷新在线年龄。时间倒退触发隔离并清空停止证据；确认时间基准变化后中止旧活动任务。重连、复位和主机活性恢复均通过显式操作恢复任务，过期目标与旧队列清理。

UART / UDP 在无其他发送时每 100 ms 补充主机保活报文。控制遥测计时复位后重建接收基准，数据来源与有效性随状态上送。

## 6. 接口扩展

| 扩展项 | 用途 | 当前接口状态 |
|---|---|---|
| PATH | 展示完整规划路径 | 有报文组包函数，固件应用发送尚未接入 |
| COSTMAP_TILE | 展示实时局部代价图 | 分片、快照身份和上送链路待实现 |
| 启动与地图身份 | 区分复位、地图替换和旧数据 | 通用 boot/session 与地图版本合同待补充 |
| 命令 seq / ACK / 有效期 | 关联接收、执行与结果 | 地图已有专项 ACK，通用任务合同待扩展 |
| CONTROL_V2 / 0x83 | 在 NV 链路中封装原遥测 | SFP 扩展已定义；双串口使用原 V2 帧 |

扩展保持单一链路所有者，并按字段、坐标、频率、缓存及 FPGA 资源分别设计。类型号和最终编码在 ICD 中维护。

## 7. Web、小程序与云端

Web 与小程序共享 FastAPI 和任务状态机。REST 提供查询和操作，WebSocket 推送任务与导航更新。地图展示机器人位姿、航点、目标与历史轨迹；Web 另提供地图文件上传和预览。

Web 采用 Vue 3 / TypeScript，小程序采用微信原生页面。小程序按住说话由 WechatSI 转写，车载语音使用 RK 本地 SenseVoice。

云网关负责 HTTPS / WSS、鉴权与请求转发。RK 只上传一路 `robot/front` 视频，MediaMTX 分别向 WebRTC 和 HLS 客户端分发。视频、语音和视觉数据由 RK 服务直接提供。

## 8. 开发与联调入口

| 检查层级 | 方法 |
|---|---|
| 协议 | 对照 ICD 检查字段、长度、单位、CRC 和错误帧 |
| 任务 | 使用 mock FPGA 与回放测试状态推进、停止反馈、重复包和复位 |
| 地图 | 检查包格式、ACK 重试、容量、READY 与显示坐标 |
| 真实链路 | 采集导航和控制双串口，检查连续性、时序与来源 |
| 系统 | 按站立、短程运动、定位、导航和视觉任务逐级联调 |

服务目录、启动配置和部署步骤见 [RK3588 服务说明](https://github.com/LRaina215/QHXD_Web/blob/yuntuo-fpga/docs/YUNTUO.md)。结果分别记录在[任务层回放](../4_design/rk_task_layer_replay_20261025.md)、[真实 FPGA 联调](https://github.com/LRaina215/QHXD_Web/blob/yuntuo-fpga/docs/REAL_FPGA_INTEGRATION_20261027.md)和[整车总计划](../1_plan/system_integration_plan_20261021.md)。
