# 轮腿车强化学习与 FPGA 部署技术路线

整理日期：2026-10-01。本文记录本次讨论确定的方案、训练设计与部署步骤。奖励权重、速度范围、网络尺寸和控制频率均为初始设计建议，不代表已经实现或经过实机标定。

## 1. 已确定的目标与术语

第一版任务：腿部保持固定支撑姿态，两轮完成动态平衡，以及前进、后退、停车的速度跟踪。先完成仿真训练和 sim2sim，再逐步接入实机，最终让 FPGA 独立运行策略推理与外设控制。

| 术语 | 本项目中的含义 |
| --- | --- |
| 两轮平衡 | 利用 IMU、轮速反馈和两轮驱动，避免车身前后倾倒 |
| 站立／抬高平台 | 用户所指的“站立”是腿部机构升降底盘，与两轮平衡分别处理 |
| 底盘升降 | 第一版采用四个舵机的预设角度，切换低、中、高姿态 |
| 速度跟踪 | 输入目标速度，控制实际速度接近指令；正值前进、负值后退、零值停车 |
| 小陀螺 | 如果指车身原地自转，则通过目标转向角速度训练 |
| 控制器 | 根据目标和当前状态计算控制指令的程序；本项目主要包括策略网络和腿部姿态控制 |
| sim2sim | 将仿真器 A 中训练好的策略加载到仿真器 B 中，验证同一策略的控制效果 |
| sim2real | 将策略接入真实传感器、执行器和通信链路，验证实车控制效果 |

## 2. 当前项目状态

依据本地 [MODEL_STATUS.md](car/urdf/MODEL_STATUS.md) 的最新记录：

- 已建立五连杆闭环模型：[car_closed.xml](car/urdf/car_closed.xml)。后续 MuJoCo 验证使用该文件。
- 每侧两根大腿、两根小腿分别建模，增加四个被动膝关节，左右各有一个闭环连接约束。
- 状态记录报告已完成零腿指令、小幅腿部指令各 30 秒的数值与闭环检查，初始无接触穿透；本次整理未重新运行这些检查。
- 模型共有六个执行器：四个腿部舵机驱动、两个轮驱动。被动关节不属于策略动作。
- 模型腿部使用位置执行器，两轮仍是理想力矩执行器占位；实际执行器响应、质量、传感器误差等需要进一步标定。
- 当前没有已完成的平衡控制器或强化学习策略，仿真链路尚未通过完整控制验证。

硬件讨论中涉及 ACG750 高云 FPGA、四个 MG996R 舵机、两个 MT6701 轮速传感器和轮电机。用户最新说明：使用外接驱动板，不依赖其型号，由用户自行核对输入输出。此前资料中的 DRV8308 信息仅作参考，不能直接作为实际接线或动作模式的依据。

## 3. 分阶段开发路线

| 阶段 | 工作内容 | 完成标志 |
| --- | --- | --- |
| 1. 模型与接口验证 | 核对 URDF、各仿真器模型中的五连杆、关节轴、质量惯量、碰撞、零位和执行器；确认驱动指令含义 | 单关节与机构运动正确，闭环稳定，输入输出定义明确 |
| 2. 两轮平衡训练 | 固定腿部目标角度，目标速度为零，训练两轮平衡 | 能持续保持平衡，漂移和摆动可接受 |
| 3. 前后速度跟踪 | 输入正、负、零目标速度，逐步训练起步、加减速、停车和反向 | 实际速度接近目标，且保持平衡 |
| 4. 第一次 sim2sim | 在另一仿真器中加载同一策略，匹配接口并评估 | 平衡、前进、后退、停车在目标仿真器中也能完成 |
| 5. FPGA 推理实现与板在环 | 导出策略、定点化、实现 RTL，通过电脑与 FPGA 通信控制仿真车 | 数值一致，延迟满足控制周期，闭环任务仍能完成 |
| 6. 基础 sim2real | 接入真实 IMU、编码器、驱动板与舵机，验证平衡和低速行驶 | 基础任务在实车上通过评估 |
| 7. 转向／原地自转 | 加入目标转向角速度，训练左右轮协调控制 | 可跟踪转向命令，并重复 sim2sim、实机验证 |
| 8. 升降协调 | 先实现预设舵机角度的平滑切换，再训练升降时保持平衡与速度跟踪 | 多种腿姿态及切换过程中控制稳定 |
| 9. 弹跳 | 先确认机构行程和执行器能力，再训练起跳、腾空和落地恢复 | 在仿真中验证后，再决定实机实现范围 |

每增加一种能力，都重复“训练 → sim2sim → 部署实现验证 → sim2real”，不必等弹跳训练完成才做第一次迁移验证。

## 4. 仿真训练、sim2sim 与 sim2real 的边界

```text
导出 URDF、建立闭环模型、加载显示
                ↓ 模型准备与验证
在源仿真器中建立训练环境并训练策略
                ↓ 仿真训练
保存策略，在另一仿真器中加载并实际控制车
                ↓ 从这里开始 sim2sim
同一策略在目标仿真器中完成任务
                ↓ sim2sim 验证通过
接入真实传感器与驱动器，控制实车
                ↓ sim2real
```

sim2sim 首轮验证保持策略权重不变，通过适配观测、动作和控制周期检查迁移效果。在目标仿真器中重新训练，不能单凭新策略的成功证明原策略迁移成功。

本地 PDF 采用 Isaac Gym Preview 4，可作为训练流程参考。[NVIDIA 已将 Isaac Gym 标为停止支持的旧软件](https://developer.nvidia.com/isaac-gym)。训练源仿真器仍需最终选定，并先验证它能正确表达五连杆闭环及执行器。可评估 Isaac Lab 作为训练平台、MuJoCo 作为迁移验证平台，不直接假设 URDF 导入即可保留闭环。

Gymnasium 是强化学习环境接口；MuJoCo、Isaac 系列承担物理仿真。在 MuJoCo + Gymnasium 中训练，再在同一 MuJoCo 物理模型上播放，属于训练与回放验证，不是跨仿真器的 sim2sim。

## 5. 传感器、观测向量与控制动作

### 5.1 传感器分工

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 车身前后倾角、倾角速度 | IMU 与姿态估计 | 两轮平衡、行驶中的姿态控制 |
| 左右轮速 | 两个 MT6701 的连续角度读数 | 速度反馈、抑制不必要的轮子运动 |
| 前进速度估计 | 轮速、轮半径与必要的运动学处理 | 速度跟踪；打滑会带来估计误差 |
| 转向角速度 | IMU | 基础阶段抑制转向，后续跟踪自转指令 |
| 目标速度、腿部姿态命令 | 上层命令 | 告诉策略当前任务 |
| 上一次动作 | 控制程序保存 | 动作历史与平滑控制 |

IMU 提供观测，不是训练算法。PPO 根据策略与仿真交互得到的奖励更新网络；部署后网络只进行推理。

### 5.2 第一版观测示例

```text
obs = [
    目标前进速度,
    实际前进速度估计,
    车身前后倾角,
    车身前后倾角速度,
    左轮角速度,
    右轮角速度,
    转向角速度,
    上一次左轮动作,
    上一次右轮动作
]
```

这是待实现的九维示例，不是当前已有网络的接口。所有输入都需要固定顺序、单位、方向、参考坐标系、时间戳与归一化规则。平衡阶段如奖励依赖起点位移，应把对应的位移估计也加入观测；速度跟踪阶段移除起点约束后可去掉该输入。

观测应对应实机能获取或估计的数据。仿真真实状态可以用于计算奖励，不必全部作为策略输入。后续升降协调可加入腿部姿态命令，不能把没有实机反馈的真实关节角度默认作为可部署观测。

### 5.3 动作与外设指令

基础策略输出：

```text
action = [a_left, a_right]，每项范围 [-1, 1]
```

随后按固定规则转换成实际驱动板支持的速度、占空比或其他指令。当前模型的理想力矩输入不能直接当作真实 GPIO 指令。左右关节轴方向可能不同，映射时需要统一“物理前进方向”。

第一版四个舵机目标角度来自低、中、高预设姿态，不由两轮策略输出。只有在训练动作定义中加入四个舵机动作后，网络才会输出对应的角度或角度偏移。

## 6. 底盘升降方案

用户所指的“站立”是抬高平台。第一版不要求直接测量底盘高度，先标定预设角度：

| 姿态 | 控制内容 |
| --- | --- |
| 低姿态 | 四个舵机的一组目标角度 |
| 中姿态 | 四个舵机的另一组目标角度 |
| 高姿态 | 四个舵机的第三组目标角度 |

姿态切换使用插值和角度变化率限制，避开机构超限与奇异位置。仿真中由位置执行器保持这些姿态，不固定车身到世界坐标系。

固定姿态切换用常规角度控制即可。后续强化学习负责在不同姿态及升降过程中协调平衡和行驶。

角度指令不能替代实际角度测量；预设角度方案不宣称实际高度闭环。若以后要求准确高度或适应复杂负载、地面，再增加相应反馈。IMU 单独不能可靠测量底盘高度，两个轮速 MT6701 也不能直接提供腿部关节角度。

## 7. 训练过程与控制周期

每个回合执行：

1. 在满足闭环的站立姿态下重置，加入小幅随机倾角、倾角速度等扰动。
2. 设置目标速度，生成观测向量。
3. 策略输出动作，执行缩放与限幅。
4. 推进物理仿真，读取新的状态。
5. 计算各项奖励，判断失败或时间上限。
6. 倾倒后重置；PPO 收集一批交互数据后更新策略。

控制周期与物理步长分别定义。例如物理步长 1 ms、策略周期 10 ms 时，每次动作保持 10 个物理步。100 Hz 策略更新只是初始试验值，最终由执行器响应、传感器频率和端到端延迟决定；舵机脉冲周期也要单独定义。

模型文件成功加载、检查脚本返回成功，均不能代替平衡与速度控制验证。

## 8. 原地平衡阶段的奖励与惩罚

本阶段目标速度为零，腿部保持固定姿态。此处“原地平衡”与底盘升降分别讨论。

定义有界归一化惩罚：

```text
C(z, s) = min((z / s)^2, 1)
e_theta = 当前倾角 - 目标平衡倾角
delta_action = 当前动作 - 上次动作
```

代码中的角度使用弧度，公式中的 `5°` 对应 `5*pi/180`。

| 类型 | 项目 | 计算方式 | 目的 |
| --- | --- | --- | --- |
| 奖励 | 直立 | +1.0 × exp(-(e_theta / 5°)^2) | 接近适合当前腿姿态的平衡倾角 |
| 奖励 | 存活 | +0.4 | 鼓励持续保持平衡 |
| 惩罚 | 前后摆动 | -0.05 × C(倾角速度, 1 rad/s) | 减少车身摇摆 |
| 惩罚 | 前后移动 | -0.03 × C(前进速度, 0.3 m/s) | 鼓励停在原地 |
| 惩罚 | 位置漂移 | -0.02 × C(相对起点位移, 0.2 m) | 减少缓慢漂移 |
| 惩罚 | 指令幅度 | -0.005 × mean(action²) | 减少长期大指令；不等同实际能耗 |
| 惩罚 | 指令变化 | -0.02 × mean(C(delta_action, 0.2)) | 减少输出抖动 |
| 失败惩罚 | 倾倒／机身触地 | 一次性 -1.0，结束回合 | 标记任务失败 |

每个控制步奖励：

```text
r_step = control_dt × 前七项之和
如果本步发生失败：r_step -= 1.0
```

初始仿真失败阈值可试倾角误差超过 25° 或机身触地；阈值需要按可恢复范围和机构情况调整。正常达到回合时间上限不扣失败分。

学习初期移动和漂移惩罚较小；站稳后可逐步把对应权重提高到 0.10、0.15。每次只调整一两个权重，记录各项贡献。

## 9. 速度跟踪阶段的奖励与惩罚

本阶段目标速度可以为正、负或零，不再要求车停留在初始位置。

```text
e_v = 实际前进速度 - 目标前进速度
```

| 类型 | 项目 | 计算方式 | 目的 |
| --- | --- | --- | --- |
| 奖励 | 速度跟踪 | +1.0 × exp(-(e_v / 0.15 m/s)^2) | 实际速度接近指令 |
| 奖励 | 平衡姿态 | +1.0 × exp(-(e_theta / 5°)^2) | 行驶中保持平衡 |
| 奖励 | 存活 | +0.4 | 持续完成任务 |
| 惩罚 | 前后摆动 | -0.05 × C(倾角速度, 1 rad/s) | 减少行驶摇摆 |
| 惩罚 | 非预期转向 | -0.05 × C(转向角速度, 1 rad/s) | 第一版先直行 |
| 惩罚 | 指令幅度 | -0.005 × mean(action²) | 减少长期大指令 |
| 惩罚 | 指令变化 | -0.02 × mean(C(delta_action, 0.2)) | 减少输出抖动 |
| 失败惩罚 | 倾倒／机身触地 | 一次性 -1.0，结束回合 | 标记任务失败 |

同样使用 `r_step = control_dt × 连续项之和 - 失败罚分`。速度跟踪奖励替换平衡阶段的零速度惩罚，移除相对起点位移惩罚。奖励保持直立时要允许起步和制动所需的小幅倾斜；过强的姿态或平滑约束会抑制加减速。

目标速度为 0.2 m/s 时，单独的速度奖励示例：

| 实际速度 | 误差 | 速度奖励 |
| --- | --- | --- |
| 0 m/s | -0.2 m/s | 约 0.169 |
| 0.1 m/s | -0.1 m/s | 约 0.641 |
| 0.2 m/s | 0 | 1.000 |
| 0.3 m/s | +0.1 m/s | 约 0.641 |

训练课程：先保持零速度学平衡，再随机给 -0.1～0.1 m/s 并包含停车指令，稳定后逐步扩大到例如 -0.3～0.3 m/s，最后在同一回合内切换速度。所有速度范围都是仿真示例，需根据驱动能力调整；目标速度变化应设置加速度限制。

前进、后退和速度闭环属于同一速度跟踪任务，不必分别训练三个完全独立的网络。固定前倾角也不能保证固定前进速度，策略需要同时反馈姿态、角速度和轮速。

## 10. 评估与调参

| 现象 | 优先检查或调整 |
| --- | --- |
| 轮子几乎不动，车倒下 | 动作方向、执行器响应、指令幅度和平滑惩罚 |
| 能平衡但持续移动 | 平衡阶段的速度／位移约束；速度阶段的命令与跟踪误差 |
| 车身前后摇摆 | 姿态反馈、控制延迟、倾角速度惩罚 |
| 指令频繁正负跳变 | 传感器噪声、动作变化惩罚、时序 |
| 加减速很慢 | 姿态或平滑惩罚是否过强，驱动输出是否受限 |

采用独立评估场景和多个随机种子，记录站立时长、速度误差、超调、停车时间、倾角波动、漂移、倾倒率、输出饱和及推理延迟。不同奖励权重下的总分不能直接比较控制效果。

普通时间上限按截断处理，真实任务失败按终止处理。训练策略、定点策略、RTL 推理与板上推理分别验证。

## 11. sim2sim 必须对齐的接口

| 项目 | 需要一致的内容 |
| --- | --- |
| 观测 | 名称、顺序、单位、坐标系、参考零位、归一化和历史数据 |
| 动作 | 顺序、方向、缩放、限幅、轮部模式、舵机角度含义 |
| 执行器 | 增益、响应、更新周期、延迟、速度／力矩限制 |
| 时间 | 物理步长、策略周期、动作保持方式 |
| 任务 | 目标速度、腿部姿态、重置状态与评估场景 |

读取模型状态和执行器时按名称映射，不能把 `qpos`、`qvel` 的全部元素直接当作六维动作。模型中的自由基座和被动膝关节会增加状态维度。

## 12. sim2real 外设与 GPIO 接口

外接驱动板的实际输入输出由用户核对，具体型号不是本路线的前提。先定义指令含义，再落实 GPIO 分配和接线。

| 外设 | 软件侧定义 | FPGA 侧工作 |
| --- | --- | --- |
| 左右轮驱动板 | 两轮指令、使能 | 按板卡要求生成 PWM、频率、方向信号或通信数据 |
| 四个舵机 | 四个目标角度、角度变化率限制 | 标定角度到脉宽的映射并产生控制脉冲 |
| 两个 MT6701 | 左右轮角度、轮速 | I²C 读取、跨圈处理、滤波和时间戳 |
| IMU | 原始测量或姿态、角速度 | 按型号读取并实现相应状态估计 |
| 故障处理 | 使能、故障、数据有效性 | 处理驱动故障、超时、异常输入与输出限幅 |

两个同地址的 I²C 器件需采用独立总线或其他地址隔离方式。GPIO 传递信号，电机三相线连接外接功率驱动板；舵机、电机使用适当供电，控制电路共地，并核对 IO Bank 电压和电平匹配。

开发时可暂由电脑运行网络，FPGA 采集状态和输出外设信号；最终目标是把推理和输入输出处理一起放到 FPGA。

电脑与 FPGA 调试通信应定义消息类型、序号、时间戳、状态／动作数据、校验、有效性和超时行为。具体编码方式和波特率等实现时确定。

本地 [ACG750 开发笔记](ACG750_GW5AT138K_开发笔记.md) 提供 GPIO0 信号与 FPGA 管脚对应关系；最终接线需核对连接器针号、方向和原理图。

## 13. 强化学习策略部署到 FPGA

训练仍在电脑上进行。FPGA 部署的是训练好的策略推理及控制接口，通常不部署 PPO 更新、奖励计算或 Critic 网络。

```text
训练策略文件
    ↓ 导出确定性 Actor 推理图
权重、偏置、归一化参数、网络结构、动作映射
    ↓ 定点化与软件验证
定点参数和定点参考推理
    ↓ 实现 RTL，验证乘加和激活函数
输入处理 + 推理电路 + 输出处理 + 外设接口
    ↓ Gowin EDA 综合、布局布线、时序检查
FPGA 配置文件
    ↓ 下载／烧录
FPGA 板上推理与外设控制
```

### 13.1 导出什么

- Actor 的网络结构、每层权重与偏置、激活函数。
- 完整推理前处理；若框架有特征提取器，也需要包含。
- 观测顺序、单位、归一化参数和裁剪范围。
- 动作方向、缩放、限幅与控制周期。
- 如网络有循环状态，还需定义状态存储和重置规则；第一版优先小型前馈网络。

训练 checkpoint、ONNX 推理图和 FPGA 配置文件用途不同。`.pt` 文件不能直接烧入 Flash 后自动执行，必须提取参数并实现对应运算。部署时使用确定性动作，不在硬件中继续执行训练探索噪声。

### 13.2 网络与定点实现

第一版可从两层、每层 64 个神经元的小型全连接网络试起。实际输入维度由最终观测定义决定，输出维度由动作定义决定。示例 `10 → 64 → 64 → 2` 约有 5000 个参数，不是已经训练好的网络。

每层计算形式：

```text
y = activation(W × x + b)
```

FPGA 使用内部存储保存权重和中间结果，通过乘加单元、激活函数和调度状态机逐层计算。激活函数必须与训练一致；需要近似时，要单独验证近似误差和闭环效果。

可从 16 位定点试验开始，根据每层输入、权重和中间结果的范围，确定小数位、累加位宽、偏置尺度、舍入及饱和规则。位宽不能只凭经验固定；量化后输出接近也不保证闭环控制通过。

### 13.3 Flash 与权重存储

| 方案 | 保存和运行方式 | 更新方式 |
| --- | --- | --- |
| 第一版：权重编译进配置文件 | 将权重作为内部 RAM／ROM 初值，和电路一起生成配置文件，烧入 Flash；上电配置后内部存储包含参数 | 重新生成并下载配置文件 |
| 后续：权重独立存 Flash | Flash 的配置与参数区域分别规划；自定义读取模块在配置后把参数加载到内部 RAM | 单独更新参数区，并保证格式与电路版本匹配 |

Flash 用于断电保存，第一版推理通常从内部 RAM／ROM 读取参数。约 5000 个 16 位参数的数据量约 10 KB；偏置等参数使用更宽位宽时，实际占用会变化。

### 13.4 FPGA 验证顺序

1. 浮点软件策略通过任务评估。
2. 定点软件模型对比输出，并在仿真中闭环评估。
3. RTL 仿真使用相同输入测试向量，核对定点输出、溢出和时序。
4. 下载 FPGA，通过串口输入观测、读回动作，对比参考结果。
5. MuJoCo 提供状态，真实 FPGA 计算动作，进行板在环闭环测试。
6. 实测全链路延迟与抖动后，接入真实传感器和驱动板。

板在环验证与跨仿真器的 sim2sim 是不同检查，两者均有价值。最终链路为：

```text
传感器 → 状态估计 → 观测组织与归一化
                         ↓
                     策略推理
                         ↓
                 动作缩放、限幅和使能
                         ↓
             GPIO／通信 → 外接驱动板 → 电机

预设腿部姿态 → 角度平滑与限幅 → 舵机控制脉冲
```

当前检查未在 PATH 中发现 `gw_sh`、`gw_ide`、`openFPGALoader`、`iverilog` 或 `verilator`。这只说明命令当前不可见，不能证明系统其他位置没有安装。后续需要准备适用工具、许可与下载访问条件。

## 14. 接下来优先完成的工作

1. 以 `car_closed.xml` 为基础复核标称姿态，明确轮驱动输入模式和仿真执行器映射。
2. 确定训练源仿真器，并验证闭环机构可正确运行。
3. 固定第一版观测、两轮动作、控制周期和网络结构。
4. 实现训练环境的重置、观测、动作、奖励与终止逻辑。
5. 先训练固定腿姿态下的两轮平衡，再训练前后速度跟踪。
6. 保存完整推理配置，开展第一次 sim2sim；随后实现 FPGA 推理及板在环验证。
