# 单芯片摄像头显示改版方案（2026-10-30）

状态：用户已确认160×120 RGB565预览，放大到LCD；本文件是实施方案，尚无本版RTL、综合或布线结果。原始功能依据为[单芯片总任务](../1_plan/g2_single_chip_total_task_20261026.md)第0、1节，控制组来源为`Chenyudog/fpga@715378a`；联合基线保持已核对的SYN50→PNR63。

## 功能边界

OV5640经DVP接入FPGA，在同一块FPGA上完成采集、缓冲、LCD显示，这是已定功能。RK上的Astra USB RGB-D仍承担其原有目标感知及Web视频；它不能替代OV5640本地显示。此次只降低本地预览的空间采样密度，不改导航、4500输入/权重/125Hz、SLF128、128KiB CPU、地图与点缓存容量。

原红外硬急停、OLED及既有CH命令/P11-40控制遥测保留。网页运行急停继续撤销运动目标、保持4500平衡；不能改成一概关闭轮控PWM。上游独立串口接管、超声波扫描/自动绕障等额外分支不因导入视频而自动加入生产功能；若原有外设已有选定绑定则保留其绑定，不另改控制所有权。

## 图像和存储

保留OV5640现有640×480 RGB565配置和完整取景范围。`ov5640_camera.v`的抽样参数由显示实例的`DECIMATE=2`改为4，采用源像素`(4x,4y)`生成160×120图像；被保留像素的16位RGB565值逐位不变。不引入RGB332减色、JPEG、DDR或新的推理任务。

| 项目 | 上游显示版 | 本次选定 |
| --- | --- | --- |
| 存储分辨率 | 320×240 | 160×120 |
| 每像素位数 | 16，RGB565 | 16，RGB565 |
| 单帧像素 | 76800 | 19200 |
| 缓冲 | 两帧 | 两帧，保留完整帧交换 |
| 图像有效数据 | 307200B / 300KiB | 76800B / 75KiB |
| 图像BSRAM | 本轮此前134仅是理想位容量下界，并非实测块数 | 按1024×16原生几何、每帧19块，预计两帧38块 |

以当前联合280块为参考，图像相加为318块，距336部署上限还有18块。**318并非整机综合结果**：HUD字模、PLL配置、PID及映射变化仍可能影响总量。实施时目标尽量控制在320块附近，物理准入仍为≤336/340；不会为追逐估算而改地图或4500。原任务预留“至少36块”不是视频必须≤36块，本次38块预测在现有56块部署余量内。

优先使用两个明确的19200×16独立帧存储实例，写端CAMERA_PCLK、读端LCD时钟。每个局部地址15位，最大19199；清楚区分写银行和读银行，不用扩大数组或无约束地址推断。RAM不整体复位：完整首帧发布前显示测试底色/未就绪，不依赖未初始化像素为零。若工具未映射为预期38块，先审真实宽度、深度、端口和拆分，不能用增加寄存器缓存掩盖问题。

## 显示与跨域

LCD保留原800×480、33MHz时序。160×120画面做4×最近邻放大，形成640×480图像，水平位于x=80…719，左右各80像素边栏；六轴等选定运行信息沿原HUD按LCD原生坐标叠加，文字不随低分辨率图像一起放大。

读坐标为`floor((x-80)/4)`和`floor(y/4)`，读地址为`row*160+column`；乘160用固定移位加法，除4用位选择。图像外读使能关闭或地址限定为有效值；RAM读延迟、RGB、HUD、DE/HS/VS必须逐拍对齐。不主动降低LCD刷新率；相机实际完整帧率和更新时间由真实采集验证，不能从像素数量推断。

沿用并核对完整帧请求/确认协议：写满且行数/行长正确才发布；LCD仅在帧边界换读银行，确认返回后写端才能复用旧银行。忙时不覆盖正在显示的银行，可跳过新采集帧。半像素、短行、缺行、不完整帧不能发布。相机、LCD停钟以及共同复位/重新锁定后，都必须等新完整帧再显示，不能播放旧帧为实时画面。

联合实现预计有50MHz核心、100MHz雷达、外部相机PCLK及33MHz LCD四个真实时钟域。原PRIMARY/LW已满，新增真时钟必须按新网表重新分配和核对，不能直接复制上游自动编号。相机像素输入及LCD输出补齐板级IO预算；同步器、帧银行所有权、HUD稳定载荷及复位释放分别审阅，不套用全域false-path。视频局部故障只影响视频就绪和提示，不得额外复位CPU、4500或绕过停止保护。

## 遥测与控制侧取舍

生产版保留当前V2/100Hz运行遥测，维持RK现有解码和状态/停稳消费关系。必需信息包括设备时间/序号、模型与传感器健康、校准状态、IMU姿态/角速度、左右轮速/编码器变化、当前指令和故障；不能因为某字段不显示在网页就删掉其健康或停止证据作用。

本次不默认引出V4的核心细分、期望ID、返回ID，不增加对应高频宽快照和调试页面；不要求为此先升级RK为V4。现有V2格式先保持，不为省16字节新增一套生产协议。保留仓库中的离线测试工具不会占用FPGA资源，无需删除验证资产。需要专项诊断时可另建显式诊断候选，不能使常态运行依赖诊断字段。

PID的`pid_run`和`sample_pending`修复作为独立、可比对的代码变更移植，参数和外层停止门保持SYN50选择。与视频一起进入最终联合候选前，验证启用同拍反馈、撤权、复位、反馈超时、故障、零模型指令下的平衡语义。不得用上游`main.v`整文件覆盖联合环形观测、动作preview、BMI恢复、红外覆盖、lease和RK失联守卫。

## 实施与验收顺序

1. **冻结候选。** 从SYN50对应受跟踪实现和补丁派生独立目录，只纳入视频必要模块、160×120存储/读出、选定IO/PLL以及经验证PID修复。记录旧核心、CPU和ROM资产对应关系，保留当前板上镜像，不混入其他会话的`build_g2.py`或SFP改动。
2. **有限功能验证。** 相机源产生带位置/颜色标记的RGB565流，逐像素核19200个输出与4×读出；测试首帧、至少两次银行交换、读写不重叠、不完整帧拒绝、忙时反压、各时钟停启及共同复位。复用未改4500的既有证明，检查新连接与时钟/复位未改变其输入和周期，不重复无关训练或旧仿真。
3. **一次完整综合。** 核对帧RAM实际几何/数量、全部既有RAM参数/INIT、CPU128KiB、实际四钟及CDC、资源和最长路径。综合估计不是物理通过；不因318预测直接宣称装得下。
4. **物理实现。** 检查通过后，同一冻结网表用两种布局选项；每个任务独立满足≥2GiB物理/≥4GiB可提交内存才入场，允许资源足够时并行，PNR总时限0/静默0。逐个核未布通0、全部目标钟setup/hold0、约束覆盖、IO、CDC、复位恢复/移除/脉宽和实际全局分配。若失败按真实路径/资源分析，不盲换种子、恢复失败优化栈或擅改RGB332。
5. **按已有授权进行SRAM台架验证。** 满足部署门槛后先只读核对实时镜像/设备/供电和支撑，验证LCD颜色/完整帧/延迟、遥测、复位与视频断连隔离，再做既有受控停止与独立硬停链。保持不写Flash；落地回稳和导航按总计划继续，画面正常不等于整车平衡通过。

下一实质交付为冻结源、图像/跨域与PID验证结果，再报告真实综合资源；当前没有启动本方案的综合、PNR或上板。
