## 完整覆盖先于有效读取

只将`rl_policy_tick_v5`的私有`snapshot`更新块从异步复位清零改成原更新条件下的时钟写入，整帧捕获、相邻词移位和全部控制条件相同。私有缓冲复位后或首次使用前可以未定义，必须证明它不会被消费者有效使用：

1. 调度器复位进入IDLE，核心仍由原`core_rst_n`复位。只有LOAD且run_ok时有有效写入。
2. 首次进入LOAD只能从SNAPSHOT且frame_valid来，原run_ok/截止优先级同时保证该边沿`snapshot_update`为真，完整4032位被覆盖。
3. 连续LOAD的每个有效字来自相同冻结帧，移位、索引、地址/history标志、START和发布拍保持。LOAD截止边沿可能仍有原有效写入，但缓冲已由此前SNAPSHOT定义，随后原故障逻辑中断。
4. 复位、停用、传感器失败或故障中断后，原状态机和核心复位/使能仍生效；再次LOAD必须重新经过完整SNAPSHOT覆盖。

已核对本次冻结的真实`fc_v4_top.v`：`wr_data`只有输入声明和`wr_en && !busy && 地址有效`保护下的input_mem写入两处使用，不在无效写周期影响核心行为；前置检查保留此实际消费边界核对。

这不要求外部4032位总线在LOAD时稳定。测试仍让所有输入逐拍变化，实际有效写入必须与原冻结缓冲一致。无效wr_data以及完整覆盖前的私有值不要求相同；所有公开输出和有效消费者输入保持比较，不能把未比较的私有值称为逐位全状态相同。
