# 闭环仿真与算法改进记录

## 1. 闭环仿真平台（`sim/closed_loop/`）

```text
场景（带真值地形标签）──虚拟 XT-M60──> FPGA 感知模型（nav_fast，与 RTL 逐位一致）──代价图──┐
     ↑                                                                                   ↓
机器人真值运动（打滑/轮径误差/陀螺零偏/姿态噪声/堵转） <──速度指令── 固件（真实 C 代码，nav_fw.dll）
```

| 文件 | 作用 |
|---|---|
| `world.py` | 场景（墙、10° 坡道+平台、8 cm 台阶、20 cm 路沿、箱子、22.6° 陡坡；回环跑道）；由真实高程场按机器人能力（可跨 10 cm、坡度 20°）生成真值标签；车体按实车 180 × 213 mm（外接圆 140 mm） |
| `robot.py` | 2.5D 地形上的运动学，轮下高度决定 z/俯仰/横滚；超过能力的地形会挡住机器人（计碰撞）；里程计与 IMU 误差模型 |
| `fpga_model.py` | FPGA 感知链路 + 匹配打分模型；每帧先融合、后匹配（帧只流过一遍），帧提交前等 IMU（双缓冲握手）；有图模式：先验槽字、固定窗口、不并图（固件经 `hal_py` 回调控制） |
| `run_cl.py` | 闭环主程序：`metrics.json`、快照（场景轨迹 / 代价图 / 判定对比 / 记忆栅格 + A* 路径，有图搜索时叠加相机已看过的区域）、`loc_error.png`（逐帧定位误差）、`trav_errors.png`（误报/漏报位置）、`--gif` 动画。有图：`--prior auto|路径`、`--init-err`、`--perturb boxes`、`--kidnap t,dx,dy,dyaw` |
| `batch.py` | 无图 4 个用例、有图 6 个用例（`--cases p_…`）× 5 个种子并行，汇总 `sim/build/batch/<tag>/summary.md` |
| `test_prior.py` | 有图模式固件单元测试：地图包分块下发、乱序、CRC 错、SET_POSE |
| `eval_trav.py` | 地形判定单独评测：真值位姿沿路线采集，按地形要素统计误报/漏报 |
| `test_nav_fast.py` | 向量化模型与逐位模型一致性 |

指标口径：误报 = 真可通行格判致命（254）；漏报 = 真致命格判可走（< 253，膨胀区对机器人中心同样不可走，不算漏报）。

```bash
python sim/closed_loop/batch.py --tag x                         # 标准评测（约 5 分钟；--extra "--match off" 对照）
python sim/closed_loop/eval_trav.py --trav v1 v2 v3
python sim/closed_loop/run_cl.py --scene terrain --goal 9.3,2.8 --seed 2 --gif --out sim/build/cl/demo
python sim/closed_loop/run_cl.py ... --ideal | --noise att | --tcfg keep_r=0 | --gmap off
python sim/closed_loop/batch.py --tag y --cases p_terrain_a p_terrain_b p_search p_loop p_perturb p_kidnap   # 有图（约 25 分钟）
python sim/closed_loop/run_cl.py --scene terrain --search 8.0,-3.0 --prior auto --init-err rand --seed 2 --gif --out sim/build/cl/demo_prior_search
```

以上是**无图模式**。剩余定位误差主要是"探索新区域时的打滑漂移"：前方结构第一次被看到时位姿已经漂了，地图随之建在漂移后的坐标里，

## 3. 规划层修复（`fw/nav/`）

| 闭环中观察到的问题 | 改进 |
|---|---|
| A* 只在 6.4 m 局部图上规划，长障碍（路沿）另一端出窗/过期就被忘掉，路径来回翻转，机器人原地打转、撞路沿（terrain_b 0/5） | **全局记忆栅格 `gmap.c`**：局部代价图每帧按 4×4 合成 20 cm 格、96×96（19.2 m）滚动栅格；每格证据计数（有 ≥2 个致命格 +2，否则 −1，饱和 [−4, 6]，≥2 为致命），局部图里未知的格不改动记忆。A* 改在它上面跑（`astar_grid`），离障 1/2 格加代价 |
| 贴着障碍时雷达最小量程 0.3 m + 俯视盲区，障碍按时间过期后"消失"，机器人开上去 | **近区不过期**（地形 `keep_r`）：窗口中心 ±12 格内不做过期清除 |
| 机器人进入膨胀区（误报/漂移使障碍"长"到脚下）后所有候选都算碰撞，永远原地转 | **脱困遍**：第一遍无可行候选时，只把 254 算碰撞、膨胀区按高代价，选离开的轨迹（同一硬件，只改 cmax） |
| 局部极小：前视点在两侧跳，原地来回摆 | **卡住检测**：6 s 内位移 < 15 cm -> 倒车 1.5 s（身后可走）或原地转，路径作废重规划；离目标 < 0.6 m 时直接接受到达 |
| 路径点落在障碍旁，漂移后永远进不去 | 中间路径点容差 0.35 m（终点 0.15 m） |
| 搜索模式只在局部图上按方向打分，绕着起点附近打转，150 s 内到不了路沿另一侧（目标在那里） | **边界探索**（`explore_frontier`）：在全局记忆栅格上广度优先，边界格 = 已知可走且邻接未知；代价 = 路程 + 访问热度；紧挨致命格的边界（平台侧沿外的遮挡区）不选；直线距离 ≥ 1 m；12 s 没到就拉黑（半径 1 m）。找不到边界才退回方向打分 |

## 4. 地形可通行性 v3（`model/trav_v3.py`，当前默认）

在 v2（跳变门控差分、遮挡落差、空洞填补、膨胀 5 格）基础上：

| 问题 | 改进 |
|---|---|
| 坡度用 5 cm 相邻格差分：3–6 cm 的小台阶（坡道侧沿）没超过跳变门限，被当成 28° 的"坡"，坡道脚下误报，机器人被困（理想传感器也复现） | **门控基线坡度（GBS）**：沿 x/y 各取 4 格（20 cm）基线，把相邻格有符号高差逐段相加，跳变段不计 -> "去掉台阶后的净升高"，> 4·res·tan20° = 73 mm 判致命。坡度只在车体尺度上有意义；有符号相加让逐格噪声相互抵消 |
| 遮挡落差沿下坡往下看时误报（远处地面自然更低） | **按坡度外推的落差**：期望高度 = 本格高度 + 本格基线坡度 × 距离；基线无效时按每格 4 mm 放宽；扫描距离 16 格 |
| 参数被 v1 的寄存器默认值覆盖（step 120、slope 60） | v2/v3 使用按机器人能力给出的默认值（step_max = 可跨高度 100 mm） |

地形判定单独评测（真值位姿，`eval_trav.py`，新口径）：

| | 误报致命 | 8 cm 台阶误报 | 漏报 | 陡坡漏报 |
|---|---|---|---|---|
| v1（当前 RTL） | 1.1% | 12.5% | ≈ 40% | 93% |
| v2 | 0.6% | 5.5% | 5.9% | 0% |
| v3 | 0.0% | 0.0% | 6.3% | 0.4% |

v3 剩余漏报集中在坡道侧沿（从坡面上看侧沿外侧被遮挡、落差 < 10 cm 的一段），对机器人中心不构成危险。
膨胀半径按车体外接圆设置：实车 140 mm -> 3 格（`MAP.INFL` 缺省值同步改为 3）。

## 5. 姿态与帧时序（`fw/nav/pose.c`、`fw/app/nav_app.c`）

| 问题 | 改进 |
|---|---|
| 姿态一阶低通有滞后：原地转向时车体姿态 10–20°/s 变化，0.16 s 滞后 = 2–3°，4 m 外地面高差 15–20 cm，误报 12% | **α-β 滤波**（α=1/4，β=1/32）：同时估计角速度，匀速变化无稳态滞后 |

## 6. 结构似然场匹配定位（SLF，`model/slf_match.py` + `rtl/match/` + `fw/nav/pose_match.c`）

EICM（高程区间一致性）已删除。定位发散的直接原因之一也在这里找到：候选角的正弦表索引向下取整，
负角候选多转一格（−0.5° 实际转 −0.70°，+0.5° 实际 +0.35°），代价曲面不对称 -> 航向持续单向漂移。

每帧流程（先融合、后匹配，帧只流过一遍）：

1. **结构点**（提交帧时旁听 pc_transform 输出）：同一列上下相邻像素连线陡于 63°（|Δz| > 2|Δxy|，|Δz| ≥ 20 mm），
   且离机器人足底 6 cm–1.5 m（有图模式 −30 cm–1.5 m，见第 8 节；`MATCH.ZREL` 由固件按模式设置）。
   LeGO-LOAM 地面分割"相邻线束夹角"的反面，只需一行点的行缓存。
   存入点缓冲（≤ 4096 个，相对帧平移的 18 位坐标），打分/并图时按步长 ceil(n/1024) 取点。
2. **打分**（硬件，约 40 ms，固件异步等待）：7×7 平移（25 mm）× 5 角度（0.70°，正好是正弦表 2 格）= 245 个候选。
   门控：预测位置离窗口边 ≥ 8 格且该格 gate=1（2 格内有已知结构——新看到的结构不参与，否则把位姿往已知区拉）。
   每点取 3×3 邻域结构格的最小**点到线法向距离**（无法向的格用点到质心 L1），上限 2.5 格。
   每个候选输出 {代价和, 参与点数, 内点数（残差 ≤ 19 mm，定位质量用）}。
3. **求解**（固件）：从零增量出发取严格最优；平移在 3×3 邻域拟合二次曲面，**Hessian 2×2 特征分解**，只沿特征值
   > 600/千点 的方向做牛顿步；角度轴抛物线拟合。增益 0.625。
4. **并图 + 建似然场**（硬件，约 1 ms）：缓冲点按最终修正量变换后写入结构图——256×256、5 cm 滚动栅格，
   槽字 23 位 {tag 4, hit 3, 格内亚格质心 4+4, occ, 法向扇区 5, has, gate}；一帧内同格只取第一个点（"本遍已写"位图），
   质心前 4 次累计平均后冻结。然后按窗口扫描一遍：5×5 邻域质心的整数协方差（列和分解）-> CORDIC 求法向扇区（32 向）、
   线状判定 25((A−C)²+4B²) > 9(A+C)²、gate，写回槽字。

每一步都来自离线测试暴露的偏差：

| 做法 | 问题 |
|---|---|
| 二值结构格 + 距离变换、整数格查表 | 2.5 cm 步长落在同一格内，曲面呈台阶；结构带 2–3 格厚，带内平坦 |
| 双线性插值距离场 | 格中心 ≠ 真实面位置，半格量化偏差 2–3 cm，且随视角变化 |
| 质心 + L1 距离 | 无偏，但沿墙方向在相邻质心间"跳"，噪声 ±700/千点，淹没弱约束方向 |
| 远处按距离场给梯度 | 新看到的结构把位姿往已知区拉，沿运动方向偏 25 mm/帧 |
| 逐轴曲率退化判定 | 墙斜着时失效；沿墙噪声偶尔越过门限 -> 沿运动方向 25 cm/s 误修 |
| 质心指数平均 | 退化期间带偏差的帧把地图"拖着走" |
| 2×2 近邻（省存储带宽） / 128×128 结构图（省存储） | 闭环 xy RMS 分别变差约 50% / 100%，不采用 |

硬件验证：`tb_slf` 5 帧在线（结构点数、245 个候选的打分结果、并图 + 建图后整张结构图 65536 槽）+ 2 帧有图
（先验槽字写入、不门控 / 门控打分、UPDATE 后先验图不变），与模型逐位一致；`tb_nav_top` 经总线走通 MATCH 寄存器与窗口。

## 8. 有图模式：先验地图 + 定位（`model/prior_map.py`、`fw/nav/loc.c`、`fw/nav/prior.c`）

按选题 3 方案：地图在外部电脑上建好，FPGA 运行时只做定位，不建图；局部高程图 / 可通行性分析与无图模式共用。

```text
赛前扫图（XT-M60 + IMU，Linux SLAM）-> 地图点云 -> tools/map_tool.py -> .nvmp（定位图 + 20 cm 代价图）
      -> PC 或 RK3588 下发（MAP_BEGIN/DATA/END）-> 定位图写进 SLF 结构图 RAM，代价图进记忆栅格的先验层
      -> SET_POSE（大致位置）-> 对准 -> 跟踪（每帧 245 候选，不并图）-> 地图系 GOAL / WAYPOINTS / 探索
```

**定位图**：与在线结构图同一槽字格式，离线由整张点云算：5 cm 竖直柱内高差 ≥ 40 mm 的点为结构点
（与板上相邻行判据等价：平台顶面、坡面不入选），每格取全部点的亚格平均（比板上"前 4 次平均后冻结"准），
法向 / 线状判定 / 门控用与硬件相同的整数算法。硬件改动很小：`MATCH.CTRL.PRIOR` 置 1 后窗口原点取
`MATCH.LFO_*`（固定），UPDATE 只释放点缓冲，门控与邻格读核对槽字标签（窗口外 = 无结构，不再需要 8 格保留带）；
`NOGATE` 让对准时所有点参与；结果里的 `n_in` 改为内点数（残差 ≤ 19 mm）。`tb_slf` 增加有图两帧（不门控 / 门控），逐位一致。

**对准**（机器人原地保持）：同一帧结构点上打 38 批候选——±0.5 m（50 mm 步长）× ±10°（1°）全枚举，
保留互相分开的最优峰；再在最优峰周围 7×7×5 细化两轮（25 mm/0.7°、10 mm/0.35°）。硬件时间约 1.6 s。
接受条件：内点率 ≥ 40% 且第二峰平均代价高出 ≥ 0.3（1/16 格/点；0.5 时 p_perturb 对准平均 9.1 s，0.3 时 6.4 s）。随机位姿统计（terrain，25 个）：错误对准的
第二峰代价差都 < 0.15，正确的多在 0.3 以上。不接受时原地转 35° 换视角再试（单帧里只有平行结构时，沿结构方向本来就不可观）。

**跟踪与质量**：先验图固定，匹配增益 0.81（无图 0.625）、退化判定门限 200/千点（无图 600）——先验图沿墙方向的代价是真平的，
少量垂直结构就足以约束前进方向（600 时平台上沿行驶方向漂 0.28 m，200 时最大 6 cm）。
质量 = 最优候选内点数 / 本帧结构点数，指数平均；< 45% 退化（限速一半），< 35% 持续 2 s 或最优候选连续 6 帧落在
约束充分方向的搜索边界 -> 丢失：原地保持，以当前估计为中心重定位（同对准）；失败则每 3 s 再试。

**结构点高度带**：有图模式下限从足底 +60 mm 放到 −300 mm。机器人在平台 / 坡顶上时，脚下的路沿、平台侧面也在先验图里，
+60 mm 会把它们全部丢掉（闭环中平台上沿行驶方向漂 0.28 m）。无图模式保持 +60 mm（自建图时互有胜负）。

**规划与搜索**：记忆栅格的先验层 = 离线代价图，原点固定；观测到的格用观测（动态障碍），先验致命而观测可走时须证据
降到 occ_min + 1 以下才采信（地图之后被搬走的物体），避免偶发漏检把墙"擦掉"。有图 Search：未知改为"相机还没看过"——
按相机视场（70°、4 m，被致命格挡住为止）标记看过的格，在看过 / 没看过的可走格之间找边界，按路程 + 访问热度选最近的；
全部看过后清空重来。

## 9. 两轮自平衡小车 + 5 m 场地（`world.scene_field5`、`robot.BalanceBot`）

按实车更新：两轮自平衡轮腿（轮径 65 mm）、机身 180 × 213 mm；能力未实测，暂按可跨 2 cm、坡度 12°（docs/platform.md）。

**仿真模型**：左右两个着地点；机身俯仰不随坡面，而是平衡姿态——加减速前后倾（tan θ ≈ a/g）+ 持续摆动（缺省 ±1.5°、1.8 Hz）
+ 越过台阶 / 坡口时的衰减振荡（每 1 cm 高差约 3°）；横滚由左右轮高差决定。IMU 100 Hz，同时输出角度帧与角速度帧。
场地 field5：5 m × 5 m、墙高 0.5 m、快递箱（相互间距 ≥ 50 cm，含斜向）、40 cm 窄通道、8° 上坡 + 平台 + 12° 下坡、
1.5 cm 门槛条（可跨）、6 cm 路沿（不可跨）、20° 陡坡（不可通行）。

| 问题（闭环中观察到的） | 改进 |
|---|---|
| 机身持续摆动，α-β 姿态滤波跟不上（俯仰误差 RMS 0.50°、最大 1.55°），3 m 外地面高差 5–8 cm，地形误报 14% | **陀螺辅助姿态滤波**：有新鲜角速度时用它做预测、1/16 增益校正（互补滤波）：俯仰误差 0.14°（最大 0.34°），误报 0.1% |
| 雷达帧的俯仰 / 横滚取的是离帧时刻最近的旧样本 | 按 IMU 频率存姿态历史，帧时刻线性插值 |
| 高度锚定的足迹采样点按旧车体（±200 × ±180 mm），落到旁边箱子侧面，z 被拉偏 5 cm，所到之处满地误报 | 采样点改为轮子着地处（±60 × ±85 mm）：z 误差 3 mm |
| 两轮车的机身俯仰是平衡姿态，按它把前进速度分解成高度变化会让 z 随摆动漂 | 自平衡底盘不做分解（`pose.decomp_pitch = false`），高度只靠地图锚定 |
| 20 cm 记忆栅格对 18 cm 宽的小车太粗，40 cm 的缝在 A* 里只有 2 格 | 记忆栅格 10 cm × 64 格（6.4 m，覆盖 5 m 场地）；A* 离致命格 1 格重罚、2–3 格加罚 |
| 方形膨胀在斜向多出 √2 倍，两箱斜对角的缝在局部图里被堵死，而 A* 认为能过 -> 原地来回 | **圆形膨胀**（RTL 与模型逐位一致，半径 ≤ 4 格），并加"同一处第二次卡住就在前视点放临时虚拟障碍（30 s）"，A* 换路 |
