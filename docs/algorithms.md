# 闭环仿真与算法改进记录

## 1. 闭环仿真平台（`sim/closed_loop/`）

```text
场景（带真值地形标签）──虚拟 XT-M60──> FPGA 感知模型（nav_fast，与 RTL 逐位一致）──代价图──┐
     ↑                                                                                   ↓
机器人真值运动（打滑/轮径误差/陀螺零偏/姿态噪声/堵转） <──速度指令── 固件（真实 C 代码，nav_fw.dll）
```

| 文件 | 作用 |
|---|---|
| `world.py` | 场景（墙、10° 坡道+平台、8 cm 台阶、20 cm 路沿、箱子、22.6° 陡坡）；由真实高程场按机器人能力（可跨 10 cm、坡度 20°）生成真值标签 |
| `robot.py` | 2.5D 地形上的运动学，轮下高度决定 z/俯仰/横滚；超过能力的地形会挡住机器人（计碰撞）；里程计与 IMU 误差模型 |
| `fpga_model.py` | FPGA 感知链路 + 匹配打分模型；两遍帧处理（先匹配、后融合） |
| `run_cl.py` | 闭环主程序：出指标 `metrics.json` 与快照图（场景轨迹 / 代价图 / 判定对比） |
| `eval_trav.py` | 地形判定单独评测：真值位姿沿路线采集，按地形要素统计误报/漏报 |
| `test_nav_fast.py` | 向量化模型与逐位模型一致性（多帧、窗口跳变） |

```bash
python sim/closed_loop/test_nav_fast.py
python sim/closed_loop/eval_trav.py --trav v1 v2
python sim/closed_loop/run_cl.py --scene terrain --goal 9.3,2.8 --trav v2 --seed 2 --calib 4 --out sim/build/cl/demo
python sim/closed_loop/run_cl.py ... --ideal            # 理想传感器
python sim/closed_loop/run_cl.py ... --noise att        # 只开某一类误差（slip/gyro/att/scale）
```

## 2. 地形可通行性 v2（`model/trav_v2.py`，SART）

闭环中发现的 v1 问题与对应改进（全部是 3×3 窗口或行/列扫描寄存器上的整数运算，可按 v1 的流水线结构实现）：

| 问题 | 改进 |
|---|---|
| 中心差分把可跨越台阶的边沿算成陡坡（8 cm 台阶误报 12.5%） | **跳变门控单侧差分**：一侧差分超过 JUMP 视为台阶，坡度取另一侧；否则取较大侧（陡坡边缘不被平地冲淡）。台阶只按"高差 > 可跨高度"判定 |
| 站在平台上时，边沿外侧地面被平台自身遮挡，边沿格邻居全是未知，机器人从 20 cm 平台侧边开下去卡死（理想传感器闭环 451 次碰撞） | **遮挡落差检测**：已观测格在某方向紧邻未知、而 DROP_K 格内第一个已观测格低于它超过可跨高度 -> 致命 |
| 远处扫描线稀疏，地面空洞多 | **空洞填补**：未知格 8 邻域中 ≥5 个已观测、高差极差 < 3 cm、邻居无致命 -> 判可通行 |
| 膨胀半径 3 格（15 cm）小于底盘半径 25 cm，贴边行驶时轮子压上障碍边沿 | 膨胀半径 5 格 |

地形判定单独评测（真值位姿，`eval_trav.py`）：

| | 可通行格误报致命 | 其中 8 cm 台阶 | 致命格漏报 | 可通行区未知比例 |
|---|---|---|---|---|
| v1（当前 RTL） | 1.1% | 12.5% | 42.6% | 48.0% |
| v2 | 0.2% | 2.6% | 39.4% | 44.3% |

漏报主要在陡坡与平台侧面：低矮安装（光心 20 cm、俯视 10°）的雷达看这些面时入射角很小、采样稀，用 5 cm 格的高差判不出来；不影响安全性的原因是它们的上沿/下沿会被判出，但仍是后续改进点。

## 3. 定位改进（`fw/nav/pose.c`）

| 问题（闭环中定位误差来源） | 改进 |
|---|---|
| 只积分平面位移，坡道上 z 不变，新旧观测高度不一致 -> 假台阶 | **三维航位推算**：前进速度按 IMU 俯仰分解为水平位移和高度变化 |
| 陀螺零偏 0.3°/s，90 s 航向误差约 10° | **零速零偏估计（ZUPT）**：指令为零、轮速为零、角速度读数 < 3°/s 时估计零偏（前 256 个样本累计平均，之后慢速跟踪），静止时不积分航向 |
| IMU 俯仰/横滚 0.3° 白噪声使整帧点云倾斜，远处地面逐帧跳动，高程图出现假台阶（单独开此误差时误报率 14%） | **姿态一阶低通**（50 Hz 下时间常数约 0.16 s） |
| 高度漂移 | **足迹高度锚定**：轮下栅格（此前观测、现处盲区）的地面高度就是机器人应有高度，把位姿 z 拉向地图（需要硬件增加高程读窗口，见下） |
| 受阻时轮子空转、里程计把空转当位移 | 仿真中按电机堵转保护建模（实车需底盘侧堵转检测） |

闭环（terrain 场景，目标 10.5 m 外，含坡道/台阶/路沿绕行；误差：打滑 3%±随机游走、轮径 1%、陀螺零偏 0.3°/s、姿态噪声 0.3°）：

| 配置 | 到达 | 定位 xy RMS | 终点航向误差 |
|---|---|---|---|
| 理想传感器 + v2 | 是（38 s，0 碰撞） | 0.03 m | - |
| 改进前（纯里程计、无 ZUPT、v1） | 各种子均未稳定到达 | 0.25–0.57 m | 8–10° |
| 改进后 + v2（3 个随机种子） | 2/3 到达（53 s、91 s），另 1 次 100 s 内未到 | 0.35–0.55 m | 0.1–4.3° |

## 4. 实验性：高程区间一致性匹配（EICM，`fw/nav/pose_match.c`，默认关闭）

思路：点落在各自栅格的 [zmin, zmax] 区间外才计代价，对 5×5×5 个位姿增量候选并行打分，取最小并做抛物线细化；
参考图为压缩关键帧（每格 zmin/zmax 各 8 位）。每个（点, 候选）只需查表旋转、一次查图、两次比较，适合 FPGA 并行。

**现状：尚不可用。** 离线测试中在真值附近存在约 1 个候选步长（40 mm / 1°）的系统偏差，闭环中逐帧累积导致发散
（定位误差 1–4 m），因此固件中默认关闭（`g_app.pm_cfg.enable = false`）。分析：地面点在任何平移下都落在"地面区间"内，
约束只来自竖直面点，而竖直面点数少且被截断/未知罚项主导。下一步候选方案：只用竖直结构点、对关键帧结构二值图做
距离变换（似然场）打分——同样是"查表 + 累加"的硬件结构。

## 5. 与 RTL 的关系与待办

- 当前 RTL 实现的是 v1；v2 目前只在模型中（`trav_v2.py`）。移植要点：跳变门控差分只改 `gradf`；遮挡落差需要 4 个方向的
  "最近已观测格高度"扫描寄存器（左/上方向用已扫描数据，右/下方向需一行/一列的前瞻缓冲）；空洞填补需要邻居致命标志，
  放在膨胀那一遍中计算。
- 足迹高度锚定需要在寄存器表中增加高程读窗口（`hal_map_height` 上板实现目前返回不支持）。
- 仍待解决：打滑造成的平面位置漂移（0.3–0.5 m / 10 m 级）只能靠外部观测修正——EICM 的改进版或先验地图定位。
