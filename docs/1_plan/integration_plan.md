# 全系统集成说明与联调约束

更新：2026-10-21。当前任务顺序和验收闸门以 [整车集成与导航收敛计划](system_integration_plan_20261021.md) 为准；本文维护系统分工、接口、资源和联调要点。新证据来自 [控制仓库审阅](../5_teams/control_repo_review_20261021.md)，替代本文件原先基于10月1日资料的“底盘尚无控制器、BMI088待写SPI、RL约5–6块BSRAM”等判断。

## 1. 系统组成与现状

| 功能 | 当前证据 | 剩余工作 |
|---|---|---|
| 导航感知、定位、规划 | 独立导航板级雷达和任务链路已有通过记录；新判分N1c为28/50；N2g联合验收失败 | 修复新增退化；接通真实反馈；整车验收 |
| 速度安全 | `safety_guard` 已有限幅、斜坡、看门狗、急停；独立台架通过 | 适配到现有控制器；冻结正常零速/硬停/失联语义 |
| RL与执行器 | 原4500模型、125Hz推理、四舵机、520双轮AB闭环、双速度UART已实现；用户确认新接口位流已烧车 | 车上位流与仓库文件对应；集成与实测能力 |
| IMU | 控制源码已有BMI088 I2C和姿态融合，约100Hz采样轮询 | 导航仍是WIT UART旧入口，需换轴/重力姿态/时间适配 |
| RK3588 | 导航R0邮箱任务链路已由PC在板上验证；控制另有直接速度串口 | 明确入口与所有权；RK实机视觉任务联调 |
| 视频/HDMI、SFP | 本轮未见整车实现与资源验收证据 | 需求确认、独立预算后安排 |
| 地图与装车参数 | 工具和导航有图路径已有实现；旧几何与新训练参数都有来源 | 实测轮距/滚动半径/雷达外参；制作真实场地地图 |

“用户确认已烧车”“源码已实现”“模拟通过”“整车验收通过”分别记录。当前还没有证据证明导航和控制已合入同一已验收位流。

## 2. 整车数据流（目标架构）

```text
XT-M60 → 导航雷达/地图/定位 → 软核任务与规划 → SAFE → 命令适配 → 原4500控制器 → 轮电机/舵机
                                       ↑                     ↑              │
RK3588 → 导航邮箱（任务/目标）           │      BMI088 I2C → 融合              │
                                       └── 时间/轴向/反馈适配 ← 编码器/IMU ────┘
控制UART（现有直接速度调试） ── 互斥命令仲裁 ──┘
```

这是统一工程目标，不是当前 `nav_board_top.v` 的已连接状态。现阶段两套工程各有顶层；一片FPGA一次只运行一个位流，下载独立导航位流会替换车上的控制实现。整车继续复用现有控制链，不让导航生成电机PWM。

## 3. 接口矩阵

| 接口 | 当前实现 | 集成需要 |
|---|---|---|
| 雷达XT-M60 ↔ 导航 | 历史真雷达10帧/秒、坏帧0、启动恢复通过 | 合并后回归链路和处理时序 |
| 导航任务 ↔ RK/PC | R0：USB调试桥+邮箱，921600 8N1，已有PC板测 | 保留R0；R1专用串口尚是计划 |
| 控制速度UART | P11-39/40，约230400 8N1；10字节vx/wz帧 | 不能发送导航NV任务报文；自主导航与手动速度入口互斥 |
| 导航 `ch_*` → 控制 | 导航输出已定义但板顶层悬空；控制内部Q12目标存在 | signed16 mm/s、mrad/s转signed24 Q12；原子更新、保护与所有权 |
| 控制 → 导航 `odo_*` | 编码器和陀螺数据存在；导航板顶层反馈为0 | 对地速度估计、有效性、时间和轴向，不能直接以目标代反馈 |
| BMI088 → 控制/导航 | I2C驱动和融合在控制工程；导航旧WIT入口 | 共用传感器及生产者，新增导航适配，不再开发第二套SPI主机 |
| 引脚 | 控制 `fpga/src/main.cst` 已分配舵机、OLED、I2C、AB与电机 | 合并约束，遵循 [pinout](../2_interface/pinout.md)，撤销旧冲突分配 |
| 状态/腿高/CHAS | 当前导航无 `odo_stat`、`odo_l0_mm`；CHAS地址未落地 | 有需要才扩展ICD/YAML/RTL/HAL；文档提议不算实现 |

接口细节以 [ICD](../2_interface/icd.md) 为准；控制源码版本固定在中央审阅报告。控制坐标 X右/Y前/Z上，导航 X前/Y左/Z上，向量转换为 `(Yc,-Xc,Zc)`；欧拉角不得直接交换。

## 4. FPGA资源与时序预算

| 记录 | 已知数值 | 限定 |
|---|---|---|
| 导航2026-10-01布线 | BSRAM324/340；DSP67/298；逻辑24808；寄存器19716；50MHz下Fmax50.085MHz | 独立导航历史工程，非当前统一工程 |
| 控制MEM_4500文档 | BSRAM69；逻辑22369；寄存器15975 | 更早独立构建，不是新增UART后的完整报告 |
| 控制10-19 P=3构建manifest | Fmax54.076MHz，setup/hold违例0 | 不能据此证明10-21源码和导航合并后收敛 |
| 实际模型权重 | 40704×16bit=651264bit；全放18Kbit BSRAM容量下限约36块 | 还未算偏置、ELU及工作缓冲；实际映射以综合为准 |
| N2g导航软核候选 | 镜像36968B、BSS85340B，保留8192B栈后余572B | 候选未接受，新增时间历史/诊断缓冲必须先核预算 |

控制改进路线见 [专项计划](control_improvement_plan_20261021.md)：控制侧可先做精确ROM压缩和恒零输入特化，同时修启动姿态、命令失联和反馈完整性；不能把既有控制器当作不可修改黑盒。

旧“RL5–6块BSRAM”估算撤销；也不直接把独立工程324+69当成整车实际用量。联合综合前无法承诺现有少量压缩就足够。先测量各存储的真实映射，选择重排图存储、复用缓冲、裁剪不用的主机链路等措施；若改变算法缓存/丢帧行为，要有相应验证。

**资源闸门：** 默认保留原计划BSRAM≤336；340是器件硬上限，不是自动验收标准。突破336须依据实际布局和余量分析单列偏离决定。G2用最小共同顶层和接口桩做资源可行性检查，必须核对真实数据通路和ROM未被优化删除；G3真实互连后提交最终联合报告。正确约束下setup/hold通过，控制与导航节拍符合预算。多周期约束仅用于功能确实允许的多周期路径，不能用于掩盖真实时序问题。视频/SFP第一版暂不合入。

器件版本另需核实：导航历史记录B，控制工程及位流头C。构建前按实际板卡核对。详细证据见 [中央报告](../5_teams/control_repo_review_20261021.md) 第5节。

## 5. 联调顺序

旧I0–I9线性计划由当前G/F任务替代：G1接口与版本合同、控制C1整改、F1导航回归诊断并行；G2联合资源与控制C2存储优化联动，F2执行响应与控制C3/C4联动；G3统一顶层；G4基本整车闭环；G5装车标定与导航验收。每项完成标准见 [当前总计划](system_integration_plan_20261021.md)。

不再等待“RL控制器从零开发”“BMI088 SPI驱动完成”或“重新搭建MuJoCo”后才集成；也不把N2g专项通过当作联合验收通过。N1c冻结结果保留，N2g新退化修好前不能替代接受基线。

## 6. 联调关键点

### 6.1 雷达

保留历史雷达10Hz、软核TCP启动和5s暖机保护的证据。统一顶层后确认共享负载下不丢帧、采样与位姿对齐。雷达10°俯角是项目记录，真实安装角和光心高度仍复测；不能用模型高度命令直接代替。导航工作期间其他主机不能另连雷达TCP抢流。

### 6.2 BMI088（复用现有I2C）

- 当前接线P11-7/F18为SDA、P11-8/E18为SCL；P11-1–4已经是舵机、5–6是OLED。旧SPI接线表停止使用。
- 当前源码加速度±3g、陀螺±2000°/s，约10ms轮询；加速度ODR100Hz、陀螺内部ODR2kHz，并不表示两芯片同步或融合输出2kHz。
- 控制侧已有三轴角速度、重力向量与融合；导航转换坐标和单位，按采样时刻接入历史。无绝对航向，不能凭重力向量恢复yaw。
- 上板核对静止、抬头、侧倾、左转的符号与量级、零偏初始化有效性、样本新鲜度以及雷达同时运行时的时延。旧1000Hz/800Hz验收目标撤销，以实际合同为准。
- 具体读取端口/寄存器由G1/G3实现后补入操作手册，不能把拟新增CHAS寄存器写成现成命令。

### 6.3 导航与底盘

正常车体零目标仍需平衡；当前单轮零目标却因 `MOTOR_CLOSED_LOOP_AT_ZERO=0` 禁PWM并清PID，执行模型不能默认已有主动轮速制动。轮速与陀螺必须反映实际运动，不能因命令为零而清零。对地速度需推车/摆动数据校验俯仰耦合符号，不能在未核轴向时硬套“加”或“减”。反馈频率与有效窗口匹配，建议目标50–100Hz在G1冻结。

导航默认限幅、串口可接收范围和车辆可跟踪范围是三件事。控制UART接受±0.6m/s、±2.9rad/s，不证明真实倒车/旋转已在该范围验收；初版速度包络来自G4实测。高度切换也需处理雷达外参变化，不能默认为固定腿高。

### 6.4 RK3588

自主导航模式发送任务和目标，连续速度由导航SAFE输出。控制仓库现有直接速度UART适合底盘调试，不能与导航入口并发写目标。R0任务协议和控制UART协议完全不同；详见 [RK设计](../5_teams/rk3588_design.md)。

### 6.5 视频与显示

先独立取得资源/时钟域需求再决定合入；显示姿态复用同一数据生产者。外部像素/DDR时钟域按实际域关系同步。是否需要视频或SFP及验收指标按赛题和当前队伍范围单独确认，不因旧估算直接承诺同片余量。

## 7. 停止与保护合同

| 情况 | 已有机制 | 集成待定部分 |
|---|---|---|
| 正常零速/任务停止 | 原4500继续推理和纠偏 | 以实际反馈判断停稳，不要求轮编码器绝对为0 |
| 导航SAFE急停 | 下一SAFE节拍目标直接归零并有 `ch_stop` | 是否只受控停止或映射硬停须明确，不能直接等同底盘断驱动 |
| 导航看门狗 | 缺省200ms，SAFE按斜坡减到零并有 `ch_wdog` | 必须真实接入；独立控制UART当前无命令年龄保护 |
| 主机 `mode estop` | 当前任务模式4、零目标 | 不等于 `SAFE.CTRL.ESTOP`，不产生同等硬件急停语义 |
| 控制红外急停/故障 | 关闭轮驱动、舵机保持；红外急停锁存 | 与正常保持平衡不同；不能声称每种停机都保证不倒 |
| 物理断电 | 需要核对实车线束 | 当前顶层无已确认的外部输入；P11-8被I2C使用，不能沿用旧分配 |

首次统一工程上车及方向变更先在支架上核对；下载前确认执行器状态和功率回路。硬件断线是否触发急停由触点、上拉/下拉、有效极性共同决定，“低有效＋上拉”本身不是断线保护证据。

## 8. 时间与记录

统一微秒时间是设计目标；导航 `time_us` 目前在模块内部，控制尚未接共享端口。G1/G3需定义采样时间、接收时间和时钟域，32位微秒回绕按无符号差处理。不能把不同源的计数直接当同一时钟。

每次正式集成记录：源码提交及未提交差异说明、模型/参数、工具和器件版本、实际文件名与头部生成时间、联合构建报告、导航日志、控制遥测和现场条件。按任务需要保存现有证据，不要求哈希或重复测试。失败保留输入和现场后再修复。

## 9. 文档与实现同步

ICD语义变化同步更新 [ICD](../2_interface/icd.md)、[pinout](../2_interface/pinout.md) 和相应源码；寄存器变化先改 `config/regmap.yaml` 再生成文件。当前文档审阅没有修改YAML、RTL或固件，所有“拟新增”仍是计划。几何与实测参数以 [platform](../4_design/platform.md) 的来源栏区分历史CAD、训练设置和实测。

## 10. 验收范围

基础导航、底盘运动、视觉任务和显示各自列出实际测试条件及结果。历史50/50不是当前严格口径成绩；最新N1c28/50也不是实车成功率。比赛评分和演示要求沿用队伍已确认材料，最终以官方任务书为准，本轮没有重新核定评分比例。

## 11. 当前主要风险

优先级依次是：命令/停止/反馈合同不一致、联合资源不足、导航N2g新增回归、时间/地图一致性、真实响应与装车参数缺少标定。已有控制源码和模型降低了从零开发风险，但没有消除这些整车边界问题。对应交付已放入G1/F1/G2/F2/G3–G5，不再保留“策略尚无转向”等过期阻塞项。
