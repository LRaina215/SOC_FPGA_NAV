## 1. 目标与前后方案的关系

目标是在沿用现有 FPGA 导航架构、RL 轮推控制和 BMI088 输入的前提下，修复可由离线证据确认的问题，提高地形判断、局部规划和定位的可靠性，并形成能迁移到现有 C/RTL 的实现与验收记录。

**前面的方案保留，调整的是依赖、验证方式和实施顺序。** 审阅实机资料后，并未发现“导航算法优化不该做”，而是发现原先若直接按闭环成功率调参，会混淆三件事：感知计算是否正确、规划在给定运动能力下是否正确、实车是否具备该能力。第三件事目前证据不足，不能由前两件事代替。

| 前期提出的方向 | 本计划中的安排 | 调整原因 |
|---|---|---|
| 所有运动指令统一检查，包括恢复、旋转、重定位 | 保留，优先做 N2，随后由 N3 加入响应与制动复核 | 当前存在绕过常规候选检查的运动分支；仅检查名义匀速轨迹仍不充分 |
| 终点低速、停稳确认、解决近目标绕障 | 保留，优先做 N1；末端航向兼容性单独核对 | 当前“接近但卡住”可能被算成到达，评测又在到达声明后立即结束 |
| 考虑延迟、惯性、跟踪误差和制动 | 保留，先做 S1 的执行链，再做 N3 | 当前简化车模没有串起实际 SAFE 输出；RL 响应参数尚无实测依据 |
| 定位质量门控、时间补偿和重定位改进 | 保留，L1 → L2；L3 按收益决定 | 先保证时间与观测有效，避免对已经污染的输入继续调匹配参数 |
| 地形可行性分析 | 增补为 T1/T2，并修正 P0 的评测口径 | 几何测量、噪声容忍与车辆能力阈值混用，未知区域也有被低估风险的路径 |
| 使用 MuJoCo 提高仿真可信度 | 按新总计划F2/J1–J4推进；MuJoCo动力学主验证、独立快速回归、后续实测校准 | 原4500、执行器映射与等效开链MuJoCo已提供；复用现有平台，真实闭链接触与实车参数仍未验证 |
| 目标跟踪、探索效率等增强 | X1/X2 放在基础正确性任务之后 | 不用效率提升掩盖误到达、错误放行、定位失效等问题 |

最初采用有界修复以便定位反例；用户现已允许基于证据重构导航/地图/仿真架构。是否替换A*或局部规划器仍须由收益、资源与回归证据决定；固定原4500，不执行控制C1–C5。

| 现有车模 | 有一阶响应、加速度限制、打滑及姿态摆动；不是完全瞬时跟随 | [robot.py](../../sim/closed_loop/robot.py)；没有真实 RL、轮地接触、力矩饱和和失稳动力学 |
| 机械模型 | 原CAD、控制训练URDF/STL、原4500 checkpoint和等效开链MuJoCo均有；真实闭链模型引用文件仍缺 | [platform](../4_design/platform.md)分栏记录；旧闭链脚本对应旧1000模型，不能给当前4500下通过/失败结论 |
| 地形能力 | 20 mm 台阶、12° 坡度是仿真假设，不能称为实车已测能力 | [world.py](../../sim/closed_loop/world.py) 明示能力未实测；控制调通不自动等于通过性边界已测 |
| 历史结果 | 文档记录无图/有图各 25 个选定闭环用例成功，以及 15 项 RTL 回归通过 | 历史记录只能证明当时配置和判分方式；改变判分后必须重跑原版基线 |

机械尺寸可作为几何建模的起点：资料中的车宽约 332 mm、轮半径约 33.65 mm、轮距约 270 mm、外接圆半径约 209 mm。这些是旧CAD值；新控制配置轮半径32.5mm另列，实物未测前不静默合并。它们不直接给出爬坡、制动和稳定性能力；固定腿姿态下的足迹、轮支撑位置和离地间隙须由模型变换复核。

雷达 10° 安装俯角有项目记录支持；高度约 155 mm、相关安装基准量仍需装车复测。旧标定文件存在不同历史值，P1 负责列清来源，不能静默任选一份。

### 2.2 目前不能确认的内容

- 同片整车顶层、SAFE实际接入、反馈估计与采样时间、联合资源和时序报告；目前已能核对独立控制源码。
- 实车速度跟踪误差、最慢制动、倒车与旋转可用范围；RL模型、六维动作、125Hz周期已明确，现有模拟扫描不能替代实测。
- 整车实际质量、质心、惯量、轮地摩擦、执行器限幅，以及不同腿姿态的能力边界。
- 控制调通时是否已覆盖坡面、台阶、负障碍和低附着路面；没有记录前不作推断。

这些缺项不会阻止 P0、N1/N2、L1、T1/T2 的离线工作。涉及执行响应的结论必须带上假设条件；涉及实车能力的结论留到 H2。

### 2.3 如何理解“Python 验证后能迁移”

| 验证层 | 能得到的结论 | 不能直接推出的结论 |
|---|---|---|
| 独立场景几何 → 虚拟传感器 → 地形算法 | 对受测几何、误差和遮挡条件，是否测错、漏检或错误填洞 | 实车一定能跨过被判可行的地形 |
| 同一份导航 C + 明确声明的执行响应模型 | 在这些能力与误差范围内，状态机、路径和停止行为是否符合要求 | 真实 RL 的响应一定落在这些范围内 |
| Python 定点参考 ↔ RTL 逐位比较 | 对受测输入，数值、状态与接口是否一致 | 传感器标定正确、物理模型正确或整车已通过测试 |
| 完整模型 + 对应控制器 + 实测校准，最终实机复核 | 逐步建立与实车相关的通过性和执行裕量证据 | 在未覆盖地形和姿态上也无条件安全 |

在几何测试台中按已知轨迹摆放机器人是合理的隔离实验，用于单独验证感知；不能再用这条指定轨迹证明车辆能够执行它。现有 1 cm 世界几何与受测栅格算法不同，并非全部是循环论证；问题在于两者共享了未经实测的车辆能力假设。

## 4. 第一批任务：评测与基础正确性

### P0 — 重建判分与原版基线

- **依赖与范围：** 首先执行。修改 `sim/closed_loop/run_cl.py`、`eval_trav.py` 及必要的评测辅助脚本；原版算法保留，用同一新判分运行。
- **具体工作：** 固定场景、起始位姿、目标、地图模式、随机种子、传感器配置、采样周期和误差范围。区分调参用例与保留验证用例。记录实际命令及覆盖参数，不仅记录默认配置。
- **修正成功条件：** 固件声明到达后继续观测，独立检查真实位置误差、停稳及漂移；将任务超时、假到达、无法继续、碰撞分别报告。正常 150 mm 位置容差先沿用现值；“卡住后离目标不足 600 mm”不能算到达。真实位姿只用于评测，不泄露给被测导航。
- **修正地形统计：** 分开原始危险识别、膨胀后的车体可达性、未知区域和边界忽略带。不能把 253 膨胀格的拦截效果算成地形本体识别正确，也不能只统计已知格而隐藏观测缺失。保留现有指标作为历史对照并明确其含义。
- **交付与验收：** 可复现的基线清单和报告；用构造结果证明判分能识别假到达、未停稳、原始漏检被膨胀遮盖，以及大面积未知。原版与新版均按修正后的口径比较，不继续引用旧“50/50”充当新基线。

### P1 — 冻结参数来源、接口合同与资源约束

- **依赖：** 可与 P0 并行；后续实现使用其结论。
- **具体工作：** 建立参数来源表，区分已测、CAD、厂商定义、旧配置、仿真假设。核对单位/坐标系、雷达安装、固定导航腿姿态、占用足迹、SAFE 设置及地图代价值。能力参数与感知参数分别命名和配置。
- **接口合同：** 列明 `vx/wz` 请求、实际速度反馈、姿态、时间戳、控制有效状态和停止语义。暂以适配层连接现有导航，不要求用户现在整理全部控制代码；新代码拿到后补差异核对。
- **资源合同：** 记录现有 C 段大小、共用缓存与算法边界，以及当前 100 ms 规划周期、实际 SAFE 看门狗设置（本地复位值 200 ms）和主循环其他开销。需要新增数组或寄存器的任务先说明预算和替代实现；最新整车资源未知处明确留空。
- **验收：** 每个影响几何/安全判断的参数都有来源、单位、用途和有效条件；禁止用“仿真调通值”标注成实测能力。现有 `255=未知、254=危险、253=膨胀` 的区别贯穿规划与评测。

### N1 — 路径、终点与进展判断

- **依赖：** P0/P1。主要文件：`fw/nav/nav_task.c`、`local_planner.c`、`astar.c`。
- **2026-10-21 前批记录：** 单独收紧前视路径的首个组合在坡道种子3中停滞并出现13次模型碰撞，已撤回该组合。当时只接受停稳与近目标受阻子集，路径子任务改为与N2恢复检查联合验收；本次进度见下方N2记录。
- **路径工作：** 修复近目标约 800 mm 内直接指向目标但未检查视线的路径；去掉不可见时强行推进路径点的行为；区分 A* 完整路径与部分路径，部分路径末端不等于最终目标。
- **终点工作：** 取消“卡住 6 秒且距目标不足 600 mm 即到达”的逻辑。增加终点低速与停止候选，以位置、实际运动状态和连续稳定时间确认到达；不把单次发零速当成已经停稳。
- **进展工作：** 根据模式分别看沿路径推进、剩余路径变化或转向进展，避免绕障时因直线距离暂增而误判，也避免来回摆动不断重置卡住计时。
- **航向兼容：** `GOAL.yaw_cdeg=0x7FFFFFFF` 已表示不关心朝向，主机工具默认使用它。先核对其他发送方是否默认发 0；新增末端对齐时保留哨兵语义，并检查旋转足迹。航向功能可独立交付，不阻塞位置与停稳修复。
- **验收：** 近目标隔墙、U 形绕障、部分路径、终点窄区、停稳前滑行及指定/不指定朝向的案例行为明确；独立判分中的假到达为零。无法完成应报告阻塞或失败，不能用放宽容差提高完成率。

### N2 — 所有运动分支通过统一检查

- **2026-10-21 本次进度：实现子集通过，联合验收未过。** 已统一运动出口及来源/结果诊断，最终指令经过同代地图与完整圆足迹检查；修复近目标直连、部分路径替换终点、强推不可见点、无路径直指终点、长路径丢起点、虚拟障碍自身封锁/远处反馈和可见接入点。专项及完整主机回归通过，最终联合失败见下方G记录；没有正在运行的全批评测。
- **未知近场的证据与限制：** N2a将新增未知足迹一律拒绝，坡道从起点无法行驶，已否决并保留诊断。当前明确继承 `allow_unknown` 的前向探索许可，检查结果仍记录为UNKNOWN；新进入未知足迹的倒车拒绝，恢复改用经检查的旋转。不能将该许可称为已验证轮支撑或自由地面；T1/N3仍须完成近场支撑与停止区合同。若任务要求绝不进入未知足迹，应关闭 `allow_unknown` 并接受现有传感器盲区造成的停顿。
- **资源约束：** 关闭LTO的RV链接触发128KB限制；导航构建现默认启用LTO，现有板级构建入口可沿用，selftest保持原方式。G镜像36968B、BSS85340B，预留8KB栈后余572B。板级周期未测，未知近程规则与执行效率仍待完整验收。

- **依赖：** 实现依赖P0/P1；与N1协同处理停止。实现子集已具备，整体验收按上方新增证据与L1、地图一致性、S1/N3联修。
- **具体工作：** 收敛正常规划、恢复倒车、原地转向、探索兜底旋转及重定位 `hold_wz` 等非紧急运动分支。限速、平滑和模式约束在轨迹评估前应用，发出的指令须对应受评估的轨迹。
- **已知问题：** 当前部分限速只缩小 `vx/vy` 而保留 `wz`，会改变曲率；禁止评估后再这样修改指令。缩放或重新采样均须按最终指令复核。
- **恢复语义：** 从膨胀区退出不能仅凭降低代价阈值放行；必须检查原始危险格与完整足迹。未知区域的处理结合近程停止区与轮支撑，不把所有未知永久封死，也不把它当成自由空间。
- **停止层级：** 保留紧急安全链优先级。正常无可行候选时请求保持平衡的受控停止；N3 完成前，不声称名义轨迹检查已经覆盖动态刹停过程。
- **验收：** 每个运动出口均有可追踪的检查结果；覆盖倒车后障碍、窄区旋转、重定位时近障和缩放后曲率变化。失败路径不继续发未经检查的恢复动作。

### L1 — 时间戳、历史查询与姿态有效性

- **依赖：** P1；主要文件 `pose.c`、`nav_app.c`、`target.c` 及相关 HAL。
- **具体工作：** 保持高频状态积分，按固定时间间隔保存有限长度位姿历史；不要让 1 kHz 更新把 64 项历史压缩到约 64 ms。根据实测/设定端到端延迟选择历史跨度，记录超界次数。
- **查询合同：** 返回有效、过旧、过新或缺失等明确结果，禁止静默夹到首尾样本。区分采集时间、接收时间与预测时间；32 位微秒时间差按回绕规则处理。雷达、目标和姿态插值调用者同步适配。
- **准入工作：** 姿态是否稳定依据采集时刻的有效历史判断；对于过期、乱序或无法补偿的观测采取明确的丢弃/降级策略，不拿当前姿态冒充历史姿态。
- **验收：** 高频输入、迟到帧、时间回绕、历史边界和目标延迟的定例通过；有效覆盖率、丢弃率和定位误差同时报告，不能靠丢掉绝大多数帧获得漂亮误差。

### T1 — 修复未知地形被低估风险的路径

- **2026-10-21新增阻塞证据：** `diagnose_step_margin.py`在完全观测、无噪声的正台阶上确认21/25/30mm均未输出原始危险，而当前独立物理能力假设是20mm；31/75mm能检出。此前96项只覆盖75/150/300mm，不能证明能力边界附近安全。详见`sim/build/nav_opt/step_capability_gap_audit.json`。这不是实车能力测量，不通过放宽20mm评分消除反例。
- **依赖：** P0/P1；参考文件 `model/trav_v3.py`，部署候选同步 `rtl/map/trav_v3.v`。
- **坡度有效性：** `gated_rise()` 已返回有效标志，但调用处丢弃；基线上有未知格时得到的 0 不能当作“已观测为平地”。保留各方向有效性与支持程度，区分平缓证据和证据不足。
- **孔洞与落差：** 复核小孔填补条件；对沟槽、平台边缘、单轮前方缺失、远端完全无回波等情况保留风险或未知。无法仅凭无回波判断一定是坑，也不能因此认定可走。
- **策略接口：** 原始观测质量与危险结果分开解释。近程制动走廊/轮支撑需要足够观测；探索可以朝未知边界接近和补观测，但不能盲目跨越。若需新增编码，先完成 P1/H1 的接口与资源论证，不静默改变 253/254/255 的含义。
- **验收：** 缺失坡面不再被当作零坡度放行；负障碍反例不被无条件填平；同时报告误报、未知与任务完成率，禁止“全部停住”被判成优化成功。几何结果与迁移结果分别登记。

## 5. 第二批任务：执行裕量、地形测量与定位

### S1 — 在闭环中串起 SAFE 与有界执行响应

- **依赖：** P0/P1；这是 N3 的评测前提，不依赖 RL 文件。
- **具体工作：** 建立“导航请求 → SAFE 限幅/斜坡/看门狗 → 控制响应 → 实际运动”的可观测链。依据现有 SAFE 实现/台架记录复现数字逻辑；控制响应仍使用明确标注的参数模型。
- **扰动范围：** 至少区分标称、较慢跟踪、较差制动与额外时延；覆盖转向与纵向响应不同步、测量反馈延迟及可配置滑移。不能只增加加速度限幅就称为真实控制仿真。
- **时间核对：** 检查 `hal_py` 的固定延迟与真实板级计算/地图周期。现有注释有 100 MHz 假设，但不能据此直接把所有延迟翻倍；应从周期数、调度和板级测量建立依据。
- **验收：** 请求值、SAFE 输出和实际速度分别可追溯；看门狗与斜坡事件可复现。报告使用的假设范围，留出将来用实测日志替换参数的入口。

### N3 — 动态候选与制动走廊复核

- **2026-10-22状态：进行中，未验收。** 已接实际反馈、停止保持与响应管道，补齐反馈断档/未知停止余量/启动停稳合同；33项C反例与7880组名义几何通过。地图准入后的保持仍失败，零输出仍有实际漂移，不能称停止包络已验证；详见文末AZ接续记录。

- **依赖：** N2统一出口/名义检查的实现子集、S1、L1；使用T1已明确的未知语义。N2整体闭环验收不作为本任务的先决条件，二者联合验收；地图一致性属于必要条件。
- **候选生成：** 从当前实际速度和上一有效指令出发，增加低速、停车与局部邻域候选，考虑可达速度变化。保留既有硬件候选/步数边界，先比较收益再增加数量。
- **分层评估：** 既有硬件负责粗筛；对少量优先候选做 CPU 复核，模拟延迟、SAFE 与响应斜坡，并延伸到制动结束。初始可试前 3 个候选，但数量由周期/内存测量决定，不预先承诺软核算得动。
- **几何复核：** 检查车体运动扫过的区域和轮支撑区域，处理转向时外侧扫掠；停止候选也从当前速度开始计算。明确使用“原始障碍 + 足迹”还是“已膨胀图 + 中心”，避免对同一半径重复膨胀。
- **地图一致性：** 粗评与细检核对地图代际、窗口中心和坐标系；处理 `hal_traj_eval()` 已提供的评估期间地图变化状态。地图变化时有界重试或受控停止，不能无期限重试。
- **验收：** 延迟驶向障碍、慢制动、急转弯、倒车与足迹边角擦碰等案例改善；独立碰撞检查使用世界几何，不复用规划器的放行结论。完成率、距离、耗时和停止次数不得被安全指标隐藏。
- **迁移条件：** H1 证明定点误差、最坏工作量、栈和 RAM 可接受；若超预算，先减少候选/复用缓存/收紧局部范围，再决定是否需要新的硬件支持。

### T2 — 分开几何测量、感知误差与车辆能力

- **依赖：** P0/P1、T1；L1 提供有效采集姿态。主要文件 `trav_v3.py`、`prior_map.py`、评测脚本及对应 RTL。
- **具体工作：** 在参考模型先记录台阶、落差、坡度方向与幅值、粗糙度和观测支持程度；用可配置车辆能力和误差裕量再作决策。未经校准的质量分数不得称为统计置信概率。
- **阈值梳理：** 当前感知默认台阶 30 mm、坡度高差 57 mm/20 cm（约 16°），世界能力假设为 20 mm/12°，先验地图另有 100 mm/20° 默认值。这些不因数值不同就自动构成同一种 bug；须写清分类阈值、几何误差和能力边界各自含义，并通过统一配置入口关联。
- **方向误差：** 测量 `max(rx,ry)+min/2` 近似在旋转、栅格相位与斜向台阶下的偏差，再决定改用更好近似或 LUT。沿坡与横坡能力可以分别配置，但真实边界等待 H2。
- **误差实验：** 跨能力边界连续扫描几何，而非只比较相距很远的正反例；扰动外参、采集姿态、深度噪声、漏测和边缘混合。感知噪声通过估计/决策裕量处理，不能简单放宽致命阈值。
- **资源策略与验收：** 首先用诊断输出或复用局部缓存评估效果，不直接新增整张多通道特征图。给出边界召回、误报、未知、方向偏差和空间损失的改善证据；通过 H1 后才替换部署实现。

### L2 — 定位提案、准入与提交分离

- **依赖：** L1、P0；主要文件 `pose_match.c`、`loc.c`、`nav_app.c` 及匹配 HAL/RTL。
- **具体工作：** 求解先产生位姿修正提案，根据有效点、内点比例、代价、搜索边界、创新量和退化方向决定是否提交。保留已有 Hessian 强弱方向处理；弱约束方向冻结或降低增益，不从头重写整个定位器。
- **地图顺序必须准确：** 当前流程先提交雷达并融合高程，再完成 SLF 求解。因此后置门控可约束位姿修正和结构图更新，不能撤销该帧已写入的高程图。高程图需要提交前时间/姿态准入；较大位姿修正按现有逻辑清图重建。
- **拒绝语义：** 无先验在线建图模式下，`hal_match_update(0,0,0)` 仍会把未修正结构点并入地图，不等于丢弃；有图 `PRIOR` 模式的 `UPDATE` 已仅释放点缓存、不并入固定先验图。为无先验模式增加“释放缓存但不并图”的明确操作时，须保留这一模式差异，并经配置源、三个 HAL、参考模型与 RTL 同步实现。
- **启动与失效：** 无先验模式保留受限的初始化建图通道，避免“无图就无匹配、无匹配就不建图”的死锁；失去质量时限制运动并保留恢复入口。先使用已有对外状态表达，新增字段需接口同步。
- **验收：** 错误匹配不会先改位姿再被标坏；拒绝帧不误更新结构图；走廊退化、重复结构、初始无图、连续丢帧和较大修正均有明确行为。同时报告定位有效率与失效时间，区分全程误差和仅有效时段误差。

### V1 — 可选并行的 MuJoCo 几何与可见性测试台

- **依赖：** P1；可与B/C分开推进，不阻塞时间/路径修复。几何与动力学复用项目隔离环境；早期conda/MuJoCo3.2.7导入成功只是历史准备记录，当前J1已在3.3.7实际运行。
- **具体工作：** 从现有 URDF/STL 建立固定导航姿态的几何测试台，检查足迹、轮支撑、离地间隙、雷达视野和三维遮挡。记录坐标轴、尺度和变换；接入统一几何案例，补充现有 2.5D 高程场不能覆盖的场景。
- **模型处理：** 当前 URDF 缺少四个被动膝关节与后腿闭链；完整 STL 同时作碰撞体也需简化/凸分解。固定姿态几何台无需假装这些动力学已经完成。
- **验收：** 已知尺寸、静态接触位置和视野可复核；指定轨迹仅用于观测实验，不作为动力学通过证据。只在新增三维证据对当前问题有价值时扩建，不把搭建仿真本身作为优化成果。
- **后续条件：** 得到对应闭链模型、执行器参数与策略，或得到足够实测响应数据后，再决定是否建立完整动力学闭环。现有 CAD 质量约 0.676 kg、导出关节 effort/velocity 字段均不能直接当作整车实测值；也不临时换一个 PID 来声称验证了真实 RL。

## 6. 有明确收益后再执行的任务

### L3 — 重定位的多候选细匹配

依赖 L2。现有粗搜索已有多个候选，先检查失败日志是否来自只细化首个候选；在重复结构反例中比较细化前 2–3 个候选的收益与最坏耗时。验收同时包含错误接受率、恢复时间和资源；不能只提高“找到匹配”的次数。没有收益或超预算则保留现实现，并记录原因。

依赖 L1、N1/N2，使用 `target.c`。为乱序、过期和目标身份切换建立明确处理，比较轻量滤波与有界短时预测；不直接用迟到目标位置覆盖当前目标。新目标报文若需新增字段必须遵循 ICD，现有字段足够时优先内部处理。验收看延迟/跳点场景的跟踪误差、控制抖动和丢失处理，不只看目标平滑程度。

### X2 — 探索效率与地图证据时效

依赖 T1、N1/N2、L1，使用 `explore.c`、`gmap.c`。现有系统已有 frontier/BFS 和观测记忆；局部高程图有帧龄淘汰，虚拟障碍有 TTL，全局 `gmap` 的普通观测尚无逐格时间自动衰减。先检查旧局部格是否被重复计为新证据，再比较单位行驶代价的信息增益、边界可观测性与重复访问惩罚。过期不等于自由，不能把清除障碍当作探索优化。验收包含覆盖率、重复路程、时间、危险进入与未知占比。

基础任务通过后，增加障碍出现、移动和离开的时序回放，用独立世界几何检查新增障碍生效延迟、旧障碍消退与停车响应。是否增加动态预测由结果决定，不扩展首批范围。

## 7. 从离线结果到部署结果

### H1 — 每个稳定批次的迁移与资源检查

这是一项随批次执行的检查，不能全部拖到最后，也不要求每次微调都重跑全量。

1. **固件链：** 同一导航 C 源码 → 主机测试与闭环 → RV32IMC 编译、段大小与栈分析 → 必要的板级周期测量。任何新 HAL 同时实现 `hal_fpga.c`、`hal_sim.c`、`hal_py.c`。
2. **硬件链：** 独立几何证据 → Python 定点参考 → RTL 同输入逐位/状态对照 → 全回归 → 导航独立工程综合布线。参考模型变化但 RTL 未更新时，仅记为“离线候选”。
3. **定点边界：** 覆盖符号、舍入、饱和、角度回绕、未知值、边界格、阈值相等和地图切换。TRAJ 局部轨迹候选与步数各不超过 64；SLF MATCH 每批候选不超过 256（当前常规配置 245），按各自接口检查，不能混用限制。
4. **唯一配置源：** 结构参数改 `config/nav_params.yaml`，寄存器改 `config/regmap.yaml`，运行 `tools/gen_config.py`；不手改生成的头文件、RTL 寄存器或寄存器文档。
5. **内存与周期：** 旧导航记录为镜像 36012 B、BSS 85324 B、保留 8 KB 栈，128 KB 内余量约 1.5 KB。新增缓存优先复用 `g_scratch`，须证明不与 A*/BFS 嵌套使用；不能用 PC 耗时代替 PicoRV32 最坏周期。
6. **FPGA 资源：** 旧独立导航报告 BSRAM 324/340、DSP 67/298、逻辑 24808/138240，50 MHz 时序余量很小。这不是新整车余量；不能预支剩余 16 块 BSRAM。整车继续使用集成计划的项目门槛：布线后 BSRAM ≤336、时序零违例。
7. **时间与发布：** 先用实际板级时钟核对预算；N3 必须在 P1 记录的规划周期内留出传感器处理、定位及主循环其他开销，不能仅以“不触发看门狗”为实时性验收。若缺少足够的周期证据，标为待板级确认；可采取减少细检范围或候选的降级方案。新外部状态/协议同步 ICD 与底盘对接文档。

任务通过条件是相关功能、数值一致性、接口及资源证据齐全；若只能证明 PC 上可用，不标为迁移完成。新整车源码尚未提供时，可完成导航独立工程迁移检查，但整车合入仍是 H2 的待办。

### H2 — 新整车适配与实机能力标定

- **进入条件：** 用户提供整车源码/接口资料或可复核的构建结果；实机阶段另需设备可用。今天不以缺少这些资料阻塞离线任务。
- **先做适配：** 核对控制与 BMI088 的现有实现，复用采集与控制；检查坐标、单位、符号、更新时间、时钟域、有效标志、SAFE 链和共享资源，再做整车综合布线。用实测反馈替换 S1 的响应假设。
- **测运动边界：** 从固定腿姿态、平地低速开始，测速度阶跃、转向、延迟、受控停车和跟踪误差；记录工况与重复分布。没有确认倒车/原地转向能力前，对应导航恢复动作保持限制。
- **测地形边界：** 在可控条件下逐步测沿坡、横坡、小台阶、落差边缘感知与制动；观测轮支撑、机身触地、姿态与失稳。将“能一次通过”和“有重复裕量的可用能力”分开。跨越未知负障碍不是初始测试目标。
- **回灌与再验收：** 将实测能力和误差范围写入平台参数/配置，重跑相关离线保留用例，再做有图、无图、目标跟踪与恢复的整车任务。若实测超出假设范围，调整限速/能力边界并重新验证，不只补一句免责声明。
- **最终交付：** 整车接口差异、构建资源、参数标定、任务结果与未覆盖条件。只有这一阶段完成，才能将相应能力标记为实车已验证。

先做针对性定例，再在稳定版本做同场景、同种子的原版/新版配对比较，并保留未参与调参的用例。覆盖能力边界与交互问题即可，不无差别穷举所有参数的笛卡尔积。

### 8.2 判断改进是否成立

- 定义上的错误必须消除：受测定例假到达为零，越界/过期查询不静默成功，未知坡度不伪装成平地，拒绝匹配不先提交位姿。
- 新增安全检查不能只靠拒绝一切获胜：同时报告完成率、耗时、路程、恢复次数、停顿与振荡。若安全改善伴随效率退化，给出逐例原因和取舍，不只公布一个总分。
- 改善阈值在看新版结果前确定；若暂缺工程依据，先报告差异分布和失败类型，不临时挑选有利门槛。任何因失败而改动的评测标准都要回跑双方。
- 独立几何检查不调用受测规划器的危险判断；原始几何标签与“给定车辆能力后的通行标签”分别保存。仿真真实状态不传入正常导航输入。
- 终点停稳的首轮离线建议值可设为 `|v|≤20 mm/s`、`|w|≤50 mrad/s` 连续 500 ms，并在声明到达后继续观测至少 2 s；这些是待 P0 固定的评测建议，不是实测底盘指标，H2 根据反馈噪声和控制特性复核。
- 对假设范围以外的工况报告“未验证”。参数扫描通过不等于获得了实车安全认证。
