# 总任务：3×5 m 封闭场地的单芯片整车工程（导航 + 原 4500 控制）收敛

本提示词取代此前所有分段指令和上一版总提示词。执行状态继续记录在 docs/1_plan/system_integration_plan_20261021.md 和 docs/4_design/g2_small_field_storage_plan_20261026.md。

## 0. 已定决策（不再讨论，不得自行改变）
1. SLF 结构图改为 128×128（6.4 m，5 cm 格不变），这是既定方向。256 只作为仿真里的对照基准，不再作为构建候选；任何情况下都不得自行退回 256。
2. 验收采用用户已接受的三条任务门槛（第 3 节），取代"相对 256 增量 ≤10 mm"。
3. 本工程不含 SFP 和 DDR。
4. 摄像头采集与显示将来会放在这块 FPGA 上，但不由本任务开发，合入时机另定。本任务只负责给它预留资源。
5. 红外硬急停和 OLED 保留。

## 1. 目标与完成标准
在 GW5AT-138（按器件 C 构建，实物 B/C 待核）上得到一个同时包含导航和原 4500 控制的位流：
- 布线完成、未布通为 0，且两种不同 place_option 都能布通；
- clk50 50 MHz、rgmii_rxc 100 MHz 的 setup/hold 全部为 0，跨域约束全部生效，复位恢复/移除/脉宽为正；
- 导航 + 控制的物理 BSRAM 暂定 ≤ 300 块，以 336 为部署上限，为摄像头留至少 36 块；预留量以后按摄像头负责人的实测调整；
- 功能完整：雷达链路；SLF 定位（无图、有图）；原 4500 推理（权重、训练、125 Hz 不变）；红外硬急停；OLED；双串口（CH9102 导航邮箱、P11-39/40 控制串口）；指令有效期与失联停止。
全部满足后才准备上板。

## 2. 已确定的事实

比赛要求（docx/全国大学生嵌入式芯片与系统设计竞赛'2026FPGA.pdf 第 15–16 页，选题三）：导航只要求起点到终点、避障、路径点导航，示例为"移动到其附近"，全文没有精度指标；评分为 FPGA 实时感知与控制 40%、系统稳定性 25%、自主导航 20%、创新 10%、AI 扩展 5%。用户不追求高精度。

场地与车：
- 场地 3×5 m（长轴 5 m），四周约 0.5 m 高的哑光纸板挡板，上方开口，车只在场内运行。
- 出发位置固定，车头与场地长边或短边平行（摆放误差约 ±5 cm、±3°）。出发坐标和平台/坡顶最高高度待用户提供，暂用 field3x5_v1 的 goal 起点 (0.45, −0.95, 0°) 和 84 mm，标为暂定。最窄通道尚未布置，先按 field3x5_v1。
- 雷达光心离地 155 mm、下俯 10°，视场上沿约 +9.3°；车离 0.5 m 挡板超过约 2.1 m 时能看到挡板外。SLF 结构点高度带上限（MATCH.ZREL 的 ZHI，固件 APP_ZHI，默认 1500）本场地取 350 mm，ZLO 不变（无图 60、有图 −300）；平台高度确定后按"500 − 平台高 − 约 66 余量"重算。
- 只有一块板，必须单芯片。RK3588 通过 CH9102 和 P11-39/40 连接。

布线历史（约 52 轮）：
- 只有两个网表布通过：10-22 基线（PNR27/31 复现），以及基线 + 融合模长（PNR32/35：332 块，clk50 实测 33.197 MHz，3781 个 setup 违例，hold 为 0）。
- CLS 和未布通条数都不能预测结果：PNR49 与 PNR50 网表几乎相同，未布通分别为 427 和 1659；PNR51/52（环形存储，CLS 75.6%/74.3%）仍有 1288/1026 条未布通；增量布线（PNR48）无效。
- 结论：围绕单个小候选反复整网布线是抽签，停止。下一次 PNR 必须建立在第 8 节的联合候选上。

存储：
- 联合需求约 393 块，大于 340；约 26780 个逻辑单元被挤成分布式 RAM/ROM。
- 仍为分布式的大项：u_tv/u_bm 16384×1 位图（6144 单元，迁 BSRAM 只需 1 块，优先）、u_match/u_ex/u_rb 1650、u_mbx 的 u_injb 与 u_txs 各 1536、u_match 的 slist/cand/res 各 1536、u_soc/g_con 4×768、正余弦表 4×737、策略 bias 702。u_tv 行缓存和 ELU 已在 BSRAM，不重复计算收益。packed_weight9 实测省 5 块。
- SLF128 加无损迁移的预算（以 SYN40/PNR52 为基数，已含环形存储，须实测）：约 332 − 51 − 5 + 18 ≈ 294，再加点缓冲位面重排约 286。

SLF 试点结论（field3x5_v1，冻结 N1c，seed1）：
- 要调整的"窗口"是 SLF 似然场/打分窗口，只用于定位；高程图、代价图（128×128，随车）不动。
- 定位有效段 RMSE / P95（mm）：

  | 配置 | goal | turn_loop |
  |---|---|---|
  | 256（对照基准） | 13.2 / 19.4 | 20.9 / 42.5 |
  | 128 居中 | 55.1 / 72.5 | 40.2 / 64.9 |
  | 消融：256 存储 + 128 窗口 | 51.0 / 65.5 | 46.0 / 69.8 |
  | 128 固定场地中心 | 14.3 / 24.9 | 60.3 / 105.7 |
  | 128 前移 1.5 m | 18.3 / 34.1 | 25.1 / 43.8 |
  | 128 前移 2.0 m | 22.1 / 37.8 | 43.2 / 86.0 |
  | 128 前移 2.4 m | 24.1 / 45.8 | 61.4 / 147.2 |

- 消融复现了退化，说明原因是窗口覆盖，不是存储大小：雷达只看前方约 90°，居中窗口扣掉 8 格边缘后，车前只剩约 2.8 m。前移 1.5 m 时车前约 4.3 m、车后约 1.3 m，结果最好。
- 有图模式（固定窗口）128 的 RMSE：goal 23.0、ramp 16.9、step 16.3、loop 22.6 mm。
- 16 次运行中，256 与 128 的假到达都是 2 次。冻结 N1c 在估计进入 150 mm 时就停车，终点落在线的哪一侧取决于误差方向，不作为判断依据。当前工作区固件已有 goal_pose_margin_mm=50（估计须进入 100 mm）。

相关代码位置：
- rtl/match/slf_match.v：LOG2N 默认 8；S_UC0 锁存 lfo = lf_cx − N/2；打分原点 lox = cfg_prior ? cfg_lfo_x : lfo_x；门控边缘 mg = cfg_prior ? 0 : MARGIN(8)。
- rtl/top/nav_subsystem.v：slf_match 未传 LOG2N；.lf_cx(r_MAP_CENTER_X)、.lf_cy(r_MAP_CENTER_Y)；MAP_CENTER 由固件每帧设为机器人所在格（hal_lidar_commit）。
- fw/app/nav_app.h：APP_ZHI、APP_ZLO_ODOM、APP_ZLO_PRIOR，经 hal_match_zband() 写 MATCH.ZREL。
- model/slf_match.py：SLF_SN_LOG2；build_lf(cx, cy)；score() 无图时使用 MARGIN。
- 前移窗口的模型实现与几何合同：F:/nav_integration_g2_20261023/nav3x5_N1c_stage1d_forward_windows_20261026（source_delta.patch、forward_geometry_contract.json、actual_heading_table_contract.json）。
- 合同与预算：evidence/g2_20261023/SLF128_256_RTL_FW_NVMP_coordinate_contract_20261026.json、evidence/g2_20261023/SYN40_PNR52_storage_migration_budget_20261026.json。

## 3. 验收门槛（用户已接受）
1. 不新增碰撞，不出现定位丢失；
2. 定位有效段 P95 ≤ 50 mm（对应 goal_pose_margin_mm=50 的定位预算）；
3. 至少 5 分钟多圈巡检，误差不持续增长，报告误差随时间的曲线。
到达/假到达照原判分报告，但不作为判断依据；需要比较到达时，256 与 128 都换用带 50 mm 余量的固件成对重跑。

## 4. 硬约束
- 板子只下载 SRAM（programmer_cli --run 2），绝不写 Flash；上板必须用户在场并明确同意。
- 原 4500 权重、训练、125 Hz 推理不改；任何功能的关闭或降级都要先问用户。
- 不降地图分辨率、不截结构点、不放宽 150 mm 到达判据和停稳条件。
- 不把厂商 SDK 代码拷进仓库；新工具放 D:\tools，不装 C 盘。
- 仿真批跑时不重建 nav_fw.dll、不改 model/*.py（实验改动放在冻结副本里）；Gowin 构建或 xsim/ModelSim 运行时不改 RTL；大构建前保持可用物理内存 ≥2 GiB、可提交内存 ≥4 GiB；仿真、综合、PNR 按内存串行安排。
- 在 codex/integration-g2-20261022 分支提交；不合并 main、不推送远端，除非用户要求。
- 判断改进只依据：同一冻结输入下的实际资源报告、多种子定位误差、是否布通、时序报告。不用未布通条数或 CLS 的小幅变化判断好坏，不在布不通的底座上叠加小候选。

## 5. 阶段 1：模型验证（确定前移距离 d 和 ZHI；与阶段 2、3 并行）
沿用冻结 N1c 固件 DLL、运行器、field3x5_v1 场景和判分。每个配置用独立进程和显式环境；缓存按场景版本、SLF 尺寸、窗口模式、ZREL 分开存放。
- 1a 前移距离：无图测 d = 1.0、1.25、1.5 m；有图用固定窗口（已测配置）。4 个任务 × 3 个种子 × 无图/有图，与 256 对照基准成对比较；最佳 d 另加至少 5 分钟多圈巡检。
- 1b 场外结构与高度带（继续 stage1c）：挡板外 0.5–3 m 放房间墙、桌椅、人形；对比 ZHI=1500 与 350 mm，有图、无图都测。地图工具建先验图时裁到挡板以内，使用同样的高度上限。
- 门槛不过时：在 128 内调整（更细的 d、窗口细节、ZHI），仍不过就停下来，把数据报告给用户，由用户决定。不得退回 256。

## 6. 阶段 2：SLF128 + 前移窗口的 RTL 与固件（现在开始，与阶段 1 并行）
阶段 1 只决定 d 和 ZHI 这两个运行参数，RTL 做成可配置即可，不必等阶段 1 结束。
- 从冻结的 SYN40（环形存储、50 MHz）源派生候选。新增独立的 SLF_LOG2N 参数，从顶层贯通到 nav_subsystem、u_match、u_lf，生产配置取 7；保留这个参数只是为了在 256 对照基准下做模型/RTL 逐位对比。不改 NP_MAP_LOG2N。
- 逐项核对 14 位槽地址、标签位、清图计数与完成、touch 容量、LF 边带、先验写口、调试读口；先验地址现为 16 位，要显式检查高位，不能静默截断。
- 似然场窗口中心与 MAP_CENTER 解耦：新增独立寄存器，由固件按当前位姿和航向写入"前方 d 米"的格坐标。取哪一帧的航向、怎样取整、何时锁存，要与模型试验逐拍一致。有图模式继续用固定的 LFO 窗口。
- 固件：d 和 ZHI 做成可配置（暂定 d=1.5 m、ZHI=350 mm）。NVMP 先验包加入几何/profile 标识和逐条槽地址校验，拒绝尺寸不符的旧包；地图工具同步修改。
- 验证：模型与 tb_slf 在 128、前移窗口、负坐标、回绕、标签、先验加载、清图等情况下逐位一致；既有 RTL 回归全部通过。

## 7. 阶段 3：无损存储批（与阶段 1、2 并行）
每一项先写清端口、读拍、写模式、碰撞、INIT、外部消费方的合同并验证，不能只改 RAM_STYLE 就宣称无损。
- packed_weight9（−5）、点缓冲无损位面重排（旧隔离实测 16→8）；
- 迁回 BSRAM：u_tv/u_bm 位图（+1，优先）、两个邮箱缓冲（+4）、SLF 槽列表（+1）、四路正余弦表（+4）、控制台四通道（+4）、策略 bias（+2）；列 scratch 暂不迁。

## 8. 阶段 4：一次联合综合与资源门槛
阶段 2、3 的改动通过合同后，合成一个候选，只综合一次。报告：源/物理预期 BSRAM、宽拆分、LUT/FF/ALU/RAM16/ROM16、CLS、DSP、PRIMARY/LW 全局分配、最长综合路径。
进入 PNR 的门槛：物理 BSRAM ≤ 300，且 LUT < 45825、FF < 31120（均低于 PNR52）。不满足就不跑 PNR，回到阶段 2/3 分析并报告。

## 9. 阶段 5：物理实现与时序
- 同一冻结网表，用两种不同 place_option 各布线一次（内存允许可并行；不设总时限和静默时限）。两次都布通才算稳定。
- 第一轮就做完整审查：clk50 与 rgmii_rxc 的 setup/hold、跨域约束生效情况、复位恢复/移除/脉宽、IO。
- 布通但时序不过：在这个候选上逐个加入已验证的时序候选（先加融合模长），每加一个都用两种 place_option 复核布通。若最长路径集中在控制侧且仍明显超过 20 ns，再评估控制域 25 MHz 分域（含完整跨域处理和常数换算验证）。
- 最终位流记录身份：UserCode、哈希、输入清单。

## 10. 阶段 6：上板（用户在场）
只下载 SRAM；车架空、轮子离地，执行器电源由用户控制。依次验证：雷达链路和帧率 → CH9102 导航邮箱 → P11-40 控制遥测（BMI088 六轴、编码器）→ P11-39 指令链与有效期/失联停止 → 落地低速 → 场地内无图、有图任务。任何一步失败就停在该步。

## 11. 放不下或布不通时（都要先问用户）
可选的有损项按影响从小到大：
1. 雷达帧缓冲双缓冲改单缓冲（−9，需实测是否丢帧）；
2. 高程图每格 53 位压到 36 位（−16，帧戳、标签、计数语义要重新验证）；
3. 结构点上限 4096 降到 2048（−8）。
降地图分辨率排在最后。
