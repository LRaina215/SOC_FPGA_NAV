# 扫图与先验地图链路（设计与待办）

有图模式的板上部分已经完成并通过闭环仿真：地图包 `.nvmp`（`model/prior_map.py`，版本 2，18 位槽字）、转换工具
`tools/map_tool.py`、下发协议 MAP_*（[icd.md](../2_interface/icd.md) 第 3 节）、对准 / 跟踪 / 丢失重定位、有图搜索（[algorithms.md](../4_design/algorithms.md) 第 8、10 节）。
**还缺的是"真实场地 → 地图点云"这一段**，以及用真实地图在板上跑一遍。本文给出两条路线、约定和任务分解。

## 1. 两条路线

| | A. 量测建图（推荐先做） | B. SLAM 扫图 |
|---|---|---|
| 做法 | 卷尺量墙、箱子、坡道、台阶 → 场地描述文件 → 脚本生成点云 → `map_tool.py build` | 推车录 XT-M60 数据 → 离线激光惯性 SLAM → 导出地图点云 → `map_tool.py build` |
| 精度 | 取决于量测，±1–2 cm；结构简单的 5 m 场地足够 | 取决于 SLAM 与标定；小场地特征少、视场窄（约 111° × 43°），回环弱 |
| 坐标系 | 自己定义（例如场地左下角为原点、沿长边为 x），比赛时目标点直接用场地坐标 | SLAM 起点为原点，需要再对齐到场地坐标 |
| 工作量 | 写一个约 100 行的生成脚本，半天 | 录包工具 + 点云转换 + SLAM 配置与调参，至少一周 |
| 风险 | 低；场地变动后要重量 | Flash ToF 雷达与现成 SLAM 的适配、IMU 时间同步与外参 |

建议：比赛用 A；B 作为通用场景的展示或加分项，由熟悉 Linux SLAM 的同学（可在 RK3588 或 PC 上）承担。

## 2. 约定（两条路线相同）

- 地图点云：地图系，X / Y 水平、Z 向上，单位 m，地面 z = 0；场地（含墙）≤ 12.8 m × 12.8 m（片上结构图），代价图 19.2 m 以内。
- `map_tool.py build` 支持 `.pcd`（ascii / binary）、`.ply`、`.npy`、`.xyz`；`--bounds x0,y0,x1,y1` 裁掉场地外的点。
- **能力参数要按当前车体传**：`--step 20 --slope 12`（可跨台阶 20 mm、可通行坡度 12°，[platform.md](../4_design/platform.md) 第 1 节）。
  工具缺省 `--step 100 --slope 20` 是旧大车的值，直接用会把不可跨的台阶画成可走（板上在线地形分析看到后会改判，但规划会先往那里走）。
- 初始位姿：比赛时把车放在地面标记好的起点，起点在地图系的位姿写进任务配置；`SET_POSE` 允许误差 ±0.5 m / ±10°。
- 地图版本：文件名带日期与场地版本（如 `field_20261015_v2.nvmp`），同时保存源点云、场地照片和量测记录。

## 3. 路线 A：量测建图

1. 定场地坐标系（原点、x 轴方向），在地面贴标记。
2. 量测并写场地描述文件（YAML），建议字段：
   ```yaml
   walls:   [{from: [0.0, 0.0], to: [5.0, 0.0], height: 0.5}, ...]       # 墙段，m
   boxes:   [{center: [1.2, 2.0], size: [0.40, 0.30, 0.30], yaw_deg: 0}, ...]
   ramps:   [{from: [3.0, 1.0], to: [3.6, 1.0], width: 0.6, rise: 0.084}]  # 8° 坡：0.6 m 升 8.4 cm
   steps:   [{from: [2.0, 3.0], to: [2.6, 3.0], height: 0.05}]             # 路沿 / 台阶
   ```
3. 生成点云（待写 `tools/field_to_cloud.py`）：墙面、箱子侧面每 2 cm 一个点（高 0–0.5 m），箱顶、坡面、平台、地面每 5 cm 一个点。
4. `python tools/map_tool.py build field.xyz -o field.nvmp --step 20 --slope 12`，打开 `field.png` 核对轮廓。
5. 板上验收：hardware_guide 6.8 节（对准成功、P1–P5）。

## 4. 路线 B：SLAM 扫图

1. **录包机器**：PC 或 RK3588 直连雷达（或经交换机）；录包期间让 FPGA 不连雷达（不接网线，或 `NETL_CTRL` bit 6 写 0 关掉启动客户端）。
   雷达只把 UDP 发给最近一次连它 TCP 的主机，两个主机同时连会互相抢流（[rk3588_design.md](../5_teams/rk3588_design.md) 第 3.4 节）。
2. **录什么**：原始 UDP 负载（Wireshark 过滤 `udp.dstport == 7687`，存 pcapng）——同一份数据既能离线建图，也能用
   `tools/fake_lidar.py --pcap` 回放给板子复现 FPGA 感知；另存厂家上位机 `.xbin`。
3. **IMU**：XT-M60 帧里可带内置 IMU 消息（cmdid 252；厂家 SDK 提供 IMU 帧率 `getimufps()` 与 IMU→雷达外参 `getImuExtParamters()`），
   与深度帧同一时钟，最适合激光惯性 SLAM。需要先实测这台雷达是否默认输出、频率多少。不用 BMI088 做扫图（它接在 FPGA 上，和雷达数据的时间同步更麻烦）。
4. **转点云**：按厂家 SDK 的几何（深度为径向距离、Brown-Conrady 去畸变、列号左右翻转、四角切除）把每帧深度转为雷达系点云，
   直接复用 `model/lidar_lut.py`（与板上方向表同一模型），帧尾内参每帧都有。待写 `tools/xt_to_cloud.py`。
5. **SLAM**：FAST-LIO2 一类激光惯性里程计；Flash 雷达整帧同时曝光，逐点时间取帧时间。推车 ≤ 0.3 m/s，转角处停 2 s，首尾回到同一点。
6. **导出与对齐**：导出地图点云，按场地上两三个已知点（墙角）做一次平面刚体变换对齐到场地坐标系，再 `map_tool.py build`。

## 5. 任务分解

| 编号 | 任务 | 建议负责 | 依赖 | 产出 / 通过标准 |
|---|---|---|---|---|
| M1 | `tools/field_to_cloud.py`：场地描述 → 点云，附 field5 示例 | 导航组 | 无 | 生成的地图包在仿真 field5 上对准成功 |
| M2 | 板上有图模式首次实测（路线 A） | 导航组 | 雷达安装标定（hardware_guide 6.5）、M1 | 对准成功；P1–P5 记录 |
| M3 | 录包脚本与样例数据（pcapng + 内置 IMU 核实） | RK3588 组或导航组 | 雷达 | 30 s 推车样例；IMU 消息频率实测值 |
| M4 | `tools/xt_to_cloud.py`：深度帧 → 点云序列 | 导航组 | M3 | 与 `fake_lidar` 虚拟场景点云逐点一致 |
| M5 | SLAM 建图、导出、对齐 | SLAM 负责人 | M3、M4 | 墙长、箱距与卷尺量差 < 3 cm |
| M6 | 真实 SLAM 地图包板上验收 | 导航组 | M5 | 同 M2 |
| M7 | 统一先验代价图的能力阈值（`map_tool` / `prior_map` 缺省值改为当前车体） | 导航组 | 无 | 仿真批量不变差 |
