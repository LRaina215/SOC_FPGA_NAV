# 当前整车集成与导航收敛计划（2026-10-21）

## 2. 第一批：接口冻结与回归诊断并行

### G1：把已有控制链和导航合同对齐

交付一份按源码填写的适配合同和统一工程输入清单，主要负责：导航与控制共同确认。

1. 对应车上文件、源码提交、原 4500 权重和主要配置；把 `.fs` 头日期与 README/manifest 的冲突闭合。核对芯片版本 B/C。先整理已有记录，不要求为了记录重新烧车。
2. 冻结命令入口：同片最终采用 `SAFE → 目标适配 → 控制器`；当前 UART 保留调试用途。自主导航与直接速度调试必须互斥，不能由两个来源同时覆盖目标。
3. 明确单位、符号、转换、原子更新、复位。控制 X右/Y前/Z上向导航 X前/Y左/Z上变换；由重力向量生成导航角度，实测确认抬头/左转符号。
4. 确定反馈来源、样本时刻、有效性和失效处理：现有编码器轮速不直接等于对地速度；导航采样/历史窗口与约100 Hz IMU对齐。共享时间端口或时间映射需实际实现。
5. 分别定义正常零速保持平衡、任务停止、SAFE急停、看门狗减速、控制故障及物理断电。当前串口没有命令年龄看门狗，统一入口需要补齐；不可把帧解析超时当失联保护。
6. 依照控制 `fpga/src/main.cst` 与导航 `gowin/nav_board.cst` 校正管脚。P11-1–4 为舵机、7–8 为 BMI088 I2C；撤销旧 SPI1–7 和急停8方案。`odo_stat`、腿长和 CHAS 地址扩展按需要设计，尚未实现的内容保持“拟新增”。

**完成标准：** 每个信号写清生产者、单位/轴向、频率、采样时刻、复位/失效值、消费者和保护语义；当前实现与拟新增字段分开。尚无统一工程前不标记“整车接通”。

### F1：针对 N2g 新回归补最小的时间与地图一致性工作

主要负责：导航。以 `f5_loop_s1` 为首个反例，保留 N1c 对照和原输入；联查旧任务 L1、L2/T1 中与该现场直接有关的部分。

- 对齐雷达采样、位姿历史插值、匹配修正、地图滚动和危险格生成/清除时序；判断是否混用了修正前后坐标。
- 查明足迹内 254 的证据来源及有效期；区分观测误报、地图残留、位姿坐标变化和真实危险。不要把“更接近真值的位姿修正”直接禁用。
- 按原因做最小修复，再重放已修复的路径漏洞、坡道碰撞反例和长航点；不给危险格统一放行，不为了一个样例降低碰撞口径。

**完成标准：** 反例有可复现的原因证据及修复前后对照；原先成功用例不新增失败；保持统一命令检查语义。先做目标反例，稳定后才做完整配对批量，不重复无关测试。

## 3. 第二批：资源可行性与执行模型

### G2：同片工程资源闸门

可与 F1 并行，在 G1 明确顶层边界后展开。主要负责：FPGA集成，控制与导航共同优化；对应控制专项C2。

- 用原 4500 实际网络与存储清单建立联合工程预算，先用最小共同顶层和接口桩取得模块资源分解与联合综合结果；不要沿用旧“RL 5–6块BSRAM”估算。
- 控制侧先做权重打包、逐层无损位宽、恒零观测列特化、ELU常量尾/小RAM重排；导航侧同时评估图存储物理拼接和未用缓冲。若仍放不下，按控制专项C5比较量化、小策略、外存或重新分工，不默认只缩减导航功能。
- 预估工程必须保留真实策略、ROM、控制与导航数据通路，核对综合后的模块和存储实例；未连接输出被优化删除后的资源数不能作为过闸证据。
- 统一文件清单、器件版本、时钟/复位约束，保留控制 8 ms 推理和导航实时预算。图/帧存储缩减若改变丢帧或算法行为，必须有对应验证。
- 第一版不并入视频、SFP 等可选大模块。资源不足时先报告分解和方案，再调整优先级，不能假设两套 `.fs` 轮流烧录等于整车集成。

**完成标准：** 有可重现的资源预估工程及报告，足以判断可行性和需腾出的空间；BSRAM默认保留原≤336验收门槛（器件硬上限340）。确需突破336时，单列基于实际布局结果与余量分析的偏离决定，不能自动视为通过。G3完成真实互连后再提交最终联合时序/资源报告；软核含栈余量为正且记录实用预算。单独工程 Fmax 不能代替联合报告。

### F2：S1 执行响应接入，再做有边界的 N3

主要负责：导航与控制，与控制专项C3/C4共同推进。复用原4500扫描和现有MuJoCo；测量并改善控制执行质量，而非只让导航限速适应缺陷。

- 串起规划命令、SAFE限幅/斜坡、控制采样保持、执行延迟和反馈；用当前已有模拟数据设置注明来源的不确定范围。
- 按当前 `MOTOR_CLOSED_LOOP_AT_ZERO=0` 建模：单轮零目标会禁PWM、清PID，不能假设已有主动闭环制动；这与车体零命令时策略仍可输出纠偏轮速是不同层次。
- 前后速度响应分开，纯转向与边走边转分开；包含停车漂移和制动。模拟增益不能直接作为实车补偿系数。
- N3 在这条执行链上验证响应与停止扫掠；先保守限定倒车和旋转包络，不能因串口接受负速度就认定可靠倒车已验收。

**完成标准：** 模型参数有来源、范围和适用工况；N2＋N3＋相关路径修复按同一执行链联合比较；不把模拟结果标成车辆实测。与 F1 达到可接受状态后再做完整配对批量及 H1 迁移检查。

## 4. 第三批：统一顶层和分级上车

### G3：实现适配器和统一顶层

依赖 G1、G2。主要负责：FPGA集成；导航/控制分别审阅边界。控制专项C1的启动重力、命令有效期、融合完整性属于候选上车前的必要整改，不因资源过闸而省略。

交付命令与反馈适配器、IMU/时间适配、命令所有权和失联保护、统一顶层与构建配置、对应 ICD/引脚更新。保留既有控制器内部推理和执行链，不让软核直接驱动轮电机或舵机。先用已接受导航基线；N2g只有通过F1/F2对应联合验收后才进入部署候选。

**完成标准：** 必要接口测试覆盖正负速度、原子更新、复位、无效样本、超时和急停分级；原导航/控制回归按影响通过；真实互连后的最终联合时序与资源报告过闸门。记录命令/反馈节拍和板上最坏循环时间，不能用主机测试耗时替代50 MHz软核预算。

### G4：确认整车基本闭环

依赖 G3。主要负责：控制与导航在现场执行。

1. 在已知板上控制基线上保存日志；核对方向、换轴、里程计计数、控制入口和故障状态。
2. 支架/台架验证复位、断开命令、暂停导航、非法帧和显式停止；分别记录零速保持、故障断驱动及物理断电的结果。
3. 低速落地测正/负速度、左右转向、曲线、停车、命令切换；用独立距离/角度基准测跟踪偏差、延迟、制动距离和漂移。先记录能力，不预设必须达到接口最大值。
4. 联合雷达运行确认IMU/编码器无丢样、反馈时间一致、控制节拍未受导航负载破坏。

**完成标准：** 每个动作均有命令、实测响应、时间和状态记录；自主模式控制权唯一；失联行为符合合同；由结果生成首版可用速度/加速度/停止包络。失败时修复对应项，不扩展到全场自主任务。

### G5：装车标定和导航验收

依赖 G4 和本次部署候选的导航验收。主要负责：导航，控制配合。

- 实测正常腿姿下足迹、轮距/滚动半径、雷达光心高度与安装角；区分模型高度命令、实物腿高与雷达外参。更新参数源后再生成代码，不在本轮文档审阅中擅自改数值。
- 先平地低速定点/绕障/多航点/停车，再有图定位和目标跟踪；对同一场景留存成功和失败记录。
- 坡、台阶、负障碍及低附着等能力逐项验证；20mm/12°继续标为仿真假设，直到对应实测通过。
- 本轮导航基线在新口径尚有失败用例，按影响已选任务和新增退化排序处理，不能只报告汇总成功率。

**完成标准：** 选定任务的到达/停稳/碰撞/定位失效口径提前明确；对已声明速度、地形与腿姿范围，有可复核实车记录。未覆盖范围保留限制。满足这一阶段才可说“整车导航闭环基本完成”。

## 6. 执行和验收纪律

### 本次执行入口更新

按用户最新授权，控制C1–C5暂缓，仅将固定6443f56快照作为导航输入边界；当前执行导航F1和F2/J1–J4，不以控制整改为前置。仿真路线按[选型决定](simulation_architecture_decision_20261021.md)：MuJoCo动力学主验证、独立快速回归、后续板在环/实测校准。现有训练等效开链作合同对照，真实闭链、接触与部署执行链按证据完善，不把旧代码当模型上限。

当前F1已增加只读逐帧地图、历史范围与匹配修正诊断，正在重放N2g的83–87s现场；J1正在建立隔离依赖及Windows路径适配，控制快照保持只读。J2/J3须接真实导航C、SAFE、策略与虚拟传感器，不能以一阶响应模型替代完成；新后端上的N1c/候选必须重新配对。实际结果持续追加到[导航结果](../4_design/nav_optimization_results.md)。

- 原分工建议为G1＋控制C1＋导航F1；当前按上方最新授权暂缓控制C1–C5，先执行导航F1及F2/J1–J4，控制资料仅作固定输入边界。
- 保留 N1c 冻结结果和 N2g 失败现场；修改工作区前识别既有未提交文件。待部署版本必须明确源码、权重、参数、工具、构建报告和位流文件名/生成时间，不要求SHA校验。
- 每项记录“源码已实现／离线通过／迁移构建通过／用户确认上车／实车验收通过”之一或多项，禁止混写成一个“已完成”。
- 文档改动只检查内容一致性、链接和差异格式；代码变更做与风险相称的验证。新反例稳定前不反复跑完整批量；全部必要检查通过后不无故扩大测试。
- 若资源、板上时序、命令失联或新回归任一关未通过，处理对应原因，不继续堆叠整车功能。用户已调通的控制成果保留，不因导航问题重做底层控制。

接口依据：[ICD](../2_interface/icd.md)、[引脚表](../2_interface/pinout.md)。系统关系与联合资源说明见 [集成说明](integration_plan.md)；实验细节继续记在 [导航优化结果](../4_design/nav_optimization_results.md)。

### F1/J1进度补记

F1冻结G现场已确认同帧旧位姿融合/新位姿足迹检查不一致，正用复用双缓冲的两阶段融合修复。主机、Python定例、RTL端到端专项与128KiB RV构建已通过，代码37944B/BSS84452B/8KiB栈后余484B；长航点候选复验进行中，未接受。L1历史有效性子项通过，最终XY32×20ms、姿态64×10ms。J1已在隔离MuJoCo3.3.7环境完成固定原4500的五项6s基础运行，J2–J4未验收；控制C1–C5继续暂缓。具体证据和失效探测记录见导航优化结果。

前批检查点：F1＋高侧＋精度候选长航点94.8s成功，但全量在26/50后因gap种子5退化超时停止。完整20项RTL与导航独立布线50.013MHz/0违例通过，不等于整车资源/板级最坏时序。原4500/逐次时序5对基础任务通过，仍为float32与训练等效执行器。
