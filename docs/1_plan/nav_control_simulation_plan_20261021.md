# 导航与固定控制策略联合仿真交付（2026-10-21）

本文件把整车总计划F2/S1中的仿真工作具体化。用户当前要求暂停控制改造、继续完成导航；**复用原4500策略搭建导航联合仿真属于导航验证，不要求改控制模型、训练或控制RTL。**

已有导航快速闭环、原4500模型、URDF/STL、MuJoCo运行代码和接口资料，足够开展联合仿真。真实闭链文件、轮胎接触与执行器实测参数尚不齐全，因此不能称为已完成实车动力学复现，但这些缺项不再作为启动联合仿真的前置条件。

原导航规划V1侧重几何测试台，并将完整动力学放到后续条件；取得控制仓库后，该安排应补充为本文件的明确交付。保留快速闭环，同时增加真实策略动力学后端，不把现有简化响应模型的通过当作联合仿真通过。

## 1. 三种验证各自承担什么

| 层次 | 现状 | 本轮用途 |
|---|---|---|
| 导航快速闭环 | 已有真实导航C/DLL＋虚拟雷达/地图＋简化响应车模 | 复现N2g，定位时间/地图/路径问题，做便宜的确定性回归 |
| 固定原4500＋MuJoCo | 控制仓库已有单车运行和七项固定命令评估；尚未连接导航链 | 在已有平台上接导航任务、SAFE、虚拟传感器和反馈，验证真实策略下的到达/停车/恢复/碰撞与失稳 |
| 接近部署的执行链 | 数字参数已知，实际电机/舵机/轮地响应未完全辨识 | 加入10ms轮速反馈/PID、20ms舵机锁存、约100HzIMU、延迟/限幅/过零行为；未知物理参数保留范围，未来由实测校准 |

第二层先复用仓库的训练等效执行器，不虚称FPGA轮速PID已经被复现；第三层再以可追溯数字模型/参考实现接近部署。原4500权重和策略观测/动作合同保持固定，控制改进专项C1–C5暂不执行。

## 2. 联合链路与输入边界

目标链路：导航任务/规划C → SAFE语义 → 速度/坐标适配 → 原4500推理 → 腿轮执行器 → MuJoCo物理运动 → 虚拟编码器/IMU/雷达 → 导航反馈、地图与定位。

- 复用导航 `sim/closed_loop/` 的任务、场景、判分和日志；以可选择的物理后端接入，不整套替换快速测试工具。
- 复用控制 `sim2sim/model4500_mujoco/runtime.py`、`robot.xml`、原4500及对应配置；先核对模型路径、依赖版本和可重复的无界面启动。控制仓库记录的MuJoCo版本与本地旧环境不同，兼容性应实际核对，不能直接沿用旧环境版本承诺可运行。
- 保持8ms策略周期、五帧历史、六动作、高度IK和原轴向语义。导航X前/Y左/Z上与控制X右/Y前/Z上的变换只在边界完成。
- 物理真值可用于生成传感器和独立评分；不直接灌入导航位姿、已知地图危险标签或理想对地速度作为普通反馈。
- 初版固定高度且默认命令偏置为0；不得默认调用带−0.01m/s偏置的启动脚本。任何偏置候选单独命名、同时比较。
- 按仿真时间调度导航、SAFE、策略、编码器、IMU、舵机和雷达；明确采样/发布/消费时刻、保持与时延，避免宿主机耗时决定物理节拍。
- 记录请求动作和实际锁存/采用动作，按训练合同维护上一动作历史；不因舵机50Hz就擅自改成另一个历史定义。

## 3. 实施顺序和具体交付

### J1：先把原有单车基线在本机跑通

交付可重复的无界面命令、环境/模型清单，以及短时停车、前进、后退、左右转向结果。优先复用原仓库合同验证和固定命令场景，确认路径、坐标、动作与历史顺序，无需重训或重新生成全部机械模型。

已有七项20秒结果只是参考，不冒充本机本轮运行；复跑范围以验证移植和接口为限，不盲目扩大批量。发生失稳保留失败时刻，不允许自动重置后继续当同一成功轨迹。

### J2：接通导航和传感器闭环

交付可选择的MuJoCo后端、导航/控制适配与日志，先跑平地短目标、停车、转向和单个障碍绕行。导航运行真实C实现；编码器/IMU来自物理传感器模型，雷达保持已有协议/点云/外参和帧时序语义。若首版传感器有简化，逐项写明，不能称为完整部署链。

通过条件是链路确实闭合、无真值泄漏、时间与轴向一致、失败可复现；不是要求原策略在所有任务都成功。机器人倾倒/机身触地/实际障碍接触应作为独立失败证据保留，不能只看导航足迹检查。合法轮地接触不计成碰撞。

### J3：补部署执行链与有界误差

在J2稳定后加入已知的多速率保持、轮速量化、限幅/斜坡、零轮目标关PWM/清PID及必要数字执行环；采用参考模型时核对其与RTL语义。以明确参数模拟执行器惯性、死区、力矩/电压限制和延迟，未知项用有来源的范围，避免虚构单一真实参数。

不直接对每条长轨迹运行50MHz全系统RTL逐周期仿真；数字模块用相应定点/RTL专项核对，系统任务采用经核对的执行模型。第三层通过只表示在声明模型与参数范围内通过。

### J4：配对验收和导航回灌

先选停车/接近终点、倒车恢复、原地旋转扫掠、狭窄绕障和多航点代表场景，再按风险增加坡面等用例。接入真实策略意味着执行模型改变，须在同一新后端重新比较接受基线N1c与候选；不能拿快速车模的28/50与另一物理后端的数字直接当改进幅度。

交付命令、轮目标/反馈、姿态、真实/估计轨迹、距离/停止过程、地图/定位时序、碰撞/失稳和任务进展记录。将有证据的响应界限回灌S1/N3；模拟能力不写为实车能力。

## 4. 与主窗口当前任务衔接

N2g的F1时间/地图一致性诊断继续使用快速闭环，不必先等联合平台。J1可先做依赖与复用检查；随后J2/J3作为F2的具体交付推进，再做J4。接口和物理后端完成前，不能只以S1一阶响应/延迟模型完成就宣布联合仿真完成。

本文件新增的是执行任务，当前J1基础运行及J2基础链路已通过，J3/J4仍进行中；不把这些子项等同于完整联合验收。主窗口应将J1–J4状态回填总计划和导航优化结果；控制侧暂不改造，实车测量缺项继续单列。
