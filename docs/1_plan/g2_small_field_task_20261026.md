# 任务：3×5 m 封闭场地的单芯片整车工程（导航 + 原 4500 控制）收敛

## 0. 目标与完成标准
在 GW5AT-138（按器件 C 构建，实物 B/C 仍待核）上得到一个同时包含导航和原 4500 控制的位流，要求：
- 布线完成、未布通为 0，且用两种不同 place_option 都能布通；
- clk50 50 MHz、rgmii_rxc 100 MHz 的 setup/hold 全部为 0，52 条跨域约束全部生效，复位恢复/移除/脉宽检查为正；
- BSRAM ≤ 336/340；
- 功能完整：雷达链路、SLF 定位（无图和有图）、原 4500 推理（权重、训练、125 Hz 不变）、红外硬急停、双串口（CH9102 导航邮箱 + P11-39/40 控制串口）、指令有效期与失联停止。
全部满足后才准备上板。

## 1. 已确定的事实（不再重新论证）
场地与车：
- 场地 3×5 m（长轴 5 m），四周用约 0.5 m 高的哑光纸板挡板围合，上方开口；车只在场内运行。
- 出发位置固定，出发时车头与场地长边或短边平行（摆放误差约 ±5 cm、±3°）。具体坐标待用户提供，暂用 field3x5_v1 中 goal 任务的起点 (0.45, −0.95, 0°)，标记为暂定。
- 场内平台/坡顶最高高度待用户提供，暂按 84 mm。
- 雷达光心离地 155 mm、下俯 10°，M60 视场上沿约 +9.3°：车离 0.5 m 挡板超过约 2.1 m 时，能越过挡板看到场外。
- 只有一块板，必须单芯片；本工程不含 SFP、DDR。RK3588 通过 CH9102（导航邮箱）和 P11-39/40（控制串口）连接。

布线历史（约 50 轮）：
- 只有两个网表布通过：10-22 基线（PNR27/31 复现），以及基线 + 融合模长（PNR32/35：332 块，clk50 实测 33.197 MHz，3781 个 setup 违例，hold 为 0）。
- CLS 和未布通条数都不能预测结果：PNR49 与 PNR50 网表几乎相同，未布通分别为 427 和 1659；PNR52（环形存储 + 50 MHz，CLS 74.3%，LUT 45825，FF 31120）仍有 1026 条未布通。增量布线（PNR48）无效。
- 结论：围绕单个小候选反复整网布线等于抽签，停止。下一次 PNR 必须建立在阶段 3 的大幅资源改动上。

存储：
- 联合需求约 393 块，大于 340；约 26780 个逻辑单元是被挤进 LUT 的分布式 RAM/ROM。
- PNR35 网表中仍为分布式的大项：u_tv/u_bm 16384×1 位图 6144、u_match/u_ex/u_rb 1650、u_mbx 的 u_injb 与 u_txs 各 1536、u_match 的 slist/cand/res 各 1536、u_soc/g_con 4×768、正余弦表 4×737、策略 bias 702。u_tv 行缓存和 ELU 已在 BSRAM，不得重复计算收益。
- 预算（以 SYN40/PNR52 为基数，已含环形存储，均须实际综合确认）：
  - 保留 SLF256：无损分批 332→319（packed_weight9 −5、点缓冲位面 −8）→329（位图、邮箱、槽列表、正余弦）→335（控制台、bias）；列 scratch 不迁。
  - SLF128：条件预算 332−51−5+18≈294，再加点缓冲位面约 286。

SLF 128/256 试点（field3x5_v1，冻结 N1c，seed1，16/16 已完成）：
- 无图（窗口随车）：定位有效段 RMSE（128 减 256）为 +41.8、+19.3、+6.7、+0.5 mm，一致变差。
- 有图（窗口固定、罩住全场）：+4.6、+7.7、+6.9、−19.4 mm，无一致退化。
- 待证的解释：雷达只看前方，打分只用当前帧的点；128 窗口以车为中心，再扣掉 8 格门控边缘，前方只剩约 2.8 m 可用。
- 终点误差 112–163 mm，贴着 150 mm 门槛，到达/假到达的翻转主要是门槛噪声，以定位误差为准。

固定窗口的几何余量：128 窗口扣掉边缘后可用 5.6 m，场地长 5.0 m，每边约余 0.3 m；摆放误差 ±5 cm、±3° 时仍余约 0.17 m。出发朝向不与场地边平行时（例如 45°）放不下。

相关代码位置：
- rtl/match/slf_match.v：参数 LOG2N 默认 8；打分窗口原点 lox = cfg_prior ? cfg_lfo_x : lfo_x，其中 lfo_x 在 S_UC0 取 lf_cx − N/2；门控边缘 mg = cfg_prior ? 0 : MARGIN(8)。
- rtl/top/nav_subsystem.v：slf_match 实例化时未传 LOG2N；.lf_cx(r_MAP_CENTER_X)、.lf_cy(r_MAP_CENTER_Y)。MAP_CENTER 由固件每帧设为机器人所在格（hal_lidar_commit）。
- fw/app/nav_app.h：APP_ZHI 1500、APP_ZLO_ODOM 60、APP_ZLO_PRIOR −300，经 hal_match_zband() 写入 MATCH.ZREL。
- model/slf_match.py：SLF_SN_LOG2 环境变量；build_lf(cx, cy)；无图时 score() 使用 MARGIN。
- 现有方案与证据：docs/4_design/g2_small_field_storage_plan_20261026.md、evidence/g2_20261023/SYN40_PNR52_storage_migration_budget_20261026.json、evidence/g2_20261023/SLF128_256_RTL_FW_NVMP_coordinate_contract_20261026.json；试点目录 F:/nav_integration_g2_20261023/nav3x5_N1c_SLF128_256_stage1_20261026。

## 2. 硬约束
- 板子只下载 SRAM（programmer_cli --run 2），绝不写 Flash；上板必须用户在场并明确同意。
- 原 4500 权重、训练、125 Hz 推理合同不改；红外硬急停保留；OLED 只能作为单独开关评估，不和其他改动混在同一次里。
- 不降地图分辨率、不截结构点、不放宽 150 mm 到达判据和停稳条件来换取通过。
- 不把厂商 SDK 代码拷进仓库；新工具不装 C 盘，放 D:\tools。
- 仿真批跑时不重建 nav_fw.dll、不改 model/*.py（实验改动放在冻结副本里）；Gowin 构建或 xsim/ModelSim 运行时不改 RTL；大构建前保持可用物理内存 ≥2 GiB、可提交内存 ≥4 GiB。
- 在当前分支 codex/integration-g2-20261022 上提交；不合并 main、不推送远端，除非用户另行要求。
- 判断改进只依据：同一冻结输入下的实际资源报告、多种子定位误差、是否布通、时序报告。不得用未布通条数或 CLS 的小幅变化判断好坏。不在布不通的底座上叠加小的时序或资源候选。

## 3. 阶段 1：模型级决策试验（不改 RTL）
沿用试点的冻结 N1c 固件 DLL、运行器、field3x5_v1 场景和判分。每个配置用独立进程和显式环境变量；缓存按场景版本、SLF 尺寸、窗口模式、ZREL 设置分开存放。

1a 快速判别（先做，只跑无图 goal 和 turn_loop 的 seed1）：
- 消融：SLF256 存储，但建似然场和打分都只用以车为中心的 128×128 范围（门控边缘仍为 8 格）。若复现 128 的退化，说明原因是窗口覆盖。
- 无图 128 + 固定窗口：窗口原点由固定出发位姿和场地尺寸换算（场地中心在里程计系中的格坐标减 N/2），建似然场的中心同步改为这个固定中心；继续并图，不进入有图语义（不跳过 UPDATE、不改门控边缘）。

1b 若 1a 中固定窗口接近 256：扩到 4 个任务 × 3 个种子 × 无图/有图 × 256/128 固定窗口。

1c 场外结构与高度带：新建一个场景版本，在挡板外 0.5–3 m 处放房间墙和桌椅（可加静态人形）。对比 ZHI=1500（默认）与 ZHI=350 mm（500 减平台 84，再减约 66 余量），256 和 128 固定窗口都测，有图、无图都测。同时让地图工具建先验图时裁到挡板以内，并使用同样的高度上限。

1d 只有固定窗口失败时才做：窗口沿航向前移 1.5/2.0/2.4 m，作为备选。

验收（相对同种子的 256）：
- 不新增碰撞和假到达；
- 定位有效段的 RMSE、P95、终点误差增量都 ≤10 mm；
- 有图对准成功次数按 k/n 报告，且不低于 256。

决策：
- A 路线：128 固定窗口通过，进入阶段 4（2A）。
- B 路线：不通过，保留 256，跳过 2A，只做阶段 5（2B），并在综合前向用户报告预算余量偏小的风险。

## 4. 阶段 2A：SLF128 + 无图固定窗口的硬件与固件（仅 A 路线）
- 从冻结的 SYN40（环形存储、50 MHz）源派生候选；SLF256 保留为可选配置。
- 新增独立的 SLF_LOG2N 参数，从顶层贯通到 nav_subsystem、u_match、u_lf；不得改 NP_MAP_LOG2N（高程图和代价图保持 128×128）。逐项核对：14 位槽地址、标签位、清图计数与完成信号、touch 容量、LF 边带、先验写口和调试读口。nav_subsystem 的先验地址现在是 16 位，要显式检查高位，不能静默截断。
- MATCH.CTRL 新增一个控制位（例如 FIXWIN）：置位且 PRIOR=0 时，似然场建图中心取 LFO + N/2（不再取 MAP_CENTER），打分窗口原点因此等于 LFO；并图、建图、门控边缘不变；高程图仍随车。
- 固件：按固定出发位姿和场地尺寸计算 LFO 并写入，同时置 FIXWIN。出发朝向相对场地边必须是 0°/90°/180°/270°（允许 ±3°），否则拒绝并报错。APP_ZHI 改为可配置，本场地取 350 mm，平台高度确定后重算。
- NVMP 先验包：加入几何/profile 标识和逐条槽地址校验，128 配置拒绝尺寸不符的旧包；地图工具同步修改。
- 验证：模型与 tb_slf 在 128、固定窗口、负坐标、回绕、标签、先验加载、清图等情况下逐位一致；既有 RTL 回归全部通过。

## 5. 阶段 2B：无损存储批（两条路线都做；可与阶段 1 并行做合同验证，综合留到阶段 6）
每一项先写清端口、读拍、写模式、碰撞、INIT、外部消费方的合同并验证。不能只改 RAM_STYLE 就宣称无损。
- packed_weight9（旧实测 −5）；点缓冲无损位面重排（旧隔离实测 16→8）。
- 迁回 BSRAM：u_tv/u_bm 位图（+1，约省 6144 逻辑单元，优先做）、两个邮箱缓冲（+4）、SLF 槽列表（+1）、四路正余弦表（+4）、控制台四个通道（+4）、策略 bias（+2）；列 scratch 暂不迁。
- B 路线按预算只做到 ≤335：先到 319，再到 329，再到 335；每步实测不过就停。

## 6. 阶段 3：一次联合综合与资源门槛
把通过合同的改动合成一个候选，只综合一次。报告：源/物理预期 BSRAM、宽拆分、LUT/FF/ALU/RAM16/ROM16、CLS、DSP、PRIMARY/LW 全局分配、最长综合路径。
进入 PNR 的门槛：
- A 路线：物理预期 BSRAM ≤300，且 LUT < 45825、FF < 31120（均低于 PNR52）；
- B 路线：BSRAM ≤336 且逻辑低于 PNR52，进入 PNR 前先向用户汇报。
不满足就不跑 PNR，回到阶段 4/5 分析。

## 7. 阶段 4：物理实现与时序
- 同一冻结网表，用两种不同 place_option 各布线一次（内存允许时可并行；不设总时限和静默时限）。两次都布通才算稳定。
- 第一轮就做完整审查：clk50 与 rgmii_rxc 的 setup/hold、52 条跨域约束是否生效、复位恢复/移除/脉宽、IO。
- 布通但时序不过：在这个候选上逐个加入已验证的时序候选（先加融合模长），每加一个都用两种 place_option 复核布通。若最长路径集中在控制侧且仍明显超过 20 ns，再评估控制域 25 MHz 分域（含完整的跨域处理和常数换算验证）。
- 全部门槛通过后才准备上板位流，记录位流身份（UserCode、哈希、输入清单）。

## 8. 阶段 5：上板（用户在场）
只下载 SRAM；车架空、轮子离地，执行器电源由用户控制。依次验证：雷达链路和帧率 → CH9102 导航邮箱 → P11-40 控制遥测（含 BMI088 六轴、编码器）→ P11-39 指令链及有效期/失联停止 → 落地低速 → 场地内无图、有图任务。任何一步失败就停在该步。

## 9. 失败分支（都要先问用户）
若 B 路线综合后仍放不下或布不通，可选的有损项按影响从小到大：
1. 雷达帧缓冲从双缓冲改单缓冲（−9，需实测是否丢帧）；
2. 高程图每格从 53 位压到 36 位（−16，帧戳、标签、计数的语义要重新验证）；
3. 结构点上限从 4096 降到 2048（−8）。
降分辨率排在最后。
