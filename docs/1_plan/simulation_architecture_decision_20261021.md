# 仿真与导航方案选型决定（2026-10-21）

用户明确授权按项目目标自主选择平台和整体方案，没有指定仿真品牌。按其最后一句“选择你认为最优的”理解本轮意图。现有工具、代码和先前规划的“最小修改”只是可参考资产，不是不可变约束；若证据支持更换实现或算法，应允许调整。当前任务范围仍是导航，固定控制器用于联合验证，控制专项改造暂缓。

## 1. 选择标准与决定

优先顺序是：导航C/RTL接口语义与时序正确；轮腿动力学和实际动作链可检查；传感器与任务失败能复现；支持无界面批量；能在当前设备持续运行并迁移到硬件验证。画面逼真度和已有代码多少均不是首要标准。

**当前决定：MuJoCo承担动力学主验证，独立快速闭环承担导航反例和大批回归，实机日志/板在环承担最终校准与迁移验证。** 三者共用场景/任务定义、时间与日志合同、判分口径；不要求一个引擎包办所有验证。

这是根据文档能力、当前任务和本机条件作出的工程选择，尚未对全部候选运行同一基准，不能宣称跨所有任务的绝对最优。选定后通过J1/J2的真实运行验证适用性；若出现不可解决的闭链、接触或性能问题，依据测量重新选择。

## 2. 已比较的路线

| 路线 | 已查明能力/条件 | 对本项目的判断 |
|---|---|---|
| MuJoCo | 关节/接触动力学、执行器、等式闭合约束、射线查询和程序接口；可直接与现有导航C库和固定策略相连 | 适合作为轮腿平衡、执行响应、传感器时序和导航任务的主动力学平台。XT-M60误差和协议需自行建模，不因使用物理引擎自动获得真实雷达 |
| Isaac Sim＋Isaac Lab | RTX传感器支持材质相关反射/透射；面向机器人学习和多传感器场景。当前Isaac Sim官方最低配置为32GB RAM、16GB显存 | 若后续视觉、复杂材质传感器或大规模GPU训练成为主要目标，重新评估。当前任务及本机资源不足以证明其总体收益高于MuJoCo，先不作为主链依赖 |
| Gazebo（DART等物理插件） | 支持运行时选择物理引擎和系统集成 | 若后续ROS2系统集成成为主要工作，可重新考虑；本项目直接运行FPGA导航C，不需要为仿真引入另一套导航软件栈 |
| Webots等集成仿真器 | 具有机器人场景/传感器工具 | 作为备选；当前没有证据证明迁移能改善本项目的闭链、控制链对齐和FPGA验证，暂不额外维护一个主平台 |
| 现有快速导航模型 | 已有确定性场景、真实C/DLL和独立判分，计算量较小；不含真实RL和完整接触动力学 | 保留为缺陷定位与便宜回归层。不能用它替代真实策略物理闭环，亦不因新增MuJoCo而丢弃已有反例 |

本机只读盘点：Windows11，i7-12700H（14核/20线程），约16GB物理内存；`nvidia-smi`确认RTX3060 Laptop、6144MiB显存、驱动581.32。WMI的AdapterRAM可能不准确，显存采用nvidia-smi结果。现有独立环境装有MuJoCo3.2.7/NumPy1.23.5，未装Torch；这只是当前环境，**不是强制版本选择**。应在隔离环境选择经原4500合同/模型运行验证的稳定依赖组合并锁定，不盲目沿用旧版本或自动追最新开发分支。

## 3. 模型和架构同样按目标改进

1. **保留训练等效模型作对照，建立物理模型的校验目标。** 已有开链模型适合验证原策略合同及跨引擎差异；工程动力学验收目标包括真实五连杆闭合关系、轮胎/接触、质量惯量、执行器响应和传感器安装。恢复或按有依据的几何重建闭链，不把“仓库已有开链”当作最终模型必须如此的理由。缺参数先列来源/范围，不杜撰成实测值。
2. **建立共同场景定义。** 地形、静/动态障碍、任务和事件脚本可被快模型及动力学引擎加载；物理碰撞、雷达命中和独立真值评分的几何应能核对，避免三套场景悄悄不同。
3. **传感器与部署接口优先。** 按XT-M60方向表、安装外参、帧时序和已知协议生成深度/点云；加入明确的无效值、遮挡、量化、噪声和时延。射线命中距离不等同于真实回波；反射/透射等需求若成为决定性问题，再选择适合的RTX传感器后端。
4. **保留替换算法的自由。** N2g反例优先定位；若局部修复不能保持任务进展或实时预算，可比较候选搜索、地图更新或规划结构的替代实现，不为维持旧代码强行补丁。替换须与冻结基线同输入、同评分比较，不能通过修改验收口径掩盖退化。
5. **软件与硬件形成连续证据。** 原4500FP32合同、必要定点执行模型、导航真实C和相关RTL分别核对；任务级不默认用50MHz逐周期RTL跑全部轨迹。后续以板在环/实机测得的时序和反馈检验仿真假设。

## 4. 实施及重新选型条件

[联合仿真计划J1–J4](nav_control_simulation_plan_20261021.md)按本决定执行：先核对并跑通主平台合同；接真实导航与虚拟传感器；加入部署执行链；进行N1c与候选配对。快速F1诊断继续推进，不等待整个平台完成。

J1/J2必须实际报告依赖版本、模型差异、相同输入复现、动力学稳定情况、射线与系统吞吐/内存、任务日志。场景雷达目标为现有约9600方向/帧、10Hz；实际吞吐和批次耗时需测量，不预先保证达到实时。离线仿真按仿真时间调度，不以宿主机变慢改变控制周期。

若MuJoCo闭链/接触与实测不符，先区分参数、几何、数值设置和引擎机制；若确认是机制限制再换后端。若新增视觉/反射材质任务、拥有适合GPU工作站或进入大规模重训，可比较Isaac Sim/Lab及其他加速后端。任何平台都不能靠引擎品牌替代机械/执行器标定，也不能把模拟通过写成整车实测通过。

主窗口应把这一选择及J1–J4进度并入总计划；若实施阶段有更优证据，可调整并说明理由。现阶段该文是已作出的路线决定，联合环境和真实性能尚需实际交付。
