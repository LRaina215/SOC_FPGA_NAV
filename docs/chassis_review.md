## 0. 结论：最重要的 10 条

1. **同一块 FPGA、同一个比特流**。底盘 RTL 必须作为模块进入本仓库的整车工程一起构建；单独生成的比特流下载后会把导航整个覆盖。
   BSRAM 只剩 16 块（324 / 340），推理核按 ≤ 6 块设计；时钟用导航的 50 MHz。（第 3.1 节）
2. **转向必须进入第一版可部署的控制器**。导航每一步都在发角速度（最高 1.2 rad/s），还有纯原地转向；路线文档把转向放在第 7 阶段，
   这样导航无法上车。速度跟踪阶段就同时训练 vx 与 wz，或在策略外加经典偏航角速度环。（第 3.2 节）
3. **实时控制全部放 RTL**。软核在雷达流下主循环最长约 38 ms，而且忙于导航；平衡、状态估计、推理、执行器输出都不能依赖软核。（第 3.3 节）
4. **按导航实际会发的指令训练**：范围、组合、原地转、10 Hz 阶梯 + 斜坡、急停阶跃到 0、看门狗减速到 0；`SAFE` 限幅设在训练范围以内。（第 3.4 节）
5. **IMU088 接 P11 第 1 / 2 针（FPGA C18 / C19），导航与底盘共用一颗**，FPGA 内部扇出；协议、频率、量程、轴向与零位双方统一。（第 3.5 节）
6. **里程计回传按导航口径**：对地速度（扣掉机身俯仰角速度）、角速度用陀螺、固定 50–100 Hz、静止时给精确 0。（第 3.6 节）
7. **引脚按 pinout.md 分区**，P9 跳线保证 3.3 V；使能类信号高有效 + 外部下拉，下载比特流和复位期间电机不能动。（第 3.7 节）
8. **腿部姿态**：导航期间固定在一档"导航姿态"；切换只在停车时进行并上报腿长；导航模式下禁止弹跳。（第 3.8 节）
9. **定义底盘状态机与故障降级**，物理急停直接断电机电源；`ch_stop` 是"速度归零、保持平衡"。（第 3.9 节）
10. **新增底盘状态上报与调试通道**：状态字、腿长回传、寄存器块 CHAS（`0xD800` 起）、板在环独立串口、统一时间基准。（第 3.10 节、第 4 节）

## 3. 需要调整或特别注意的关键点

每一条按"路线文档现状 → 问题 → 要求 → 验收"写。验收中的阶段号见第 5 节与 [roadmap.md](roadmap.md) 第 8 节（D2.1–D2.7）。

### 3.1 部署形态：同一块 FPGA、同一个工程

- **现状**：§13 计划"Gowin EDA 综合 → 配置文件 → 下载 / 烧录"，§13.3 第一版把权重编进配置文件"烧入 Flash"，§14 只考虑 RL 自己的工程。
- **问题**：
  - 整片 FPGA 只有一个配置。底盘单独的比特流（无论 SRAM 还是 Flash）都会覆盖导航，反之亦然。
  - 资源已经很紧：BSRAM 布线后 324 / 340，逻辑 18%，DSP 23%；50 MHz 时序余量只有约 0.1 MHz（[integration_plan.md](integration_plan.md) 第 4 节）。
  - 高云授权文件绑定导航组这台电脑的网卡；工作区里另有 V1.9.11.03 Education 版，能否支持 GW5AT-138 需要底盘组自己确认。
- **要求**：
  1. 底盘 RTL 以模块形式进入本仓库 `rtl/chassis/`（建议顶层模块名 `chassis_top`），按 [dev_guide.md](dev_guide.md) 第 3 节接入：
     登记 `sim/tests.py`、写 testbench、算法模块配 Python 定点参考模型逐位比较。整车顶层 `car_top` 由导航组建立，底盘组提供模块与约束需求。
  2. 资源预算（第一版）：BSRAM ≤ 6 块、DSP ≤ 16 个、逻辑 ≤ 15000 LUT。超出要在接入前提出，导航组先做存储压缩腾空间。
  3. 时钟与复位：用导航的 `clk`（板级 50 MHz）与同步高有效 `rst`。PWM、I2C / SSI、舵机脉冲都用计数器分频，不另开时钟；对外端口全部打寄存器。
  4. 权重第一版作为 BSRAM / ROM 初值编进比特流（与导航固件编进软核 RAM 的做法相同，`syn.py` 负责生成初值文件）。"权重单独存 Flash"暂不做。
  5. 调试阶段只下载到 SRAM（`programmer_cli --run 2`），Flash 只在比赛前由导航组统一固化一次。
  6. 构建统一在有授权的电脑上用 `python gowin/syn/syn.py --board …` 完成；仿真用 Vivado xsim（`sim/run.py`），不需要另装 iverilog / Verilator。
- **验收**（里程碑 I2）：整车比特流（导航 + 底盘模块）布线后 BSRAM ≤ 336、0 违例；导航 15 项回归与闭环批量不退化。

### 3.2 转向（wz）必须进入第一版

- **现状**：§1、§3 第一版只做平衡 + 前进 / 后退 / 停车，转向在第 7 阶段；§9 速度阶段还对"非预期转向"做惩罚（"第一版先直行"）。
- **问题**：导航的局部规划每 100 ms 输出一组 (vx, wz)，wz 范围 ±1.2 rad/s。以下情况必定发**纯转向**（vx = 0）：
  卡住时原地转（0.6 rad/s）、有图对准失败换视角（0.4 rad/s 持续 1.5 s，约 35°）、跟踪到位后转向面对目标、探索找不到边界时原地转一圈。
  没有转向能力时，导航上车连第二项实地测试（N2，到斜前方的目标点）都做不了。
- **要求**（二选一，D2.1 时定）：
  - A：速度跟踪阶段（路线文档第 3 阶段）就把目标角速度加进观测与奖励（例如 `+1.0 × exp(-(e_w / 0.3 rad/s)²)`，`e_w` = 实际偏航角速度 − 目标），
    "非预期转向"惩罚改成"偏航角速度跟踪误差"，按第 3.4 节的指令分布训练。
  - B：策略只管平衡与 vx，策略外加经典偏航角速度环：左右轮指令 = 策略输出 ± `k_p·e_w + k_i·∫e_w`（`e_w` 用 IMU 陀螺 z），在仿真里与策略一起验证。
  建议先 B 后 A：B 让导航尽早上车，A 在第 7 阶段替换 B，接口不变。
- **验收**：架空与落地分别测 wz = ±0.3、±0.6、±1.0 rad/s 阶跃，稳态误差 < 10%；原地转 360° 不倒、轮轴中点漂移 < 0.3 m；
  vx = 0.2 m/s 与 wz = 0.5 rad/s 组合时轨迹为圆弧（半径误差 < 15%）。

### 3.3 实时控制回路放在哪里

- **现状**：§12"开发时可暂由电脑运行网络，FPGA 采集状态和输出外设信号"；§13 最终由 FPGA 独立推理与控制。
- **问题**：软核 PicoRV32 跑导航，雷达流下主循环单次最长约 38 ms，不能承担 100 Hz 以上、抖动小的平衡控制；板上只有一个 USB 调试串口，被导航工具占用。
- **要求**：
  1. 状态估计、策略推理、执行器输出全部做成 RTL（状态机 + 乘加单元），不依赖软核；软核只通过 CHAS 寄存器读状态、改参数（第 3.10 节）。
  2. 电脑运行网络的板在环阶段，链路走 P11 第 31 / 32 针的独立串口（PC 侧 3.3 V USB-TTL），帧里带类型、序号、FPGA 时间戳、数据、CRC，超时即进入保持平衡 / 安全停机。
     USB 串口有 1–3 ms 的往返抖动（FT232 类要把延迟计时器设 1 ms），仿真里要加同等延迟和抖动验证。
  3. 板在环时实测"观测采样 → 动作生效"的端到端延迟分布（中位数、99%），写进测试记录。
- **验收**：最终部署时拔掉 PC，底盘控制不受影响；软核暂停（`nav_uart.py wr 0xF000 1`）时底盘仍保持平衡（只会触发导航看门狗）。

### 3.4 指令输入：导航会发什么，就按什么训练

- **现状**：§9 课程从 ±0.1 m/s 扩到 ±0.3 m/s，"目标速度变化应设置加速度限制"；§5.2 观测含"目标前进速度"。
- **导航实际发出的指令**（固件 + `safety_guard`，见 [icd.md](icd.md) 第 4 节）：

| 项目 | 现值 | 出处 |
|---|---|---|
| 前进 | 规划上限 0.5 m/s；板上初始化缺省限到 0.3 m/s，首次上车 0.15 m/s | `lp_cfg.v_max`、`SAFE.LIM_V`、`board_init.py --v-max` |
| 倒车 | 0.15 m/s（卡住脱困，持续约 1.5 s） | `lp_cfg.v_back` |
| 角速度 | ±1.2 rad/s；原地转 0.4–0.6 rad/s | `lp_cfg.w_max` |
| 更新 | 固件每 100 ms 提交一次；`ch_valid` 每 `SAFE.TICK_US`（缺省 1 ms）一次 | `APP_PLAN_PERIOD_US`、`SAFE.TICK_US` |
| 斜坡 | 每节拍最多变 DV = 2 mm/s、DW = 3 mrad/s（1 ms 节拍下即 2 m/s²、3 rad/s²） | `SAFE.LIM_A` |
| 看门狗 | 200 ms 没有新指令：按斜坡减到 0，`ch_wdog = 1` | `SAFE.WD_US` |
| 急停 | 下一节拍直接 0（**不经斜坡**），`ch_stop = 1` | `SAFE.CTRL.ESTOP`、`ext_stop` |
| 主机 `mode estop` | 速度按斜坡到 0、`ch_mode = 4`、`ch_stop` 不置位 | 固件 |
| 定位未就绪 / 对准 | 原地保持（0 速度）或 0.4 rad/s 原地转 | `nav_app.c` |

- **要求**：
  1. 训练的指令分布覆盖：vx ∈ [−0.15, +0.5] m/s（或双方协商的更小范围）、wz ∈ [−1.2, +1.2] rad/s、二者组合、纯原地转向、
     每 100 ms 一次的阶梯变化经斜坡平滑、随机"阶跃到 0"（急停）、"斜坡减到 0"（看门狗）。
  2. 底盘给出能承受的最大加速度与角加速度，导航据此设 `SAFE.LIM_A`。1 ms 节拍下 DV 最小为 1（= 1 m/s²），对自平衡车可能偏大，
     **建议把 `SAFE.TICK_US` 改为 10000（10 ms，与 100 Hz 策略周期一致）**，加速度分辨率变成 0.1 m/s²（例如 DV = 5 即 0.5 m/s²）。D2.1 确认。
  3. `SAFE.LIM_V` / `SAFE.LIM_W` 一律设在策略训练范围的 80% 以内；超出训练范围的指令由 `safety_guard` 截断，不能指望策略外推。
  4. 接口层在 `ch_valid` 时锁存指令，策略每个周期用最近一次的值（零阶保持）；检查 `ch_seq` 连续性，跳号计数并上报。
  5. 单位换算只在接口层做一次：`v_cmd[m/s] = ch_vx / 1000`、`w_cmd[rad/s] = ch_wz / 1000`。`ch_stop = 1` 时目标强制为 0；
     `ch_wdog = 1` 时 `ch_vx / ch_wz` 本身已在按斜坡减到 0，照常跟随即可（底盘可以另加更保守的处理，但不要把它变成阶跃）。
- **验收**：导航组从闭环仿真导出真实固件产生的指令序列（给 `run_cl.py` 加一个按控制步记录 vx / wz 的导出选项，导航组待办），底盘在自己的仿真中回放，平衡与跟踪通过。

### 3.5 IMU088：型号、接线、共用与配置

- **现状**：§5.1 IMU 提供倾角、倾角速度、转向角速度；§12"按型号读取并实现相应状态估计"，接口未定。赛前讨论记录写的是"购买 IMU088"。
- **问题**：
  1. **"IMU088"的具体产品还没确认**。网上查不到同名产品，最可能是基于博世 BMI088 的模块，常见三类，对 FPGA 接口的影响完全不同：

| 可能的产品 | 怎么认 | 对外接口 | 协议 | 对导航 / 底盘的影响 |
|---|---|---|---|---|
| A 达妙 DM-IMU（BMI088，带外壳） | 外壳有 DAMIAO 标识，USB-C + CAN + RS485 | **没有 TTL 串口**；RS485（出厂 2 Mbps，只有请求-应答）、CAN（主动上报最高 1 kHz）、USB 虚拟串口 | USB：`55 AA` 帧头 + float + CRC16；RS485：24 字节 `A5 … 5A`；CAN：8 字节定点。**都不兼容 WIT** | 要加 RS485 或 CAN 收发器；FPGA 侧要新写协议模块（RS485 还要按周期轮询）；导航的 `imu_parse.c` 要重写 |
| B 裸 BMI088 板 | 能看到 3 × 4.5 mm 芯片，引脚 CSB1 / CSB2 / SDO1 / SDO2 / INT | SPI（≤ 10 MHz）或 I2C | 寄存器读写，原始加速度 / 角速度，**没有姿态解算** | 延迟最低，最适合平衡；但姿态（俯仰 / 横滚）要自己在 RTL 里算，导航也要改用该结果 |
| C 维特 WIT 协议模块 | 丝印 VCC / TX / RX / GND，USB-TTL 收到每 11 字节一次 `55 51/52/53` | 3.3 V TTL 串口 | WIT 0x55 帧，寄存器命令可配输出内容、频率（≤ 200 Hz）、波特率（≤ 921600） | **导航固件现在就是按它写的**，直接可用 |

  2. 导航与底盘都需要 IMU，而且必须测同一个刚体（机身）的姿态；两颗 IMU 各自漂移，导航与平衡的"水平"会不一致。
- **要求**：
  1. 底盘组本周内给出实物照片、购买链接或手册，确定是 A / B / C 中的哪一种（或别的），双方据此定接口：
     - C：接 P11 第 1 / 2 针（C18 / C19），不需要改硬件，接法见 [pinout.md](pinout.md) 第 5 节；
     - A：建议走 RS485（3.3 V 收发器如 MAX3485 类，RO → C18、DI ← C19、DE/RE ← P11 第 10 针 D16），或 CAN（需要收发器 + CAN 控制器 RTL）；
     - B：走 SPI，占 5–6 根线（SCK、MOSI、MISO、CSB1、CSB2、可选 INT），用 P11 的底盘区，具体针号在分配表 v0.2 里定。
  2. **只用一颗 IMU，装在机身上（与雷达同一刚体），导航与底盘共用**：整车顶层把 IMU 数据同时送给两边。
     推荐由导航组写一个**硬件 IMU 解析模块**（协议确定后），输出带 FPGA 时间戳的角速度 / 加速度 / 姿态样本：底盘直接用并行输出（零软核延迟），
     导航固件改读解析结果（顺便解决 IMU 字节 FIFO 的容量问题，[icd.md](icd.md) 第 5 节）。视频组的姿态显示也用同一份结果。
  3. 配置统一并保存在 IMU 内部、记进 [platform.md](platform.md)：输出角速度 + 加速度 + 姿态；频率 200 Hz（硬件解析之前导航侧按 100 Hz）；
     陀螺量程 ±2000°/s（导航固件按此换算）；串口波特率按"每秒字节数 ≤ 波特率 / 10 的 60%"选（200 Hz × 33 字节需要 ≥ 115200，建议 230400 以上）。
  4. 轴向与零位统一：机身系 X 前、Y 左、Z 上；安装方向的换轴只在解析模块里做一次，导航与底盘用同一张换轴表；俯仰正方向按导航约定（pitch > 0 为低头）。
     车体水平时的俯仰 / 横滚零位、底盘的平衡俯仰角都由底盘组标定后写进 platform.md。
  5. 电机旁磁场干扰大，不要依赖 IMU 的磁力计航向（导航本来就不用 IMU 航向，用陀螺积分）。
- **验收**：[integration_plan.md](integration_plan.md) 第 6.2 节检查表全部通过；车静止 60 s，导航航向漂移 < 1°，底盘平衡俯仰角读数稳定。

### 3.6 里程计回传 `odo_*`：口径、频率与静止

- **现状**：§5.1"前进速度估计：轮速、轮半径与必要的运动学处理；打滑会带来估计误差"。
- **导航怎么用**（`fw/nav/pose.c`，[icd.md](icd.md) 第 4 节）：FPGA 在 `odo_valid` 时打时间戳，固件每轮读最新一组（不排队），按相邻样本的时间差积分；
  航向用 `odo_wz` 积分（不用 IMU 航向角）；导航指令为 0、`odo_vx = odo_vy = 0` 且 `|odo_wz| < 50 mrad/s` 持续 0.3 s 时，把 `odo_wz` 当陀螺零偏估计；
  位姿历史 64 项、每个样本一项，雷达帧和 RK3588 目标都靠它按时间插值。
- **要求**：
  1. `odo_vx` = 机身前向**对地**速度 = r_w ·（ω_L + ω_R）/ 2。ω 是轮子相对**地面**的角速度 = 编码器测得的轮相对腿（机身）的角速度 + 机身俯仰角速度（腿部固定时），
     符号统一成"前进为正"（左右轮电机安装方向相反，在接口层统一，§5.3 已注意到）。r_w 先按 33.65 mm，推车标定后修正。
  2. `odo_wz` = IMU 陀螺 z 轴（机身系，左转为正）；零偏可以不扣（导航会估）。不要用左右轮速差（打滑、转向时误差大）；底盘若融合了两者，说明方法。
  3. `odo_vy` 恒为 0。
  4. 固定 50 Hz 或 100 Hz（推荐 100 Hz），单位 mm/s、mrad/s，int16，`odo_valid` 单拍。**不要 1 kHz**：位姿历史只有 64 项，1 kHz 时只覆盖 64 ms。
  5. 静止给精确 0：原地平衡时轮子来回微动，估计速度在零附近抖，导航的零偏估计就永远不会启动。
     建议底盘在"指令为 0 且 |v| < 10 mm/s 持续 0.2 s"时输出 0，或在状态字里给 STILL 位、导航改用该位判断（二选一，D2.1 定）。
  6. 打滑、腾空、倾倒时在状态字里置位（第 4 节），导航暂停积分或降低里程计权重。
- **验收**（D2.5）：推车直线 2 m，导航 x = 2000 ± 60 mm；原地转一圈 yaw 回到 ±5°；静止 60 s 航向漂移 < 1°；`SAFE_ODO_CNT` 每秒增加 50 或 100。

### 3.7 引脚、电平与执行器接口

- **现状**：§12 列了外设类型，外接驱动板"由用户自行核对输入输出"；两个 MT6701 需要独立总线；要核对 IO Bank 电压。
- **要求**：
  1. 按 [pinout.md](pinout.md) 第 4 节分区：P11 的 13–28、31–40 针归底盘，1–10 针归导航与整车安全。驱动板与编码器方式确定后 3 天内回填分配表 v0.2。
  2. 电平：P11 在 FPGA Bank 2，底板跳线 **P9 必须短接 7–8**（VCCIO2 = 3.3 V），接线前量 TP8。驱动板若是 5 V 逻辑输入，确认 3.3 V 能被识别，否则加电平转换。
  3. MT6701 测轮速**推荐 SSI**：每路 CSN / CLK / DO 三根（两路共 6 根，正好是分配表 13–18 针），24 位帧 = 14 位角度 + 4 位磁场状态 + 6 位 CRC，
     传播延迟约 5 µs，时钟最高约 15 MHz，带状态与校验，标准料号不用改配置。ABZ 正交输出延迟更低，但标准料号出厂只有 1 PPR，要在 5 V 下写 EEPROM 或买预编程料号；
     I2C（地址 0x06，最高 1 MHz，读一次角度约 0.1–0.2 ms）只适合做配置。**MT6701 的 IO 电平跟随它的 VDD，接 FPGA 时必须用 3.3 V 供电**。
     MODE 脚电平与模式的对应关系手册写得不清楚，上板前用实物确认。（依据：MT6701 手册 Rev.1.8）
  4. 舵机 MG996R：50 Hz、0.5–2.5 ms 脉宽；四路堵转电流合计可达约 10 A，用独立的 5–6 V 大电流电源；多数舵机能识别 3.3 V 脉冲，不稳定时加 5 V 缓冲。
  5. 电机驱动使能、电机电源、舵机电源的控制信号一律高有效 + 外部 4.7–10 kΩ 下拉；驱动故障输出用开漏 + 上拉（[pinout.md](pinout.md) 第 6 节）。
- **验收**：下载比特流的过程中、按复位时、导航单独的比特流运行时，电机与舵机都不动；线束通断表与分配表一致。

### 3.8 腿部姿态、腿长与弹跳

- **要求**：

### 3.9 安全与故障降级

- **现状**：§12 列出"使能、故障、数据有效性"，§10 评估项里有倾倒率，但没有底盘状态机。
- **要求**：
  1. 定义底盘状态机并写成文档：上电初始化 → 自检（IMU、编码器、驱动器）→ 待命（使能断开）→ 起立 / 平衡 → 跟随导航指令 → 降级（保持平衡、限速）→
     安全停机（缓慢趴下或断使能）→ 故障锁定（需人工复位）。每个转移条件写清楚，至少包括：`ch_wdog = 1`、`ch_stop = 1`、`ch_seq` 跳号、IMU / 编码器超时、
     策略输出 NaN / 饱和、倾角超限、过流 / 驱动报警、电源欠压。
  2. `ch_stop` = 速度归零但保持平衡（不是断电）；物理急停 = 硬件断电机电源 + 状态机进入故障锁定。两者的行为都要在仿真里先验证。
  3. 复位与重配置：按 S0 会复位整片逻辑（底盘也会复位，车会倒），实车测试时禁止；导航软核暂停或重装固件只会触发导航看门狗，底盘要保持平衡。
  4. 故障可观测：状态字与故障码寄存器（第 3.10 节），必要时用板上蜂鸣器（V17）报警。
- **验收**：[chassis_integration.md](chassis_integration.md) 第 8 节阶段 2 的六项架空检查与故障注入全部通过。

## 附录 A：接口层参考写法（Verilog 示意，非最终代码）

```verilog
// chassis_top 内的接口层：与 nav_subsystem 同一 clk / rst
reg signed [15:0] cmd_vx, cmd_wz;
reg               cmd_stop, cmd_wdog, seq_err;
reg        [15:0] last_seq;
always @(posedge clk) begin
    if (rst) begin
        cmd_vx <= 0; cmd_wz <= 0; cmd_stop <= 1'b1; cmd_wdog <= 1'b1; seq_err <= 1'b0; last_seq <= 0;
    end else if (ch_valid) begin
        cmd_vx   <= ch_stop ? 16'sd0 : ch_vx;                // mm/s；看门狗时 ch_vx 已在按斜坡减速
        cmd_wz   <= ch_stop ? 16'sd0 : ch_wz;                // mrad/s
        cmd_stop <= ch_stop;
        cmd_wdog <= ch_wdog;
        seq_err  <= (ch_seq != last_seq + 16'd1);            // 跳号：计数并上报
        last_seq <= ch_seq;
    end
end
// 里程计回传：固定 100 Hz，单拍 odo_valid
always @(posedge clk) begin
    odo_valid <= 1'b0;
    if (tick_10ms) begin
        odo_vx    <= still ? 16'sd0 : v_ground_mm_s;         // 对地速度（已扣俯仰角速度）
        odo_vy    <= 16'sd0;
        odo_wz    <= gyro_z_mrad_s;                          // IMU 陀螺 z，左转为正
        odo_valid <= 1'b1;
    end
end
```

## 附录 B：单位与符号速查

| 量 | 接口单位 | 换算 | 正方向 |
|---|---|---|---|
