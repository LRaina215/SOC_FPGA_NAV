# 全系统联调计划与关键点

本文是整车所有功能联调的总计划：每个模块谁负责、接口在哪份文档、FPGA 资源怎么分、按什么顺序联调、每一步怎样算通过、
最容易出问题的地方在哪里。具体接口以 [icd.md](icd.md) 为准；底盘细节见 [chassis_integration.md](chassis_integration.md) 与
[chassis_review.md](chassis_review.md)，RK3588 见 [rk3588_design.md](rk3588_design.md)，引脚见 [pinout.md](pinout.md)，扫图见 [mapping_plan.md](mapping_plan.md)。

## 1. 系统组成与现状（2026-10-01）

| 功能 | 主要模块 | 负责 | 现状 |
|---|---|---|---|
| 雷达感知、定位、规划、避障、探索 | `nav_subsystem` + 软核导航固件 | 导航组 | 真雷达上板通过（10 帧/秒、坏帧 0、自动启动与掉电恢复）；无图 / 有图闭环仿真 50/50；**整车实地未测** |
| 速度安全（限幅、斜坡、看门狗、急停） | `safety_guard` | 导航组 | RTL 回归通过；板级 `ch_*` / `odo_*` / `ext_stop` 仍是占位 |

| 摄像头采集 + 姿态显示（基础要求） | OV5640 → DDR3 → HDMI + 字符叠加 | 视频组（待定） | 未开始；资源需求未知 |
| 先验地图 | `tools/map_tool.py` + 量测或 SLAM | 导航组 + SLAM 负责人 | 工具与板上部分完成；真实场地未做 |

## 2. 整车数据流

```text
                      ┌──────────── ACX750（GW5AT-138，一个比特流）─────────────┐
XT-M60 ──RJ45(100M)──>│ 雷达口 MAC → 帧接收 → 点云 → 高程图 / 可通行性 → 代价图   │
                      │                         └→ 结构点 → SLF 匹配定位           │
BMI088 ──SPI(P11)──>│ imu_bmi088 + imu_att（1 kHz 样本、姿态）─┬→ 软核：位姿（200 Hz 样本） │
                      │                                         └→ 底盘、视频（并行样本）    │
                      │ 软核：A* / 局部规划 / 探索 / 跟踪 / 有图定位管理                    │
                      │      → SAFE（限幅、斜坡、看门狗、急停）→ ch_*（含地形模式）          │
                      │ 底盘模块：状态估计 → RL 推理 → 驱动 / 舵机输出                       │──> 驱动板 / 舵机
MT6701 ×2 ─I2C/SSI──>│      ↑ ch_*                         odo_* ↓ → 软核位姿积分 │
急停按钮 ──GPIO─────>│ ext_stop                                                    │
RK3588 ──USB 串口 / P11 串口──> 邮箱：GOAL / WAYPOINTS / TARGET / MODE / MAP；STATUS 回传 │
OV5640 ──摄像头口──>│ 视频：DDR3 帧缓冲 → HDMI（叠加姿态角）                    │──> 显示器
                      └──────────────────────────────────────────────────────────┘
```

## 4. FPGA 资源与时序预算（所有模块共用一片 GW5AT-138）

当前导航比特流（2026-10-01 构建，含 10° 安装参数的固件）布线后：

| 资源 | 已用 / 总量 | 余量 | 说明 |
|---|---|---|---|
| BSRAM（18 Kbit） | **324 / 340（96%）** | 16 块 | 综合 299 块，布线后多约 25 块；逐模块见 [roadmap.md](roadmap.md) 第 6 节 |
| 逻辑（LUT + ALU） | 24808 / 138240（18%） | 充裕 | |
| 寄存器 | 19716（15%） | 充裕 | |
| DSP | 67 / 298（23%） | 约 230 | RL 推理的乘加单元不缺 |
| IO | 32 / 297 | P11 余 34 脚 | 分配见 pinout.md |
| 时序 | 50 MHz 约束下 Fmax 50.085 MHz，0 违例 | **约 0.1 MHz** | 关键路径见 roadmap 第 4 节第 5 条 |

**BSRAM 需求估计**（接入前各组用综合报告替换这些估计值）：

| 新模块 | 估计 | 依据 |
|---|---|---|
| 底盘 RL 推理（如 10 → 64 → 64 → 2，约 5000 个 16 位参数） | 5–6 块 | 权重 80 Kbit；偏置、激活可用分布式 RAM |
| 底盘外设（I2C / SSI、PWM、舵机、板在环串口） | 0–1 块 | FIFO 用分布式 RAM |
| 主机串口 `host_uart`（RK3588 R1） | 0–1 块 | |
| BMI088 采集与姿态（`imu_bmi088` / `imu_att`） | 0–1 块 | 样本 FIFO 很小；姿态滤波用几个 DSP；替换掉的串口 FIFO 还能省出一点 |
| 视频（DDR3 控制器、行缓冲、字库） | 10–20 块（未知） | 先单独综合厂家例程 `ov5640_ddr3_hdmi` 得到实数 |
| SFP 1G Serial Ethernet IP（只在 R2b 时） | 未知 | |

合计约 16–28 块，已经超过余量。导航侧可以腾出的空间（按风险从低到高）：

| 措施 | 腾出 | 风险 |
|---|---|---|
| SLF 结构图按 1K × 18 分块（现在综合按 16K × 1 拼） | 约 8 块 | 低：只改存储拼法，逐位回归可验证 |
| 高程图按 1K × 18 拼 | 约 4 块 | 低 |
| 不用 SFP 时裁掉主机网口 `NETH` 的收发缓冲（主机改走 R0 / R1 串口） | 约 3–5 块 | 低：宏开关，SFP 方案需要时再打开 |
| 软核控制台缓冲 4 → 1 块 | 约 3 块 | 低：控制台只是调试打印 |
| 雷达帧缓冲双缓冲 → 单缓冲 | 约 9 块 | 中：地图处理慢时丢帧率上升，要实测 |

**资源闸门**：任何模块合入前，整车构建布线后 BSRAM ≤ 336（约 99%，再高时布线经常不收敛）、0 违例；不满足就先做上表的压缩，不靠"碰运气重新布线"。

**时序**：余量只有约 0.1 MHz，新模块合入几乎必然出现负 slack。对策按顺序：新模块输入输出全部打寄存器；
对静态配置寄存器到数据通路的路径加多周期约束；视频放在自己的像素时钟域；仍不够时把导航关键路径（帧长乘法、ROI 选择、方向表片选）再切一级流水。

## 6. 各接口的联调关键点

### 6.1 雷达 ↔ FPGA（主体已通过，剩余收尾）

- 5 s 暖机保护的冷启动复测：2026-10-01 已通过（`tools/xt_reboot_test.py` 远程重启雷达 4 次，每次只成功启动一次、之后 10 帧/秒）。
  以后改动 `xt_link.c` 或雷达固件升级后，用同一脚本回归。
- 10° 安装参数的板上验证：`nav_fw_128k_d1_10deg_20261001.fs` 已上板；雷达装车后按 hardware_guide 6.5 节验收地面与箱子。
- 左右方向与深度定义各核对一次（hardware_guide 6.5）；装到车上后量实际光心高度，与 `L0 + 25 mm` 不符超过 1 cm 就改三处参数。
- 关注项：雷达帧尾温度（实测 46–62 °C），整车封装后连续运行 30 分钟看温度与坏帧；雷达供电 12–25 V / ≥ 3 A 单独供电。
- 导航运行时任何主机都不能连雷达 TCP（会抢走 UDP 流，rk3588_design 第 3.4 节）。

### 6.2 BMI088 ↔ FPGA（导航与底盘共用）

前提：`imu_bmi088` / `imu_att` 已写好并上板（roadmap N5）；接线按 [pinout.md](pinout.md) 第 5 节。

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 电平与 VCCIO2 | 万用表 | BMI088 的 VDD / VDDIO = 3.3 V；TP8 = 3.3 V；PS 脚接地 |
| 初始化 | 读 IMU 寄存器块的状态与芯片 ID | 加速度计 ID = 0x1E、陀螺 ID = 0x0F，初始化完成位为 1；读不到就先查 CSB1 是否给过上升沿、MISO 是否接对 |
| 样本率 | 隔 10 s 读两次样本计数 | 陀螺约 1000 个/秒、加速度约 800 个/秒，丢样本计数不增长（雷达 10 帧/秒同时运行） |
| 静止噪声与零偏 | 车静止 60 s | 角速度噪声与零偏在手册量级内，零偏估计收敛；导航航向漂移 < 1° |
| 轴向 | 车静止水平、抬车头、左转 | 抬头时俯仰为负（导航约定 pitch > 0 = 低头）；左转时 z 轴角速度为正；不一致在 `imu_bmi088` 的换轴表里改，导航与底盘自动一致 |
| 零位 | 车体水平放置读数 | 俯仰 / 横滚零位 < 0.5°；超过就在 `imu_att` 里扣除，并记入 platform.md |
| 动态 | 平衡状态下前后推车、原地转 | 俯仰不因加减速明显偏（互补滤波的加速度修正增益合适）；导航地形误报 < 2% |
| 与雷达帧对齐 | 原地转向时看代价图 | 地面不出现成片假障碍 |
| 底盘输出 | 逻辑分析仪看测试点或读 CHAS 寄存器 | `imu_valid` 1000 Hz、时间戳单调，底盘收到的姿态与导航一致 |

### 6.3 导航 ↔ 底盘

接口契约与 RL 代码分层见 [chassis_integration.md](chassis_integration.md)，对底盘组技术路线的具体调整要求见 [chassis_review.md](chassis_review.md)。联调时最容易出错的点：

1. 符号：`vx > 0` 前进、`wz > 0` 从上往下看逆时针（左转）；`odo_*` 同一约定。架空先测方向，再测比例。
2. 里程计口径：`odo_vx` 是**对地**速度（轮速已扣掉机身俯仰角速度），`odo_wz` 用陀螺 z 轴角速度；静止时 `odo_vx` 必须给精确的 0（导航用它估计陀螺零偏）。
3. 频率：`odo_valid` 固定 50–100 Hz。导航的位姿历史只有 64 项，1 kHz 回传会让历史只覆盖 64 ms，雷达帧与 RK3588 目标的时间补偿都会失效。
4. 指令包络：导航会发前进最高 0.5 m/s（板上初始化缺省 0.3 m/s）、倒车 0.15 m/s、角速度最高 1.2 rad/s 的组合指令和纯原地转向；
   底盘必须在这个范围内都能跟踪，否则用 `SAFE.LIM_*` 与 `lp_cfg` 把导航限到底盘能做到的范围。
5. 急停与看门狗：`ch_stop` 时输出**下一节拍直接变 0**（不经斜坡），看门狗超时则**按加速度限制减到 0**，两种情况底盘都要保持平衡。
6. 腿长：导航按雷达离地 `L0 + 25 mm` 建图；姿态切换会改变离地高度，必须停车切换并告诉导航。
7. 指令层次：连续运动只有 `ch_vx` / `ch_wz`；地形模式、姿态请求、起立 / 趴下走 `ch_mode`（编码见 chassis_review 第 4 节）；跳跃等底盘证明能跳之后再加。

### 6.4 导航 ↔ RK3588

见 [rk3588_design.md](rk3588_design.md) 第 10 节 K0–K8。关键是：只发任务、不发速度；TARGET 用机身系、`latency_ms` < 200 ms；导航 STATUS 是网页唯一的位姿来源。

### 6.5 视频 ↔ 导航

- 只共享 FPGA 资源与 IMU 数据，不共享数据通路。姿态角直接取 `imu_att` 的并行输出（无软核延迟），不经软核寄存器读。
- 视频组立项时先单独综合厂家例程，把 BSRAM、PLL、时钟域、引脚（摄像头口、HDMI）写进第 4 节，再决定合入顺序。
- 合入后必须重跑导航回归与板级时序；HDMI / DDR3 的高速时钟只在视频模块内部使用，跨到 50 MHz 域一律走异步 FIFO。

## 7. 安全链（整车统一，所有组都要遵守）

| 层级 | 机制 | 作用 | 谁实现 |
|---|---|---|---|
| 1 硬件断电 | 物理急停按钮串在电机功率回路，常闭触点同时接 P11-8 | 直接断电机电源；断线 = 急停 | 底盘组（线束）+ 导航组（`ext_stop[0]`） |
| 2 FPGA 急停 | `ext_stop` + `SAFE.EXT_MASK`、`SAFE.CTRL.ESTOP` | 速度下一节拍归零、`ch_stop = 1` | 导航组（已有） |
| 3 指令看门狗 | `SAFE.WD_US`（缺省 200 ms） | 软核卡死 / 暂停 / 重装固件时速度按斜坡减到 0、`ch_wdog = 1` | 导航组（已有） |
| 4 底盘自保护 | 倾覆、过流、编码器 / IMU 超时、策略输出异常 | 降级到保持平衡、趴下或断使能 | 底盘组 |
| 5 上电与重配置 | 使能类信号外部下拉 | 比特流下载期间、复位期间电机不动 | 底盘组（硬件） |

规则：

- 首次通电、改过运动控制或方向相关代码后，**先架空**；实车测试一人专职手放急停。
- `mode estop`、`SAFE.CTRL.ESTOP` 都要经过串口，不能代替物理急停。
- 不在平衡状态下按 S0 复位、不下载比特流；要换固件先让车停在支架上。
- 每次实车测试前检查急停：按下后电机断电、控制台 `SAFE_STAT` 的外部急停位为 1。

## 8. 时间基准与日志

- 全车唯一时间基准：FPGA 的 `SYS.TIME_US`（32 位、微秒、约 71.6 分钟回绕）。底盘模块直接用导航的 `time_us`；RK3588 记录 STATUS 里的 `t_us`。
- 每次联调建一个以日期和测试编号命名的文件夹，至少保存：比特流文件名与 SHA256、固件版本（控制台第一行）、`board_init.py` 输出、
  `nav_uart.py stat`（开始与结束各一次）、控制台日志、`nav_host.py listen` 日志、底盘遥测、RK3588 收发日志、现场视频。
- 出问题先收集、再改（hardware_guide 第 8 节）；结论写回 roadmap 第 4 节（踩过的坑）或第 7 节（已知问题）。

## 9. 版本与签字

- 接口版本号 `ICD vX.Y`：X 变 = 语义不兼容（坐标、单位、位宽、周期、急停语义），Y 变 = 只增字段。写在 icd.md 开头的版本记录里。
- 比特流命名：`nav_<内容>_<日期>.fs`（例如 `nav_fw_128k_d1_10deg_20261001.fs`），并在 hardware_guide 4.1 节登记"是否已上板验证"。
- 每个里程碑（第 5 节）通过时，在 roadmap 第 1 节写一行结论与日期，附测试记录路径。
- 改动接口的提交必须同时改真值文档与相关说明文档（[dev_guide.md](dev_guide.md) 第 7 节）。

## 10. 与赛题要求的对应

依据《选题指南》选题 3 与赛前讨论记录整理（以官方最新文件为准）：基础功能包括摄像头与 IMU 感知、编码器闭环运动、实时避障、自主导航；
拓展功能为 RK3588 上的识别、跟踪与智能任务。讨论记录中的评分权重：FPGA 实时感知与控制 40%、系统稳定性 25%、自主导航 20%。

| 赛题项 | 由谁实现 | 联调里程碑 | 演示方式 |
|---|---|---|---|
| 摄像头采集与显示、IMU 姿态 | 视频组 + IMU（导航 / 底盘共用） | I3、I8 | HDMI 画面叠加实时姿态角 |
| 编码器闭环运动 | 底盘组（MT6701 + 平衡 / 速度控制） | I4 | 架空与落地速度跟踪曲线 |
| 实时避障 | 导航（雷达高程图 + 可通行性 + 局部规划）+ 急停输入 | I5 | 动态放箱子、台阶 / 陡坡判不可通行 |
| 自主导航 | 导航（无图探索、有图定点 / 巡检） | I5、I6 | 定点、路径点循环、探索 |
| 识别、跟踪、智能任务（拓展） | RK3588 + 导航跟踪 | I7 | 找物、跟人、网页任务 |
| 系统稳定性 | 全体 | I9 | 连续运行、故障注入、拔掉 RK3588 仍能导航 |

## 11. 主要风险与对策

| 风险 | 影响 | 对策 | 负责 |
|---|---|---|---|
| BSRAM 不够（导航已用 96%） | 底盘 / 视频合不进同一比特流 | 第 4 节的压缩措施提前做；各组接入前报预算 | 导航组 |
| 时序余量约 0.1 MHz | 合入新模块后负 slack | 边界打拍、多周期约束、关键路径加流水 | 导航组 + 各组 |
| 底盘第一版策略没有转向 | 导航完全无法上车（规划必须转向） | 转向并入第一版训练，或先用经典偏航环兜底（chassis_review 第 3.2 节） | 底盘组 |
| 底盘 RL 进度慢 | I4 之后全部顺延 | 先上经典平衡控制（LQR / PID）走通接口，RL 成熟后替换 | 底盘组 |
| BMI088 采集与姿态模块未完成（N5） | 导航姿态与底盘平衡都受影响 | 优先排期；先用 testbench + 定点参考模型做完，再上板；底盘可先用仿真样本开发 | 导航组 |
| 里程计质量（打滑、俯仰耦合） | 无图定位漂移、跟踪不准 | 对地速度在底盘侧估计并标注可信度；推车标定比例 | 底盘组 |
| 自平衡车身摆动 | 点云整体倾斜、地形误报 | IMU ≥ 100 Hz 带角速度；按帧时刻插值姿态（已实现） | 导航组 |
| 雷达近处盲区约 0.24 m（下俯 10°） | 贴近的低矮障碍看不到 | 近区不过期（已实现）；可选近距 ToF 接 `ext_stop[1]` | 导航组 |
| 只有一个调试串口 | 多组同时调试冲突 | 底盘板在环用 P11 上的独立串口；RK3588 走 R1 专用串口 | 各组 |
| 供电与干扰 | 复位、串口误码、雷达断流 | 电机、舵机、雷达、逻辑分开供电只共地；线束带锁、远离电机线 | 底盘组 |
