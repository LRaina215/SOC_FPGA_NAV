# 现有板静态接入与BMI诊断

当前进度统一见[总计划](../../docs/1_plan/system_integration_plan_20261021.md)。用户2026-10-23授权必要实机测试；早先供电状态仅归当时。最新13:20整车供电且垫高后，同一B1镜像读到完整BMI六轴，30秒＋60秒两段全部有效；逐地址观察器本轮也正常。当前SRAM留4B28恒零输出诊断，未自动恢复99A6控制、未写Flash、未发运动命令。具体小板供电/上拉原因未测；12:48仅USB时的失败和计数矛盾保留，不将当前恢复冒充其电气根因已查清。

控制依据是`control/README.md`、`control/fpga/md/BMI088_OLED.md`和实际`main.cst`：BMI SDA=P11-7/F18、SCL=P11-8/E18；控制TX=P11-40/A16、RX=P11-39/A15，现行源码230400/100Hz。板载CH9102的L21/M21属于另一串口。控制README早先表格和历史7000/SPI/9–10记录不能取代当前源码；当前物理供电/小板上拉电压没有因这些引脚记录而得到测量确认。

`capture_existing_telemetry.py --port COMx --seconds 30 --out F:/new_capture`只接收原控制V1/V2协议，无自动选口或UART写入。打开前请求DTR/RTS为低；不宣称测过驱动/电气瞬态。保留原始字节、CSV、时间步长、序号和故障，物理单位来自原解码器标称配置。遥测是快照，不能把每包原始轮计数相加当作无漏样里程；V1仅50Hz，更不能覆盖100Hz编码器窗。读取现有RTL线级记录和坏CRC恢复的合同已通过，不代表板上收到数据。

## 临时SRAM诊断

`bmi_probe_top.v`不实例化策略、轮速PID或舵机控制，10路执行器引脚恒低；BMI及I2C使用未编辑的原`bmi088.v`与`oled_driver.v`。原配置、自动地址探测和错误重试均保留，样本必须由原驱动完成两组六字节读取后发布。UART改走M21，10Hz/230400，仅发送独立诊断协议，不接受命令、不写Flash。它可观察供电/连接问题产生的实际错误，串口通了也不自动视为BMI有效。

构建：`python integration/g3/build_bmi_probe.py --out F:/new_probe_build`。独立138C工程、50MHz约束，300秒总预算/180秒无日志进展预算。构建脚本绝不下载；必须检查实际时序/器件/引脚及恒低物理输出后才使用SRAM Program。该小工程不改变正在运行的冻结G2网表；独立诊断通过也不代表G2通过。替换前记录现有UserCode、保留原控制位流并尝试SRAM回读；读出的数据能否作为可重放镜像需另行确认。

采集：`python integration/g3/read_bmi_probe.py --port COM11 --seconds 30 --out F:/new_probe_capture`。显式新目录、不覆盖旧记录、无UART发送，输出原始字节、CSV和错误/样本计数摘要。离线`--replay`清楚标为非实测；现有驱动未做硬件时钟同步，不能把多轴或遥测快照视为严格同刻。

协议：A5 5A B0 20，32字节小端负载，CRC覆盖B0/20与全部负载，CRC16/CCITT-FALSE低字节先发。版本B0与原控制V1/V2隔离。

| 7/8 | 原驱动错误码、事务operation |
| 9/10 | 加速度/陀螺地址 |

仅在初始化成功、无当前错误、完整样本计数递增、IDs/配置由原驱动通过时认定有有效采集。数据读到后，再采静态噪声/零偏；没有独立静止条件不做标定接受，更不写成导航或停止包络通过。

本轮实测323帧/CRC0、相邻序号连续/时间100ms；可见加速度ID1E，但最终陀螺69地址探测显示错误1、完整样本0。错误标志会跨重试保留，323份错误快照不是323次独立I2C失败；68每次交易的ACK或错误ID没有单独事件计数。原始零值不能作传感器数据。已重新加载保存的仓库99A6控制位流，工具报告UserCode与测试前一致，Flash未写；SRAM回读全1不能作为备份或完整身份验证。实机记录和恢复文件统一链接在总计划第5节。

## B1：按地址的I2C观测与原始编码器反馈

`feedback_probe_top.v`是另一个独立诊断顶层，使用未编辑的原BMI/I2C、两份`motor520_speed`和UART模块；M2为左轮、M1为右轮，原始AB计数保持原符号（名义前进左正、右负）。十路执行器输出仍恒低，不实例化策略/PID/舵机控制，不改原4500或正在运行的G2输入。串口为M21、230400/100Hz，只发送B1，不接收命令。

`i2c_id_observer.v`只采样SDA/SCL，不驱动总线，分别累计18/19/68/69的地址阶段ACK、NACK和寄存器0读取，保留最后ID。地址写与读阶段分别计数，一次成功ID读取通常含两个地址ACK；主机读取后的NACK为正常结束，不算地址失败。各32位计数回绕；只识别同地址、重复START的寄存器0读取，STOP或复位丢弃指针。不用遥测错误快照数代替交易次数。

样本序号和年龄分别归原BMI完整发布、两轮同时发布；BMI六轴与序号一并锁存，未发布时不采纳变化的live值。编码器位置在原速度发布沿锁存，不能称为精确门结束位置；年龄有不足1ms相位不确定性。`bmi_initialized_sample`表示初始化/ID/完整发布条件满足，`bmi_fresh_50ms`另外要求年龄<50ms；二者均不证明静止、标定完成或融合就绪。原始轮计数是快照，不直接逐包累加成无漏样里程。

协议A5 5A B1 78，120字节小端负载、总126字节，CRC范围与原UART一致。诊断签名BC02。

必要合同：`test_i2c_id_observer.py --out <新目录>`验证独立合成总线的ACK/NACK、错误ID、过滤、STOP/复位；`test_feedback_probe.py --out <新目录>`通过实际原UART线级解码3帧/378字节，核对原编码器正负计数、六轴极值/原子保持、序号/年龄、I2C计数、坏CRC恢复与十路恒低。时钟/串口参数缩放、BMI发布为测试注入，不是实物或物理时序通过。已通过记录见[专项证据](../../docs/4_design/evidence/g3_20261023/feedback_probe_offline.json)。

`build_feedback_probe.py --out <新目录> [--prepare-only]`冻结七个源与实际引脚，独立138C/50MHz，单次总预算300秒/静默180秒，不下载。`run_prepared_probe.py <冻结目录> --after-runtime <现有构建的tool_runtime.json>`只排队一次：前项结束、所属进程退出、物理空闲≥2GiB且提交余量≥4GiB后执行；默认等待95分钟，可用`--wait-until <带时区绝对时间>`显式指定最多4小时后的截止。`--resume-waiting`仅允许旧队列已退出、尚未有impl的等待任务，先保留旧job/launch记录。用户延长本轮G2至13:00后，B1等待截止同步为13:15，11:09实际开始、11:11完成，构建仍只300/180秒，不自动编程、不恢复定时监督。冻结目录`F:/nav_hardware_20261023/feedback_probe_build1`。读取脚本`read_feedback_probe.py --port <明确端口> --seconds 30 --out <新目录>`只接收，支持标为离线的`--replay`。

## 12:48 B1实际采集与诊断限制

`audit_feedback_probe.py <实际构建> --out <结果>`核对实际报告、全部19个物理引脚、十路执行器OBUF接实际GND、无时序例外、50MHz与setup/hold/复位/脉宽。当前实际Fmax88.359MHz，setup/hold0，Recovery13.650ns、Removal2.369ns、最小脉宽7.983ns，0 BSRAM，独立门槛通过。报告解析首次误取目录标题导致缺失复位/脉宽，门槛拒绝；修正为正文锚定后取得实际正裕量，未因此重构建。

`run_feedback_probe_session.py`要求15分钟内人类供电/支撑确认、实际构建通过、现有UserCode99A6及保存恢复候选存在。默认`--power-state actuators-disconnected`要求执行器实际断电，下载一旦尝试，无论采集成功与否均在finally恢复候选并读UserCode。新增`--power-state powered-supported`仅用于人类明确整车通电且已垫高/支撑的恒零诊断，采集后保留诊断，绝不自动恢复有动力控制；异常同样不自动恢复。供电参数不得代替人类确认，脚本不会电气检测供电或保证配置瞬态。操作2仅SRAM Program，不使用Flash命令、不接受UART运动命令；UserCode一致不证明完整镜像身份。

实测3022帧、CRC0、相邻序号/编码器发布序号均+1、时间均+10ms；两轮原始delta/位置/非法跳变均0，编码器年龄均9ms。只确认采集路径与静态输入，不能证明编码器有运动响应或物理停止。2315份快照读到加速度ID1E、陀螺ID0F为0份、完整六轴发布0；原始零值仍属占位。新增观察器四地址的ACK/NACK/ID计数全0，与原驱动已读ID矛盾，所以逐地址计数不接受，不据此判68或69的真实结果。12:49恢复99A6，原始字节/CSV留在`F:/nav_hardware_20261023/feedback_session_1248/capture`。见[完整实测、构建及恢复证据](../../docs/4_design/evidence/g3_20261023/feedback_probe_hardware_1248.json)。

针对矛盾新增必要检查：`test_i2c_id_observer.py --original-master`使用未改原BMI/I2C及模型从机，通过初始化地址回退/ID解码；`test_observer_physical_netlist.py --build <B1构建> --observer-cone --out <新目录>`从实际网表反向选出观察器逻辑，切在已核对的IOBUF输出，930原语、830参数原文保持，无悬空驱动，全部LUT/DFF INIT保留；理想总线下合同通过。它没有实际总线波形、SDF或完整设计接受结论。全设计75123实例超过BASIC50000仿真许可，在启动前被阻止；切取逻辑是正常模块分析。较早提取夹具因转义实例名尾空格漏INIT而失败，已保存并修正，不能归因厂商映射。仅USB时计数0的具体电气原因仍未解释；后续整车供电时同一观察器已正常，因此暂缓新增事务探针，不用历史0接受停止。

## 13:20整车供电后的恢复与连续采集

用户确认整车上电、车体垫高并采取安全措施。同一B1构建重新SRAM下载后，第一段3023帧、第二段6013帧全部为有效且新鲜的六轴发布，CRC0，两段内均10ms/+1连续，数据年龄3ms，无传感器错误或轴值饱和。实际加速度地址19/ID1E、陀螺69/ID0F；18/68各一次探测NACK，19/69 ACK持续递增且NACK0，旁路ID与原驱动一致。这足以确认当前供电条件下原驱动与硬件采集可用，不证明具体电源、上拉或温度因素；没有重编驱动或位流。

长段60.12秒加速度模长均值0.99247g、标准差0.00262g；陀螺均值约[0.116,−0.001,0.052]°/s、标准差[0.526,0.586,0.603]°/s。按现有工程10920 raw/g、16.384 raw/(°/s)换算。`analyze_feedback_capture.py <capture> --out <json>`从原始字节重新解码，按发布序号去重统计；不输出校准系数、不把支架观测当独立静止真值。两轮采集内位置不变、delta/非法跳变0，左轮−2初值在采集前发生，不能据此证明完整配置过程没有运动。

原始数据在`F:/nav_hardware_20261023/feedback_powered_1322/capture`与`F:/nav_hardware_20261023/feedback_powered_stability_1321`（目录后缀只是标签，实际时间以元数据为准）。[完整证据](../../docs/4_design/evidence/g3_20261023/feedback_powered_recovery_1320.json)包含供电确认、SRAM日志、原始分析和后续边界。当前SRAM保持4B28恒零诊断；Flash未写，断电后的启动配置不在本次变更范围。原4500、权重、PID、125Hz未改。轴向、温度/静止标定、融合就绪和物理停止仍待各自验证；G2也仍未通过。
