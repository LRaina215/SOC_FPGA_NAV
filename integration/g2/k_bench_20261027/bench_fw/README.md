# 台架固件与 10-31 静态建图结果

构建：`K_fw_bench1`（PNR66 的导航固件源码 + 下列改动），`build_rv_k.py --define APP_BENCH_STATIONARY=1 [--define APP_MOUNT_PITCH_CDEG=.. --define APP_MOUNT_Z_MM=..]`。同一套源码不加宏重新编译，和板上前移 1000 固件逐字节一致，只差编译时间那一行。

改动：
1. `APP_BENCH_STATIONARY`（只用于台架）：控制停止、里程计不来时，每 20 ms 补一个零速样本，雷达帧照样能取到位姿；有真实里程计时以真实的为准。
2. `hal_imu_config` 开机时把 IMU 接收字节 FIFO 和时间戳 FIFO 重新对齐。**这是正式固件也该带上的修复**：CPU 被保持复位时（调试口装载固件、`imu_peek`/`ram_peek` 读内存），BMI 姿态帧仍在 115200 下持续到达，256 字节的接收 FIFO 溢出丢新字节，32 项的时间戳 FIFO 却留着最旧的 32 项。CPU 放开后，每个新突发都会弹出一个早约 210 ms 的时间戳，姿态永远"过期"，导航按 `n_time_skip` 丢掉全部雷达帧（实测 imu_t_us 落后 221 ms，IMU_STAT_OVF 6342）。
3. `APP_MOUNT_PITCH_CDEG`、`APP_MOUNT_Z_MM`：雷达安装俯仰和高度改成可编译期覆盖，缺省仍是 1000（10°）和 155。

静态建图（车放地上、遥控 5 停轮、人扶车直立，纸板约 1.5 m 外）：
- 原安装参数（下俯 10°、155 mm）下，地面在高程图里平面拟合为：向前每米低 160 mm（−9.1°），向左 +2.6°，rms 22 mm。按射线模型拟合：安装俯角多算了 9.1°，雷达实际离地约 128 mm。
- 改为 0.9°、125 mm 后（`out_bench3`），剩余俯仰误差 −0.4°～+1.6°（看取多远的地面），实际高度估计 114～137 mm：地面基本放平。**还需要现场核对雷达实际是不是水平安装。**
- 纸板：x 1.65～1.80 m，y +0.53～−0.08 m（宽约 60 cm，中心偏左约 22 cm）。左侧约 0.95 m、右侧约 0.5 m 处各有一列连续的高物体（墙或家具）。
- 代价图里地面仍几乎全是致命/膨胀：地面格内高差 p50 16 mm、p90 60 mm（>50 mm 的占 13%），相邻格高差 p90 28 mm（>20 mm 的占 15%），零散的致命格再膨胀 20 cm，就把整片地面盖住了。人手扶着车会晃，近处（0.5 m）格内高差中位数 37 mm，远处（1.4 m）只有 1 mm。台阶 20 mm、粗糙度 50 mm 的阈值相对实测噪声太紧；放宽到 40/80 mm 后致命格从 1081 减到 852，仍然盖满。规划测试要等地面能判成可通行之后再做。
