# PNR66：4.3 寸 480×272 屏版本（时序收敛，已上 SRAM）

位流 `D:\tools\g2_video_lcd480_pnr66_20261031.fs`（sha 6b3083a5…，哈希见 `hashes.txt`），构建目录 `F:/nav_integration_g2_20261023/K_pnr66_lcd480p2r0`。

起因：PNR65 上板，屏幕实物是芯路恒 4.3 寸 TFT（480×272，9 MHz），控制组原设计按 5 寸 800×480、33 MHz 写的。屏只显示了 800×480 帧的左上 480×272：左边 80 像素黑边，摄像头画面下面一半看不到，HUD 面板偏到右下，GZ、DIST 两行被切掉。

改动（相对 PNR65 的 syn3 源，补丁在 `../lcd480/`）：
- `g2_camera_lcd.v`：时序改为芯路恒例程 `disp_parameter_cfg.v` 的 480×272 参数（行 525 = 同步 41 + 后肩 2 + 有效 480 + 前肩 2；场 286 = 10 + 2 + 272 + 2）。160×120 画面 2 倍放大成 320×240，放在 x 0～319、y 16～255。HUD 面板放在 x 304～479、y 60～211。未就绪彩条按 480 宽重新分段。
- `g2_video_hud.v`：新增参数 `TEXT_W`（默认 252，与原版一致）。这一版用 168，即 14 列：每行最长的内容（"GX: +0000.0 dps"）就是 14 列。
- PLL：`ODIV1_SEL` 由 25 改为 92，VCO 825 MHz 不变，LCD 时钟 8.967 MHz（约 59.7 帧/秒）。SDC 的生成时钟改为 `lcd9`（50×33/184）。

验证：
- `tb_hud480.sv`：同一组 8 种输入，与控制组原版 `lcd_sensor_hud` 摆在同一位置逐像素对比 14 列，共 31360 点一致；原版在第 14～20 列没有任何字形（15680 点），收窄不丢字。原 `tb_hud.sv`（默认参数）仍然 47040 点通过。
- `tb_lcd480.sv`：完整 `g2_camera_lcd`，摄像头空闲，跑 4 帧：每行 525 拍、480 个 DE，每帧 286 行、272 行有 DE，行同步 41 拍、场同步 10 行，彩条、HUD 边框、背景采样点都对。
- 综合 0 错误、0 条 EX3988（初值缺失），BSRAM 307。

PNR（place2/route0）：clk50 50.056 MHz，rgmii 126.3，camera_pclk 94.5，lcd9 59.2（要求 8.967）；4 个时钟 setup/hold TNS 都是 0；最差 setup +0.022 ns、hold +0.164 ns、recovery +3.657 ns、removal +0.355 ns；319 条约束全部生效；BSRAM 318/340；0 条未布通；89 个引脚全部吻合。布线后网表重新审计：173 个跨域全部归类，生成的约束集与实际使用的完全一致。
