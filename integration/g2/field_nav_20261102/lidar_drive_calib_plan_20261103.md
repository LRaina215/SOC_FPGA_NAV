## 第一步　RK 当雷达直通，每次测试自动录原始帧（FPGA、固件都不改）

RK 是 Orange Pi 5 Plus，有 eth1、eth2 两个网口，联网走 wlan0。10-23 记录两口都无载波；10-24 SFP 测试时 eth2 临时接过 FPGA 的 SFP1（连接未持久化）。

1. 查口：`ip -br link`、`nmcli dev status`、`ethtool eth1`、`ethtool eth2`。SFP 那根线如果还在、且没有服务在用，拔掉腾出 eth2；两口都腾不出来就用 USB3 千兆网卡（RTL8153，内核自带驱动）。
2. 建网桥 br-lidar，持久化、开机自起：两口作从口；不配 IP（ipv4、ipv6 都 disabled）；关 STP，forward-delay 0。
3. 处理 docker：RK 装了 docker，它会加载 br_netfilter 并把 iptables FORWARD 默认策略设成 DROP，网桥转发的雷达 UDP 会被丢。二选一并持久化：`net.bridge.bridge-nf-call-iptables=0`（ip6tables、arptables 同样处理，写进 /etc/sysctl.d/）；或 `iptables -I FORWARD -m physdev --physdev-is-bridged -j ACCEPT`。
4. 用户接线：雷达网线插 RK eth1；一根短网线从 RK eth2 接到 FPGA 雷达口。RK 断电时 FPGA 收不到雷达；不录时把雷达线插回 FPGA 就是原样。
5. 验收（车静止在起点）：控制台出现 `lidar start #N (tcp -> 192.168.0.101:7787)`；`frames` 每秒约增 10，与直连相同；起点静止 q 与直连时同一水平（13:05:23–31 静止为 24–26）；`sudo tcpdump -i eth1 -c 50 'udp dst port 7687'` 有包。
6. RK 不对雷达发起 TCP 连接（`tools/xt_config.py`、厂家上位机都不用）：雷达只把 UDP 发给最近一次连它 TCP 的主机，RK 一连，FPGA 就断流。网桥不配 IP 也是这个原因。
7. 录制并进 `test_recorder.py` 的会话（`D:\tools\rk_rec`，部署用 `deploy_rec.sh`）：
   - 会话开始时起 `tcpdump -i eth1 -s 0 -U -w <会话目录>/lidar.pcap 'udp dst port 7687'`，会话结束时停。文件名要以 .pcap 结尾（Ubuntu 的 tcpdump AppArmor 规则）。权限用 sudoers 白名单或服务的 CAP_NET_RAW。
   - session.json 补三项：会话开始同一时刻的 `time.monotonic()` 和 `time.time()`（微秒；pcap 是墙钟，遥测是单调钟）；当时的 ACTIVE 文件名和固件 banner；地图 map_id。
   - 数据量约 0.2 MB/s（10 帧/s × 约 19.4 KB），30 分钟约 360 MB。沿用 MIN_FREE_MB 下限，不删旧数据。
8. 之后用户照常做导航测试，不另做标定。第一张图一趟往返有 4–6 段直线、3–4 个方向，跑 2–3 趟就够。

## 第二步　离线标定（PC，`D:\tools\xt_drive_calib`，从 nav 仓库 import 模型）

输入：会话目录里的 lidar.pcap、telemetry.csv、session.json、nav_console.log。

1. 重组帧：`model/xt_proto.py`（20 字节分包头）；帧时间取最后一个分包的抓包时间。
2. 点云：`model/lidar_lut.py`，内参取每帧 FrameInfo（与固件板上生成的方向表一致）；深度是径向距离。
3. 地面：每帧 RANSAC 拟合地面（可复用 `D:\tools\floor_fit.py`），得到雷达高度和俯仰、横滚，把点转到水平系；顺带核对固件的横滚、俯仰设定。
4. 取离地 0.08–0.55 m 的点投成 2D。
5. 逐帧配准：先核对参考几何与当次实景。11-03 新照片及部署地图审阅已确认，`config/field_home2_20261102.json` 没有三角支撑面，不能直接把它当标定真值。应先从可用原始扫描恢复稳定可见表面，并区分未建模表面和真正动态离群点；对经核对的参考面做点到线段 ICP，鲁棒核处理小瓶子、人等动态物。初值取上一帧结果加两帧之间的轮速、陀螺增量；第一帧从地图原点（起点时的雷达光心）做 ±0.3 m、±10° 粗搜。每帧输出雷达 x、y、ψ、内点数、残差、各面点数及退化方向。不能让错误地图的残差被偏角参数吸收。
6. 偏角：取 |wz| < 0.03 rad/s 持续 ≥ 2 s、雷达走过 ≥ 0.5 m 的直线段，对雷达位置做直线拟合得行进方向，偏角 = 段内平均 ψ − 行进方向（倒车段加 180°）。
   - 直行时雷达沿车身前向平移，结果与车怎么摆、杆臂多长无关；地图整体有小转角时，ψ 和行进方向一起转，相减抵消。
   - 只看到一面无限长平面的段，沿墙平移不可观；仅凭该面的点云不能独立恢复完整位置轨迹。引入轮速会带入其误差，不能再把它算作独立雷达标定依据。优先使用能同时看到非平行面或稳定端点的直线段，并检查退化与解的多义性。
   - 合格：≥ 6 段、至少 2 个方向，段间标准差 ≤ 0.6°。报均值和每段的值；与 3.0° 相差不到 0.5° 就不改。
7. 同一份数据顺带出（不另跑车）：
   - 每趟起点的实际航向（ψ − 偏角）：摆放误差多大，是否常超过 1.5°；
   - 原地转向前后 ψ 的变化与陀螺积分之比：陀螺比例误差，180° 掉头后会不会超出 ±2.8°；
   - ψ 与陀螺积分的时间差：雷达帧延迟；
   - 每面墙、每个箱子的残差：地图量错的地方，小瓶子的影响；
   - 控制台融合位姿对 ICP 轨迹：误差什么时候超出跟踪窗（±1.4°、±75 mm），之前发生了什么（起步、掉头、哪片区域）。
